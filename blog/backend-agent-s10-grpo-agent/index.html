组内比较怎样替代单独的价值估计

GRPO（Group Relative Policy Optimization，组相对策略优化）对同一提示采样多个输出，用组内奖励形成相对优势，减少对单独价值模型的依赖。本文限定DeepSeekMath论文中的结果监督形式；后来的同名实现可能改变归一化、长度权重和KL处理。

对提示q，从π_old采样G份输出o_i，每份获得结果奖励r_i：

A^i=ri−rˉstd⁡(r1,…,rG)\hat A_i=\frac{r_i-\bar r}{\operatorname{std}(r_1,\ldots,r_G)}

结果监督把这份相对奖励用于该输出的有效Token。教学组[0,0,1,1]的均值为0.5；明确采用总体标准差时std=0.5，优势为[−1,−1,1,1]。使用样本标准差会得到不同数值，因此实现必须核对统计约定。DeepSeekMath第4.1.2节

这组优势表示同题候选之间的相对差异。若另一题四个回答全部正确，组内没有差异；若全部错误，也同样没有差异。零方差不能直接除以0，实现需要显式跳过相应奖励梯度或采用约定的稳定处理，并记录这类样本比例。若存在KL或其他损失项，整组也不一定完全没有梯度。

目标中的两层平均为什么不能省略

令ρ_i,t=πθ(o_i,t|q,o_i,<t)/π_old(o_i,t|q,o_i,<t)。原论文目标包含组内平均与每份输出内部的Token平均，可以写为：

J(θ)=Eq∼PQ, {oi}i=1G∼πold(⋅∣q)[1G∑i=1G1∣oi∣∑t=1∣oi∣(min⁡(ρi,tA^i,clip⁡(ρi,t,1−ϵ,1+ϵ)A^i)−βD^i,t)]J(\theta)=\mathbb E_{q\sim P_Q,\ \{o_i\}_{i=1}^G\sim\pi_{\mathrm{old}}(\cdot|q)} \left[\frac1G\sum_{i=1}^G\frac1{|o_i|} \sum_{t=1}^{|o_i|} \left(\min(\rho_{i,t}\hat A_i, \operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i) -\beta\widehat D_{i,t}\right)\right]

其中P_Q是训练提示分布，|o_i|是输出的有效Token数，D̂表示使用的KL相关估计项，β为其系数。先从P_Q取提示，再由旧策略对该提示采样输出，不能把提示也写成从语言策略采样。采样数据、旧概率和组内奖励统计在策略更新时作为固定输入，梯度通过当前策略相关量计算。裁剪项的正负优势行为见PPO算例。

先在每份输出内平均，再在组内平均，与直接把全组所有Token平均不同。 前者让每份输出在该归约结构下具有相同的总权重；后者会让较长输出贡献更多Token项。改动这个分母会改变优化目标，不只是代码风格变化。

论文采用的逐TokenKL估计形式可写为u−log(u)−1，其中u=π_ref/πθ，各概率针对同一前缀及采样Token。该量非负；把其期望解释为KL时，需要核对样本分布及支持集。在使用旧策略样本进行多轮更新时，不能无条件宣称每次小批估计都等于当前策略的真实KL。DeepSeekMath式3、4

一批数据从采样到训练怎样流动

一次简化迭代先固定采样策略版本，取一批提示，对每题生成G份输出；随后计算奖励、有效长度和组内统计，保留旧策略log概率及必要的参考策略结果，再组成训练batch，计算损失并更新策略。

采样与训练异步执行时，要保存policy版本。训练器已经更新到v12，而新收到的轨迹仍由v8生成，就出现策略滞后。概率比需要对应真实采样分布，数据过旧时还要采取丢弃或其他经过验证的处理；不能把所有数据都标成“当前策略采样”。

记录还应包含提示、输出、终止原因及奖励细项。达到长度上限而被截断，与自然完成答案不是同一结果；若截断恰好丢掉结论，奖励和长度分析都需要识别这种情况。

Agent训练还要恢复工具环境

把输出从一段文本扩展为“查资料→调用工具→核验结果”的轨迹后，奖励可以来自最终状态、过程检查和约束违规。只奖励工具次数，模型可能反复调用；只奖励文本长度，也可能学会无用扩写。

一个教学任务是根据证据创建唯一工单。可以检查工单字段正确、没有重复创建、引用支持结论，分别保留对应奖励与失败原因。最终成功仍不能自动告诉模型哪一步决策起了作用，多步信用分配需要结合轨迹与训练方法处理。

环境reset必须恢复任务资源和外部状态。只清空消息但保留上一轮创建的工单，会改变下一次训练题的起点。涉及外部副作用时，应使用隔离环境或可控模拟器，固定工具数据版本，并区分模拟评测与真实服务验收。

本文只核查公式和教学计算，没有运行LLM训练，也不把历史CPU教学实验写成本轮集群训练结果。

面试问答：GRPO原理与训练数据流

GRPO 算法原理

回答： GRPO对同一提示由旧策略生成一组候选，利用组内奖励形成相对优势，再通过带概率比裁剪及相关正则项的目标更新策略。原始结果监督形式把输出的归一化奖励用于其有效Token，不需要另外训练传统价值Critic。

例如奖励[0,0,1,1]，按总体标准差归一化得到优势[−1,−1,1,1]。它提供同题的相对学习信号，但全对或全错时可能零方差，需要稳定处理。原论文按输出内Token平均、再按组平均，不能任意换成全组Token平均而仍声称目标完全相同。

没有Critic减少部分资源开销，但组采样仍有成本，奖励质量和多样性也决定学习效果。具体实现还需核对KL形式、统计约定和版本，不能把所有GRPO变体当成同一配置。

延伸追问（自拟）：组内全零时增加一个很小的分母就解决了吗？ 只能避免数值除零，不能制造奖励差异。应检查任务难度、奖励是否正确、采样是否有探索，并观察零差异组比例。

原问ID：FQ-doxcnC1zKCqUcY2irpPl4deZ6Eg。出处：原始面经。

GRPO训练的数据流

回答： 提示进入采样器，由明确版本的旧策略为每题生成多个输出；奖励模块给出评分，再按题组计算优势，整理有效Token、旧log概率和参考策略所需信息；训练器计算裁剪目标及正则，反向更新策略；更新后的版本再进入后续采样。

需要保留题组边界，防止把不同问题的奖励混合归一化；处理padding、截断与零方差；异步流程还需记录采样策略版本并控制数据滞后。工具Agent额外保存动作、观察和外部状态，以便复现及重置环境。仅保留最终文本无法解释全部轨迹失败。

延伸追问（自拟）：奖励服务变更后旧数据还能混用吗？ 需要判断奖励定义是否兼容。定义发生改变时，原分数未必可比较，应记录奖励版本，决定重评分、分组使用或排除，不能直接当成同分布数据。
