1d:T289e,<h2 id="section-长度最小的子数组题意与窗口目标">一、题目一：长度最小的子数组</h2>
<section class="problem"><div class="problem-heading"><strong>209. 长度最小的子数组</strong><a href="https://leetcode.cn/problems/minimum-size-subarray-sum/" rel="noopener noreferrer">力扣原题 ↗</a></div><p><strong>题目要求</strong></p><p>输入正整数数组nums和正整数target。在nums中选择一段连续、非空的子数组，使它的元素总和大于或等于target。</p><p>返回满足条件的最短长度；如果整份输入里没有满足条件的子数组，返回0。子数组必须保留原来的相邻关系，不能从不同位置挑出几个数拼成一段。</p><div class="examples"><p><strong>示例1</strong></p><p>输入：<code>target = 7, nums = [2,3,1,2,4,3]</code></p><p>输出：<code>2</code></p><p>末尾的[4,3]之和为7，长度为2；没有单个元素达到7，因此最短长度是2。</p></div><div class="examples"><p><strong>示例2</strong></p><p>输入：<code>target = 4, nums = [1,4,4]</code></p><p>输出：<code>1</code></p><p>任选其中一个4就已经达标。</p></div><div class="examples"><p><strong>示例3</strong></p><p>输入：<code>target = 11, nums = [1,1,1,1,1,1,1,1]</code></p><p>输出：<code>0</code></p><p>全部元素相加也只有8，不存在达标区间。</p></div><p><strong>约束条件</strong></p><ul><li>1 ≤ target ≤ 10⁹</li><li>1 ≤ nums.length ≤ 10⁵</li><li>1 ≤ nums[i] ≤ 10⁴</li></ul><p><strong>进阶要求：完成O(n)解法后，还可以尝试实现O(n log n)的解法。</strong></p></section>
<p>做完<a href="/blog/longest-substring-without-repeating-characters/">无重复字符的最长子串</a>后，我继续尝试用左右边界维护一个连续区间。不过，209要找的是<strong>和已经达标时，长度最短的窗口</strong>。这会改变收缩窗口的目的，也会改变记录答案的位置。</p>
<h3 id="section-从枚举区间到保留一个可以继续修改的窗口">1.1 从枚举区间到保留一个可以继续修改的窗口</h3>
<p>先暂时只用数组和循环考虑。最直接的办法是选定一个起点，再逐个加入右边的数，直到总和达到target。因为所有数都是正数，对于这个起点而言，第一次达标就已经得到最短候选，再往右延长只会增加长度。然后换一个起点，重新做相同的事情。</p>
<p>这个办法能够求出答案，不过相邻起点会反复经过同一批元素。以<code>target=7、nums=[2,3,1,2,4,3]</code>为例，从下标0出发，依次得到2、5、6、8，第一次达标的是<code>[2,3,1,2]</code>；接着从下标1开始时，3、1、2这些刚加过的数又需要重新参与计算。即使每次都用一个变量累加，最坏也要枚举接近<code>n(n+1)/2</code>个位置组合，时间仍为O(n²)。</p>
<p>因此可以进一步考虑：<strong>换起点时能否保留已有的区间和，只减去离开的元素，而不从头重算？</strong>上面的窗口总和为8，删去开头的2后，剩下<code>[3,1,2]</code>，总和直接变成6。此时不够7，再把右边的4加入，就得到总和10。这些变化只涉及两个边界，不需要重新遍历中间的元素，这就是滑动窗口能节省的工作。</p>
<p>但只会更新总和还不够，还需要决定什么时候移动哪一端。这里可以分成两种情况：<strong>和不够时，加入右边的新元素；和已经够时，先把当前长度作为候选，再尝试删除左端，看看能否更短。</strong>正整数使这两个操作的方向很明确：加入会使和增加，删除会使和减少。</p>
<p>第3题需要先排除重复，恢复合法窗口，再记录长度；209则要在窗口达标时尝试缩短，<strong>每次移除左端之前，都有一个合法候选需要检查</strong>。两个题都在移动边界，但检查条件和记录答案的顺序需要重新从题意推出来。</p>
<h3 id="section-第一版的末尾窗口漏检">1.2 第一版的末尾窗口漏检</h3>
<p>我原先把扩展和收缩拆成了两部分：先检查手里已有的窗口，和已经够了就缩短；不够时，再把右边的新元素加进来。单看一次循环，这个顺序似乎也能继续向前走，所以写的时候没有把“最后一次加入后还会不会再检查”单独考虑进去。问题就出在这里：加入后的检查实际被留给了下一轮，而最后一次扩展之后已经没有下一轮了。</p>
<p>具体看代码时，先明确它使用的区间约定：<code>right</code>表示右开边界，<code>total</code>对应<code>nums[left:right]</code>，窗口长度为<code>right-left</code>。也就是说，下标right处的数还没有加入。关于这种右端不包含的范围，可以回看<a href="/blog/python-slices/">切片的起止下标</a>。</p>

<p>以<code>target=7、nums=[7]</code>为例，开始时和为0，不会进入收缩循环。随后把7加入，<code>right</code>变成1，已经等于数组长度，外层循环直接结束。<strong>刚加入的7还没有接受达标检查，答案就被返回了</strong>，所以得到0。</p>

<p>这组只有一个元素的输入，把问题缩小到了最明显的一步：扩展成功并不等于已经处理了扩展后的结果。修正时需要把<strong>加入元素和检查新窗口放在同一轮</strong>，保证最后一次加入也有机会更新答案。</p>
<p>同样的问题也出现在<code>[2,3,1,2,4,3]</code>中：最后加入3后，本来还能把窗口缩成<code>[4,3]</code>，第一版却提前结束，留下的最短长度是3。</p>
<p>代码里的<code>right-left+1</code>也需要结合它出现的位置看。这里是先把<code>left</code>加1，再计算长度，因此数值恰好等于收缩前的<code>right-left_old</code>。这条算式本身没有多算一位，不过它使用的是<strong>修改后的下标，表达修改前的长度</strong>，读起来比较绕。把记录放回删除之前，区间含义就一致了。</p>

<h3 id="section-起点无需回退的依据正整数与最短窗口">1.4 起点无需回退的依据：正整数与最短窗口</h3>
<p>这里起作用的是题目中的<strong>正整数条件</strong>。右端加入一个数，和增大；左端移出一个数，和减小。因此，固定右端后，可以不断缩短达标窗口，直到第一次不达标。</p>
<p>一个起点被移出前，已经记录过以它开始、以当前右端结束的合法窗口。将来右端只会更靠后，继续使用这个起点得到的窗口更长，不会改善最短答案。所以<strong>左边界可以一直向前，不需要回退重新尝试这些起点</strong>。</p>
<p>这也解释了内层为什么是<code>while</code>：一次扩展后，可能有多个起点都能形成达标窗口，只收缩一次会留下更短的候选没有检查。</p>
<p>还可以反过来检查停止条件。假设当前窗口已经不达标，继续删去左边的正数只会让和更小，所以此时所有“右端不变、左端继续向右”的候选都不用再试。等右端加入新元素后，才重新有可能达标。这样，扩展和收缩各自什么时候继续、什么时候停止，都有了依据。</p>
<p><strong>循环不变量是：每次加入新右端之前，total准确表示此前尚未排除的窗口；所有已经移出的起点，都有一个已检查过、且不会被未来更长窗口改善的候选。</strong>这说明左端一直前进并没有随意漏掉起点。能够安全排除旧起点，才是把两层枚举减少到一次扫描的关键。</p>
<h3 id="section-209的时间空间复杂度与边界">1.5 209的时间、空间复杂度与边界</h3>
<p>右端读取每个元素一次，最多移动n次；左端也只会从0移到n，每个元素至多被删除一次。虽然代码中有两层循环，收缩循环的总次数仍不超过n，因此<strong>总时间复杂度为O(n)，额外空间为O(1)</strong>。代码只保存边界、和与答案，没有为每个窗口创建切片。</p>
<p><code>best=n+1</code>表示还没找到答案，最后转为题目要求的0。单个元素就达标时应返回1；整个数组的和仍不够时返回0；最优窗口位于数组末尾时也必须检查，<code>[7]</code>就是很直接的测试。</p>
<p>如果数组允许负数，删除左端可能使和增大，未达标时继续扩展也可能让和减小，上面的移动证明就不成立了。例如<code>target=3、nums=[1,-1,3]</code>，直接照搬这段代码会停在长度3，漏掉末尾的<code>[3]</code>。<strong>这种最短且和至少达标的问题，不能仅凭“有前缀和和哈希表”就套用等值查询</strong>；后面的<a href="/blog/prefix-sum/">560前缀和笔记</a>处理的是另一种条件。</p>
<p>题目还给出了O(n log n)的进阶方向。可以先建立前缀和P；由于nums全为正数，P严格递增。固定起点left后，寻找最早满足<code>P[end]≥P[left]+target</code>的end，就得到该起点的最短达标区间，这次查找可以使用二分搜索。对n个起点分别二分，总时间为O(n log n)，前缀表占O(n)空间。它把“每个起点向右找终点”改成了有序表查询，而滑动窗口进一步利用了不同起点之间可以连续推进的关系。这里先保留两条思路的联系，前缀和的含义可以在关联文章中展开理解。</p>
<h2 id="section-找到字符串中所有字母异位词从集合到频次统计">二、题目二：找到字符串中所有字母异位词</h2>
<section class="problem"><div class="problem-heading"><strong>438. 找到字符串中所有字母异位词</strong><a href="https://leetcode.cn/problems/find-all-anagrams-in-a-string/" rel="noopener noreferrer">力扣原题 ↗</a></div><p><strong>题目要求</strong></p><p>输入两个字符串s和p，找出s中所有与p互为字母异位词的连续子串，返回这些子串在s中的起始下标，下标从0开始。结果列表的排列顺序没有要求。</p><p>字母异位词可以调整字母的排列顺序，但每种字母的出现次数必须相同。因此候选子串的长度也必须等于p的长度。</p><div class="examples"><p><strong>示例1</strong></p><p>输入：<code>s = "cbaebabacd", p = "abc"</code></p><p>输出：<code>[0,6]</code></p><p>起点0对应cba，起点6对应bac，两段都各有一个a、b、c。</p></div><div class="examples"><p><strong>示例2</strong></p><p>输入：<code>s = "abab", p = "ab"</code></p><p>输出：<code>[0,1,2]</code></p><p>三个长度为2的子串依次是ab、ba、ab，全部满足要求；这些子串允许重叠。</p></div><p><strong>约束条件</strong></p><ul><li>1 ≤ s.length, p.length ≤ 3 × 10⁴</li><li>s和p的字符都属于小写英文字母a～z。</li></ul></section>
<p>这次需要比较的是字符组成。最初我先考虑把字符串变成集合，看看窗口与p里包含的字符是否一样。这个办法能够忽略排列顺序，但字符重复时也会被集合合并，所以接着又需要考虑：重复的次数应该保存在哪里，保存下来以后，又怎样比较两个窗口？</p>
<p>这样就从“有没有这个字符”，转到了“每个字符分别出现几次”。频次字典同时保存字符和数量，而两个字典是否相等，正好可以用来判断这些数量有没有一一对应。</p>
<p><strong>字母异位词要求各字符的出现次数相同，排列顺序可以不同。</strong><code>aab</code>与<code>abb</code>都包含a和b，集合相同，但前者有两个a，后者有两个b，所以只记录“出现过哪些字符”还不够。</p>
<p>用频次字典保存<code>字符→次数</code>后，<code>aab</code>对应<code>{a:2,b:1}</code>，<code>abb</code>对应<code>{a:1,b:2}</code>，缺少的区别就保留下来了。Python的<code>Counter(p)</code>可以直接统计p中的字符；它属于计数映射，下面只用到创建、按键读取和比较，不需要先记全它的API。</p>
<h3 id="section-固定窗口长度再复用相邻子串的字符统计">2.1 固定窗口长度，再复用相邻子串的字符统计</h3>
<p>异位词可以交换顺序，但不能增加或删除字符。因此，如果p长m，每个候选的长度就已经确定为m。无需再像209那样尝试各种长度，只需要依次检查起点0、1、2……对应的定长子串。</p>
<p>一种直接写法是对每个长度为m的子串重新统计。例如p为<code>abc</code>时，先统计s的前三个字符，再统计第2到第4个字符。这样容易理解，但相邻子串有m−1个位置是相同的，每次重新计数会反复处理这些字符，最坏需要O(NM)时间。</p>
<p>既然相邻候选只相差两个边界，就可以保留一张窗口频次表：<strong>右边进来一个字符，就把它的次数加1；左边离开一个字符，就把它的次数减1。</strong>以<code>s="abab"、p="ab"</code>为例，首个窗口<code>ab</code>的计数为<code>{a:1,b:1}</code>，下一步移出a、加入a，表仍然相同，但窗口起点已经从0变为1，对应的子串是<code>ba</code>。</p>
<p>到这一步，两个原本混在一起的问题就分清楚了：边界负责确定正在检查哪一段，频次表负责说明这一段包含什么。<strong>比较字典是在比较字符和次数组成的映射，插入顺序不影响普通dict的相等判断。</strong>如果对按键查询还不熟悉，可以先看<a href="/blog/hash-table-introduction/">哈希表与Python字典</a>，再回来对照这里保存的内容。</p>

<p>最终采用的定义是：<strong>match表示p中有多少种字符，其窗口计数已经至少达到需求数量。</strong>设p中有K种字符，全部达标时<code>match==K</code>。</p>

<table><thead><tr><th>操作</th><th>b的计数变化</th><th>是否跨过“达到2次”的门槛</th><th>match变化</th></tr></thead><tbody><tr><td>加入b</td><td>1→2</td><td>从不足到达标</td><td>+1</td></tr><tr><td>加入b</td><td>2→3</td><td>仍然达标</td><td>不变</td></tr><tr><td>移出b</td><td>3→2</td><td>仍然达标</td><td>不变</td></tr><tr><td>移出b</td><td>2→1</td><td>从达标到不足</td><td>−1</td></tr></tbody></table>
<p><strong>这里没有在“超过需求”时减去match，因为它记录的是至少达标，不是恰好相等。</strong>按照这个定义，每次只检查新加入或被移出的那一种字符，就能维护计数。</p>
<p>这也是写更新条件之前需要先明确变量含义的原因。假如把match理解成“恰好相等的字符种类数”，那么2→3时也必须减1，3→2时又必须加1；这同样可以设计成另一种算法，但维护规则就不同了。当前代码使用“至少达到需求”的定义，所以只在跨过不足与达标的门槛时变化，不能在解释中临时把它改成恰好相等。</p>
<p>对应到代码，入窗时先加次数，再看新次数是否刚好等于need；出窗时先减次数，再看新次数是否刚好变成need−1。前者说明这次加入刚好补足需求，后者说明这次移出刚好使需求不足。<strong>两处判断都在检查当前操作是否跨过达标阈值，所以只有跨过时才修改match。</strong>这样理解后，就不必把几个if当作互不相关的写法去记。</p>

<h4 id="section-固定窗口长度将全部达标转为频次相等">2.4.3 固定窗口长度将全部达标转为频次相等</h4>
<p>答案检查还有一个条件：<strong>窗口长度恰好为m，也就是p中所有需求次数的总和。</strong></p>
<p>当每种字符都至少够用时，窗口至少需要m个字符；现在窗口正好只有m个位置。如果某种字符还多占一个位置，其他字符就必然有一种不够，与“全部达标”冲突。因此，在这个长度下，全部至少满足就能推出各频次恰好相等。</p>
<p>如果改成长度大于m的窗口，这个结论就不能沿用。比如<code>p="ab"</code>，窗口<code>aab</code>中两种需求都满足，却不是异位词。它可以被视为覆盖了需求，但不能作为438的答案。</p>
