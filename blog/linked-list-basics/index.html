链表

  1. 链表（一）：节点、引用与next连接知识点

做合并、删除这几道链表题时，最容易影响后续操作的地方，是一个变量还在不在原位置，以及某条next是否已经被改掉。先把这两件事分清楚，再看哑节点与三道链表题的完整复盘，指针移动就比较容易跟上了。

一、单链表的组成：节点、入口与结束位置

单链表由一组节点组成，每个节点保存数据，以及指向下一个节点的引用next。它的顺序由next连接决定，不要求节点在内存中连续存放。下面用一个简单的Python类表示节点：

python
# 定义一个单链表节点
class ListNode:
    # 创建节点时，可以同时指定数值和后继节点
    def __init__(self, val=0, next=None):
        # val保存这个节点的数据
        self.val = val
        # next保存后继节点的引用；None表示没有后继
        self.next = next

这里的val是数据，next是连接；两者负责的事情不同。假设有三个节点A1、A2、A3，数值分别是2、2、5，可以画成下面这样：

A1、A2是不同的节点，只是val恰好都为2。图中的ID用于区分对象，不是题目额外提供的字段。head保存首节点A1的引用，通过head.next找到A2，再通过A2.next找到A3；A3.next为None，表示链表到这里结束。

空链表的head直接为None，没有任何数据节点。None也不是一个值为0的节点，因此不能访问None.val或None.next。

二、变量赋值与next修改的区别

2.1 移动变量只改变查找位置

执行cur=head后，cur与head指向同一个A1，并没有复制节点。继续执行cur=cur.next，cur改为指向A2，head仍然指向A1，A1→A2这条连接也没有变化。

操作完成后headcurA1.next
cur=headA1A1A2
cur=cur.nextA1A2A2

这就是Python对象引用的常见行为：多个变量可以指向同一个对象，给变量重新赋值不会自动修改那个对象的内容。可以结合Python官方文档中的对象与别名理解。

因此，pre=head只让pre也指向头节点，并不能凭空让pre变成“头节点前面的节点”。变量名可以叫pre，但它是否真是前驱，要由实际连接位置判断。

2.2 修改next会改变节点之间的关系

如果执行head.next=head.next.next，左侧访问的是A1的next属性，右侧得到A3，结果是把A1.next由A2改为A3。沿head继续遍历时，就会从A1直接到A3。

这时A2本身并没有被改成None，A2.next仍然指向A3。从主链表绕过一个节点，与清空这个节点的所有属性不是一回事。如果还有别的变量指向A2，通过那个变量仍然能访问它。

链表图最好一直保留节点ID，并明确标出被改写的边。只展示数值序列，很容易看不出到底移动了变量，还是改动了连接。

三、插入与删除：先找到需要修改的前驱

3.1 在pre后插入节点，先保存后面的连接

原来是pre→cur，现在要在两者之间插入node。可以按以下顺序连接：

python
# 让新节点先接上原来的后继，保留后面的链表
node.next = pre.next
# 再让前驱接到新节点，形成pre→node→cur
pre.next = node

先保存原后继，再改前驱的next。如果先写pre.next=node，再写node.next=pre.next，第二行读到的已经是node自己，会把node.next接回自身。也可以先用另一个变量保存原后继，再调整写入顺序，关键是改写之后仍然能够找到尚未处理的节点。

3.2 删除pre后面的节点，让前驱直接接到后继

若目标为cur，且已经确认pre.next is cur，删除可以写成：

python
# 让前驱绕过cur，直接连接cur原来的后继
pre.next = cur.next

删除后，pre仍然是下一处待检查位置的前驱。例如连续两个节点都需要删除，第一次绕过cur以后，应继续检查新的pre.next；如果直接把pre也向后移，可能跳过第二个待删节点。

已知前驱时，插入或删除只需固定次数的连接修改，是O(1)操作；如果需要先从head寻找前驱，查找最坏还要O(L)时间。只说“链表删除是O(1)”会漏掉这个前提，L表示链表长度。

四、哑节点：为头部操作补一个固定前驱

普通节点前面有pre，可以通过pre.next修改连接；头节点前面没有数据节点，删除或前插时就需要单独更新head。若这些特判反复出现，可以增加一个不计入结果的辅助节点dummy，让dummy.next指向原head。

哑节点（dummy node）为头部提供了固定前驱，使原头节点也能用普通的连接修改处理。它的val不参与题目的数据比较，返回时通常取dummy.next。链表为空时，dummy仍存在，但dummy.next为None。

合并两条链表时，也可以让dummy起初指向None，用tail从dummy开始逐个接入已有节点。此时dummy负责保存结果入口，tail负责记录已选前缀的末端，两者的职责不同。

哑节点没有消除所有边界条件，仍要根据题目处理空输入、结束位置和指针移动。它主要统一的是需要修改前驱next、但头部原本没有前驱这一类情况。具体推导、成环错误和n/n+1两种间距，见哑节点（一）：三道链表题的复盘。

五、单链表常见操作的复杂度

操作时间条件或原因
读取已经持有的节点的val或nextO(1)直接访问节点属性
从head定位第k个节点O(k)，最坏O(L)需要沿next逐个前进，不能直接按下标跳到该节点
遍历整条无环链表O(L)每个节点访问一次
在已知前驱后插入或删除一个节点O(1)只改固定数量的next连接
先查找目标，再修改连接最坏O(L)查找成本通常占主要部分

链表本身保存L个节点，需要O(L)存储空间；遍历时只增加cur等固定变量，遍历算法的辅助空间可以是O(1)。后者不包含已经给定的输入链表。用原节点重连与为每个结果新建节点，额外空间也不同，需要结合具体代码判断。
