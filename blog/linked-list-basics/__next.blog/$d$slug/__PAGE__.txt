2a:T2511,<p>做合并、删除这几道链表题时，最容易影响后续操作的地方，是一个变量还在不在原位置，以及某条next是否已经被改掉。先把这两件事分清楚，再看<a href="/blog/dummy-node-linked-lists/">哑节点与三道链表题的完整复盘</a>，指针移动就比较容易跟上了。</p>
<h2 id="section-单链表的组成节点入口与结束位置">一、单链表的组成：节点、入口与结束位置</h2>
<p><strong>单链表由一组节点组成，每个节点保存数据，以及指向下一个节点的引用next。</strong>它的顺序由next连接决定，不要求节点在内存中连续存放。下面用一个简单的Python类表示节点：</p>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-comment"># 定义一个单链表节点</span>
<span class="hljs-keyword">class</span> <span class="hljs-title class_">ListNode</span>:
    <span class="hljs-comment"># 创建节点时，可以同时指定数值和后继节点</span>
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">__init__</span>(<span class="hljs-params">self, val=<span class="hljs-number">0</span>, <span class="hljs-built_in">next</span>=<span class="hljs-literal">None</span></span>):
        <span class="hljs-comment"># val保存这个节点的数据</span>
        <span class="hljs-variable language_">self</span>.val = val
        <span class="hljs-comment"># next保存后继节点的引用；None表示没有后继</span>
        <span class="hljs-variable language_">self</span>.<span class="hljs-built_in">next</span> = <span class="hljs-built_in">next</span>
</code></pre></div>
<p>这里的<code>val</code>是数据，<code>next</code>是连接；两者负责的事情不同。假设有三个节点A1、A2、A3，数值分别是2、2、5，可以画成下面这样：</p>
<figure class="explain-figure"><figcaption>节点值相同，也仍是两个不同对象</figcaption><div class="ll-figure-scroll" tabindex="0"><img src="/images/algorithms/dummy-node/basics.svg" alt="节点值相同，也仍是两个不同对象" loading="lazy" decoding="async" referrerpolicy="no-referrer"></div></figure>
<p><strong>A1、A2是不同的节点，只是val恰好都为2。</strong>图中的ID用于区分对象，不是题目额外提供的字段。head保存首节点A1的引用，通过head.next找到A2，再通过A2.next找到A3；A3.next为None，表示链表到这里结束。</p>
<p>空链表的head直接为None，没有任何数据节点。None也不是一个值为0的节点，因此不能访问None.val或None.next。</p>
<h2 id="section-变量赋值与next修改的区别">二、变量赋值与next修改的区别</h2>
<h3 id="section-移动变量只改变查找位置">2.1 移动变量只改变查找位置</h3>
<p>执行<code>cur=head</code>后，cur与head指向同一个A1，并没有复制节点。继续执行<code>cur=cur.next</code>，cur改为指向A2，head仍然指向A1，A1→A2这条连接也没有变化。</p>























<table><thead><tr><th>操作完成后</th><th>head</th><th>cur</th><th>A1.next</th></tr></thead><tbody><tr><td>cur=head</td><td>A1</td><td>A1</td><td>A2</td></tr><tr><td>cur=cur.next</td><td>A1</td><td>A2</td><td>A2</td></tr></tbody></table>
<p>这就是Python对象引用的常见行为：<strong>多个变量可以指向同一个对象，给变量重新赋值不会自动修改那个对象的内容。</strong>可以结合<a href="https://docs.python.org/3/tutorial/classes.html#objects-and-individuality" rel="noopener noreferrer">Python官方文档中的对象与别名</a>理解。</p>
<p>因此，<code>pre=head</code>只让pre也指向头节点，并不能凭空让pre变成“头节点前面的节点”。<strong>变量名可以叫pre，但它是否真是前驱，要由实际连接位置判断。</strong></p>
<h3 id="section-修改next会改变节点之间的关系">2.2 修改next会改变节点之间的关系</h3>
<p>如果执行<code>head.next=head.next.next</code>，左侧访问的是A1的next属性，右侧得到A3，结果是把A1.next由A2改为A3。沿head继续遍历时，就会从A1直接到A3。</p>
<p>这时A2本身并没有被改成None，A2.next仍然指向A3。<strong>从主链表绕过一个节点，与清空这个节点的所有属性不是一回事。</strong>如果还有别的变量指向A2，通过那个变量仍然能访问它。</p>
<p>链表图最好一直保留节点ID，并明确标出被改写的边。只展示数值序列，很容易看不出到底移动了变量，还是改动了连接。</p>
<h2 id="section-插入与删除先找到需要修改的前驱">三、插入与删除：先找到需要修改的前驱</h2>
<h3 id="section-在pre后插入节点先保存后面的连接">3.1 在pre后插入节点，先保存后面的连接</h3>
<p>原来是<code>pre→cur</code>，现在要在两者之间插入node。可以按以下顺序连接：</p>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-comment"># 让新节点先接上原来的后继，保留后面的链表</span>
node.<span class="hljs-built_in">next</span> = pre.<span class="hljs-built_in">next</span>
<span class="hljs-comment"># 再让前驱接到新节点，形成pre→node→cur</span>
pre.<span class="hljs-built_in">next</span> = node
</code></pre></div>
<p><strong>先保存原后继，再改前驱的next。</strong>如果先写<code>pre.next=node</code>，再写<code>node.next=pre.next</code>，第二行读到的已经是node自己，会把node.next接回自身。也可以先用另一个变量保存原后继，再调整写入顺序，关键是改写之后仍然能够找到尚未处理的节点。</p>
<h3 id="section-删除pre后面的节点让前驱直接接到后继">3.2 删除pre后面的节点，让前驱直接接到后继</h3>
<p>若目标为cur，且已经确认<code>pre.next is cur</code>，删除可以写成：</p>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-comment"># 让前驱绕过cur，直接连接cur原来的后继</span>
pre.<span class="hljs-built_in">next</span> = cur.<span class="hljs-built_in">next</span>
</code></pre></div>
<p>删除后，pre仍然是下一处待检查位置的前驱。例如连续两个节点都需要删除，第一次绕过cur以后，应继续检查新的pre.next；如果直接把pre也向后移，可能跳过第二个待删节点。</p>
<p><strong>已知前驱时，插入或删除只需固定次数的连接修改，是O(1)操作；如果需要先从head寻找前驱，查找最坏还要O(L)时间。</strong>只说“链表删除是O(1)”会漏掉这个前提，L表示链表长度。</p>
<h2 id="section-哑节点为头部操作补一个固定前驱">四、哑节点：为头部操作补一个固定前驱</h2>
<p>普通节点前面有pre，可以通过pre.next修改连接；头节点前面没有数据节点，删除或前插时就需要单独更新head。若这些特判反复出现，可以增加一个不计入结果的辅助节点dummy，让dummy.next指向原head。</p>
<p><strong>哑节点（dummy node）为头部提供了固定前驱，使原头节点也能用普通的连接修改处理。</strong>它的val不参与题目的数据比较，返回时通常取dummy.next。链表为空时，dummy仍存在，但dummy.next为None。</p>
<p>合并两条链表时，也可以让dummy起初指向None，用tail从dummy开始逐个接入已有节点。此时dummy负责保存结果入口，tail负责记录已选前缀的末端，两者的职责不同。</p>
<p>哑节点没有消除所有边界条件，仍要根据题目处理空输入、结束位置和指针移动。它主要统一的是<strong>需要修改前驱next、但头部原本没有前驱</strong>这一类情况。具体推导、成环错误和n/n+1两种间距，见<a href="/blog/dummy-node-linked-lists/">哑节点（一）：三道链表题的复盘</a>。</p>
