先保持HTTP语义，再看数据怎样传输

请求方法、状态码、字段和资源语义贯穿不同HTTP版本。GET获取表示、POST提交处理，不会因为底层换成QUIC就变成另一套业务接口。版本变化主要体现在消息怎样编码、复用连接和传输。

HTTP/1.1默认支持持久连接，一条连接可以承载多个请求。管线化允许提前发送后续请求，但响应顺序仍有限制。HTTP/1.0常见连接生命周期较短，不过存在持久连接扩展，因此不能把“1.0绝不复用”写成绝对规则。HTTP/1.1消息与连接

多路复用让多个逻辑请求在一条连接上交错传输。它减少等待和重复建连的机会，但需要继续问：这些逻辑流在更底层是否还依赖同一条有序字节流？

HTTP/2怎样交错传输两个资源

假设A是一张大图，B是一段很小的配置。HTTP/2把消息分成二进制帧，并用流标识区分请求，可以按A1、B1、A2这样的顺序发送。客户端按流重组后，小配置B不必在应用协议层等整个A传完。

HTTP/2还使用HPACK压缩字段。GET、路径和Host等HTTP语义仍然存在，只是编码形式变了。流级控制、连接级控制和调度影响实际发送顺序，多路复用本身不保证重要资源永远优先。HTTP/2协议结构

接着改变一个条件：装有A1部分字节的TCP段丢失，后面的TCP段已经到达，其中包含B1。TCP向上提供有序字节流，前面缺口未补齐时，后面的字节不能按普通流接口越过缺口交付给HTTP/2。 因此不同HTTP流仍可能一起等待底层重传，这就是TCP层面的队头阻塞。

QUIC怎样把可靠性放到流内部

HTTP/3把HTTP语义映射到QUIC。QUIC运行在UDP之上，自己实现连接、包号、确认、丢失检测、流量控制、拥塞控制和加密等机制；UDP只是承载，可靠性来自QUIC协议。

QUIC流是带顺序的字节流，各流拥有各自的偏移。仍用A、B两个流举例：若只承载A数据的包丢失，而B所需数据已经到齐，B可以继续交付；A在自己的缺口处等待。若同一个包同时装了A和B的数据，包丢失仍会影响这两个流。QUIC流与传输

重传时需要重新发送的是尚需交付的信息，不是机械地复用原来的包号。确认和丢失检测也需要区分包号空间与握手阶段。QUIC丢失检测

这并不表示流完全互不影响。它们仍共享连接资源和网络拥塞条件；某个流占满带宽会影响其他流的可用容量。HTTP/3的QPACK字段压缩也有明确的依赖与阻塞控制，不能总结为“HTTP/3彻底消除了所有等待”。HTTP/3与QPACK

握手和网络迁移带来了什么变化

QUIC集成TLS1.3进行安全协商，不使用“先建立TCP，再额外进行TLS”的同一分层路径。首次连接、恢复连接和0-RTT需要分开：0-RTT有前置状态和重放限制，不能承诺所有首次访问都无需等待。

连接标识Connection ID使QUIC连接的识别不完全绑死在一个IP地址与端口组合上。手机从Wi-Fi切到移动网络时，路径可能改变，协议可以在验证新路径等条件下继续连接。它不保证任何切网都无损，也不意味着服务端可以忽略地址验证与滥用风险。

如果网络阻断UDP，HTTP/3连接可能建立失败，客户端应考虑回退到基于TCP的HTTP版本。评价收益要结合客户端支持、代理、丢包和路径情况；同机低延迟测试不一定体现高时延移动网络上的收益。

怎样做一个能解释差异的对照实验

在受控环境中准备相同的A、B资源，固定服务逻辑，记录连接是否复用、协议版本、首字节和完成时间。先比较正常网络，再增加可控丢包；每次都记录配置与多次测量分布。

观察点至少有两个：B是否需要等A处理完成，以及传输丢失后B能否继续获得数据。前者可能是服务器业务串行，后者才与传输的交付依赖有关。只看到“HTTP/3这次快20ms”，不能直接确定是哪一层改善。

本篇没有改动网络配置或执行流量整形。这里给出的是实验设计和预期机制，真实结果还需要记录工具、协议协商和服务端实现。

面试问答：HTTP/3与QUIC

HTTP3 和 QUIC 了解不？

回答： HTTP/3是HTTP在QUIC上的映射，QUIC是基于UDP实现的安全多路复用传输协议。它提供可靠的流、确认与丢失检测、流量和拥塞控制，并集成TLS1.3。HTTP/2在TCP上复用流，仍受TCP有序交付缺口影响；QUIC把有序交付放在各流内部，某个流缺数据时，其他数据完整的流可以继续。

例如A、B两个资源，丢失包只影响A时，QUIC中的B可以继续交付。两者仍共享带宽和拥塞条件，同包丢失或字段压缩依赖也可能造成等待。连接ID支持路径迁移，但需要新路径验证等条件。实际收益依赖网络与部署，UDP受限时还要考虑回退。

延伸追问（自拟）：既然UDP不可靠，换UDP为什么反而能可靠传文件？ 应用可以在UDP数据报之上增加确认、重传、顺序和流控。QUIC完整规定了这些行为；“用了UDP”描述承载方式，不决定上层协议是否提供可靠字节流。

原问见逐题映射，TCP与窗口基础见拥塞控制。
