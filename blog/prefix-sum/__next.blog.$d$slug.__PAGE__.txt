2d:T40be,<h2 id="section-区域和检索用累计结果消除重复求和">一、题目一：区域和检索—数组不可变</h2>
<section class="problem"><div class="problem-heading"><strong>303. 区域和检索—数组不可变</strong><a href="https://leetcode.cn/problems/range-sum-query-immutable/" rel="noopener noreferrer">力扣原题 ↗</a></div><p><strong>题目要求</strong></p><p>输入整数数组nums，此后数组内容保持不变，需要多次回答指定区间的元素总和。</p><p>实现NumArray类：NumArray(nums)接收并初始化数组；sumRange(left,right)返回nums[left]到nums[right]的和，包含两个端点，下标从0开始。</p><div class="examples"><p><strong>示例1</strong></p><p>输入：<code>操作 = ["NumArray","sumRange","sumRange","sumRange"]
参数 = [[[-2,0,3,-5,2,-1]],[0,2],[2,5],[0,5]]</code></p><p>输出：<code>[null,1,-1,-3]</code></p><p>先创建对象，构造步骤在输出序列中记为null。随后三次查询分别计算-2+0+3=1、3-5+2-1=-1，以及整个数组的和-3。</p></div><p><strong>约束条件</strong></p><ul><li>1 ≤ nums.length ≤ 10⁴</li><li>−10⁵ ≤ nums[i] ≤ 10⁵</li><li>0 ≤ left ≤ right &#x3C; nums.length</li><li>sumRange最多被调用10⁴次。</li></ul></section>
<p>数组不变，却需要多次查询不同区间的和。如果只查一次，直接循环相加就可以；但题目允许多次查询，重叠部分就会被反复累加。例如先查询下标0到2，再查询0到5，前面三个元素又会完整加一次。若还要查询2到5，其中一些元素还会继续重复参与计算。</p>
<p>因此可以先考虑把已经算过的结果保存下来。不过，保存所有区间的和需要对应O(n²)个区间，空间太多。更方便的一种选择是：<strong>只保存从数组开头到各个位置的累计和，再用较长的一段减去前面多出来的一段。</strong>两段的起点都是0，被减掉的部分完全相同，剩下的就是需要查询的区间。这种累计结果就叫作<strong>前缀和</strong>。</p>
<h3 id="section-前缀下标表示已累计的元素数量">1.1 前缀长度、数组下标与区间求和公式</h3>
<p>令<code>P[0]=0</code>，<code>P[i]</code>表示原数组前i个元素之和。原数组长n，前缀表就有n＋1项：</p>
<p><span class="katex"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>P</mi><mo stretchy="false">[</mo><mi>i</mi><mo>+</mo><mn>1</mn><mo stretchy="false">]</mo><mo>=</mo><mi>P</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo>+</mo><mi>n</mi><mi>u</mi><mi>m</mi><mi>s</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo></mrow><annotation encoding="application/x-tex">P[i+1]=P[i]+nums[i]</annotation></semantics></math></span></p>
<p>对于从0开始的闭区间<code>[l,r]</code>，<code>P[r+1]</code>包含下标0到r，减去包含0到l−1的<code>P[l]</code>，恰好留下所需部分：</p>
<p><span class="katex"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi mathvariant="normal">sum</mi><mo>⁡</mo><mo stretchy="false">(</mo><mi>n</mi><mi>u</mi><mi>m</mi><mi>s</mi><mo stretchy="false">[</mo><mi>l</mi><mo>:</mo><mi>r</mi><mo>+</mo><mn>1</mn><mo stretchy="false">]</mo><mo stretchy="false">)</mo><mo>=</mo><mi>P</mi><mo stretchy="false">[</mo><mi>r</mi><mo>+</mo><mn>1</mn><mo stretchy="false">]</mo><mo>−</mo><mi>P</mi><mo stretchy="false">[</mo><mi>l</mi><mo stretchy="false">]</mo></mrow><annotation encoding="application/x-tex">\operatorname{sum}(nums[l:r+1])=P[r+1]-P[l]</annotation></semantics></math></span></p>
<p><strong>P[i]的下标i表示已经累计的元素数量。</strong>读入原数组下标i处的元素后，累计数量增加到i+1，因此写入的是P[i+1]。预先设置<strong>空前缀P[0]=0</strong>，从数组开头开始的查询也可以直接使用同一条相减公式。</p>
<p>这里的<code>r+1</code>和<code>l</code>可以根据包含了多少个元素分别确定，不必把公式单独背下来。要包含原数组下标r，前缀必须有r+1项；要删除l之前的部分，正好删除前l项。因此，保留到r用<code>P[r+1]</code>，去掉l之前用<code>P[l]</code>。如果左右两边都随意加1，就会连下标l处需要保留的元素也一起删去。</p>
<figure class="explain-figure"><figcaption>前缀长度与原数组下标要分别看</figcaption><div class="lane"><b>nums下标0、1、2</b><div class="cells"><div class="cell"><small>下标0</small><b>2</b></div><div class="cell active"><small>下标1</small><b>-1</b></div><div class="cell active"><small>下标2</small><b>3</b></div></div></div><div class="prefix-grid"><div class=""><small>P[0] · 前0项</small><b>0</b></div><div class="selected"><small>P[1] · 前1项</small><b>2</b></div><div class=""><small>P[2] · 前2项</small><b>1</b></div><div class="selected"><small>P[3] · 前3项</small><b>4</b></div></div><p>绿色选中的原数组区间为[1,2]。蓝框选出两个累计量：<b>P[3]−P[1]＝4−2＝2</b>，去掉了前1项。</p></figure>
<p>例如<code>nums=[2,-1,3]</code>，前缀表为<code>[0,2,1,4]</code>。原数组区间<code>[1,2]</code>的和是<code>P[3]-P[1]=4-2=2</code>。前缀和允许负数，前缀表也可能下降；构造和相减都不要求表有序。</p>






























<table><thead><tr><th>前缀位置</th><th>累计了哪些元素</th><th>值</th></tr></thead><tbody><tr><td>P[0]</td><td>尚未包含元素</td><td>0</td></tr><tr><td>P[1]</td><td>[2]</td><td>2</td></tr><tr><td>P[2]</td><td>[2,-1]</td><td>1</td></tr><tr><td>P[3]</td><td>[2,-1,3]</td><td>4</td></tr></tbody></table>
<p>查询下标1到2时，P[3]先包含了整段<code>[2,-1,3]</code>，再减去P[1]对应的<code>[2]</code>，剩下的正是<code>[-1,3]</code>。如果查询从0开始，就减P[0]；如果只查下标1这一个数，就用<code>P[2]-P[1]=1-2=-1</code>。这几种边界都能用同一套定义处理。</p>
<h3 id="section-在numarray中预处理一次之后直接查询">1.2 NumArray的预处理与多次查询</h3>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">class</span> <span class="hljs-title class_">NumArray</span>:

    <span class="hljs-keyword">def</span> <span class="hljs-title function_">__init__</span>(<span class="hljs-params">self, nums: <span class="hljs-built_in">list</span>[<span class="hljs-built_in">int</span>]</span>):
        <span class="hljs-comment"># prefix[i]表示前i个数之和，prefix[0]是空前缀。</span>
        <span class="hljs-variable language_">self</span>.prefix = [<span class="hljs-number">0</span>]
        <span class="hljs-keyword">for</span> value <span class="hljs-keyword">in</span> nums:
            <span class="hljs-variable language_">self</span>.prefix.append(<span class="hljs-variable language_">self</span>.prefix[-<span class="hljs-number">1</span>] + value)

    <span class="hljs-keyword">def</span> <span class="hljs-title function_">sumRange</span>(<span class="hljs-params">self, left: <span class="hljs-built_in">int</span>, right: <span class="hljs-built_in">int</span></span>) -> <span class="hljs-built_in">int</span>:
        <span class="hljs-comment"># 题目是闭区间[left,right]，对应前缀下标right+1与left。</span>
        <span class="hljs-keyword">return</span> <span class="hljs-variable language_">self</span>.prefix[right + <span class="hljs-number">1</span>] - <span class="hljs-variable language_">self</span>.prefix[left]
</code></pre></div>
<p>初始化需要扫描n项，花O(n)时间、O(n)额外空间。每次<code>sumRange</code>只读取两项并相减，是O(1)时间；q次查询加上初始化，总时间为<strong>O(n+q)</strong>。</p>
<p>预处理放在构造函数里，是为了让后续查询复用同一张表。假如每次调用sumRange时重新创建前缀表，虽然最后的相减仍然只有一步，整个查询却还包含O(n)的建表成本，重复查询的优势就消失了。<strong>一次准备、多次使用，是303中前缀和节省时间的前提。</strong></p>
<p>直接使用<code>sum(nums[left:right+1])</code>时，每次都要重新扫描，还会创建切片，最坏总时间为O(nq)。<strong>前缀表省去的是每次查询时的重复加法与切片</strong>，准备这张表所需的O(n)时间计入初始化。</p>
<p>单点区间返回该元素，整段查询返回最后的前缀值。题目保证<code>0&#x3C;=left&#x3C;=right&#x3C;n</code>；这份代码没有另外提供非法下标检查。<strong>数组不可变也是前提</strong>：原数组改变后，这张静态表不会自动更新。</p>
<h2 id="section-560和为k的子数组把区间关系改写成旧前缀查询">二、题目二：和为K的子数组</h2>
<section class="problem"><div class="problem-heading"><strong>560. 和为K的子数组</strong><a href="https://leetcode.cn/problems/subarray-sum-equals-k/" rel="noopener noreferrer">力扣原题 ↗</a></div><p><strong>题目要求</strong></p><p>输入整数数组nums和整数k，统计其中元素总和恰好等于k的连续、非空子数组数量，返回这个数量。</p><p>这里的子数组由原数组相邻位置组成。不同的起止位置对应不同子数组，即使它们的元素内容相同，也需要分别统计。</p><div class="examples"><p><strong>示例1</strong></p><p>输入：<code>nums = [1,1,1], k = 2</code></p><p>输出：<code>2</code></p><p>下标区间[0,1]与[1,2]的和都是2，因此统计为两段。</p></div><div class="examples"><p><strong>示例2</strong></p><p>输入：<code>nums = [1,2,3], k = 3</code></p><p>输出：<code>2</code></p><p>满足条件的是[1,2]和单独的[3]。</p></div><p><strong>约束条件</strong></p><ul><li>1 ≤ nums.length ≤ 2 × 10⁴</li><li>−1000 ≤ nums[i] ≤ 1000</li><li>−10⁷ ≤ k ≤ 10⁷</li></ul></section>
<p>303已经给定区间两端，560需要找出所有满足条件的区间。即使每个区间的和都能O(1)计算，n个元素仍然有<code>n(n+1)/2</code>个非空连续区间，逐一枚举的时间还是O(n²)。</p>
<p>这个数量可以按起点算出来：从下标0出发有n种终点，从下标1出发有n−1种，依次减少到最后一个起点只剩1种。<strong>前缀和将每一对边界的求和降为O(1)</strong>，接下来还需要减少枚举边界组合的次数。<strong>要继续优化，需要处理的瓶颈已经从“怎样求一段的和”，变成“怎样少枚举一些起点”。</strong></p>
<details class="extra">

<p>进一步固定当前右边界。用半开区间<code>[start,end)</code>表示子数组，所需条件可以改写成：</p>
<p><span class="katex"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>P</mi><mo stretchy="false">[</mo><mi>e</mi><mi>n</mi><mi>d</mi><mo stretchy="false">]</mo><mo>−</mo><mi>P</mi><mo stretchy="false">[</mo><mi>s</mi><mi>t</mi><mi>a</mi><mi>r</mi><mi>t</mi><mo stretchy="false">]</mo><mo>=</mo><mi>k</mi><mspace width="1em"></mspace><mo>⟹</mo><mspace width="1em"></mspace><mi>P</mi><mo stretchy="false">[</mo><mi>s</mi><mi>t</mi><mi>a</mi><mi>r</mi><mi>t</mi><mo stretchy="false">]</mo><mo>=</mo><mi>P</mi><mo stretchy="false">[</mo><mi>e</mi><mi>n</mi><mi>d</mi><mo stretchy="false">]</mo><mo>−</mo><mi>k</mi></mrow><annotation encoding="application/x-tex">P[end]-P[start]=k\quad\Longrightarrow\quad P[start]=P[end]-k</annotation></semantics></math></span></p>
<p><strong>当前前缀P[end]已知后，需要的旧前缀值就确定了，剩下的是查它以前出现过多少次。</strong>因此可以用哈希表保存<code>旧前缀和→出现次数</code>，不再逐个枚举起点。</p>
<p>这个变形可以先用数值理解。假设当前从头累计到右端的总和是10，希望截出和为3的一段，就需要在前面找到累计和为7的位置，把那一段前缀去掉。所有累计和为7的旧位置都可以作为截断点，不需要再检查累计和为6、8或其他值的位置。<strong>固定当前右端后，合法起点虽然可能不止一个，但它们需要满足的前缀值只有一个：当前累计和减k。</strong></p>
<p>这正好适合哈希查询：扫描时把更早的前缀值记录下来，以后直接根据这个值查数量。没有命中就增加0个答案，命中几次就增加几个答案。前缀和负责把连续区间变成两个边界值的关系，哈希表负责省去逐个查找旧边界的过程，两部分各自解决了一个问题。</p>
<h3 id="section-旧前缀频次对应所有合法起点">2.1 相同前缀的出现次数与合法起点</h3>
<p>不同起点可能有相同的前缀和。例如<code>[1,-1,1]</code>中，空前缀为0，读完前两个元素后的前缀也为0。它们分别对应起点0和起点2，都能与最后的前缀1组成和为1的子数组。</p>
<p>集合只能回答有没有这个旧前缀，最后一个下标只能保留一个起点；<strong>统计所有合法区间时，需要把相同前缀对应的起点数量全部加进答案</strong>。</p>
<p>对于<code>[1,-1,1]</code>，前缀表若完整写出来就是<code>[0,1,0,1]</code>。最后一个前缀是P[3]=1，需要找旧前缀0。P[0]=0对应从原数组下标0开始，P[2]=0对应从下标2开始，因此得到<code>[0,3)</code>与<code>[2,3)</code>这两段。它们用了同一个右边界，却有不同起点，所以不能因为前缀数值相同就合并成一个答案。</p>

<p>这张表按“查询时看到什么”来写，是为了把当前前缀与旧前缀区分开。当前元素已经加入running，说明右端已经确定；但当前running还没有加入频次表，所以表中记录的都是位于它之前的截断位置。</p>
<h3 id="section-空前缀初始化与先查询再记录的顺序">2.2 空前缀初始化与先查询再记录的顺序</h3>
<p>初始<code>frequency={0:1}</code>表示<strong>数组还没读入任何元素时，累计和0已经出现一次</strong>。这样，从下标0开始、恰好和为k的区间也能被查询到。<strong>这条记录提供了位于数组开头的可用起点</strong>，等读到后面的元素、累计和恰好为k时，才能与当前右端组成一个答案。</p>
<p>每轮先查询<code>running-k</code>，再把当前running加入表中。这个顺序保证查到的前缀都来自以前，即<strong>start&#x3C;end，区间至少包含一个元素</strong>。如果先记当前前缀，在k＝0时就会把当前前缀与自身配对，错误计入空区间。</p>
<p>最小的检查例子是<code>nums=[0]、k=0</code>。开始时表里只有空前缀<code>{0:1}</code>；读入这个0后，running仍为0，查询得到1，对应唯一的非空子数组<code>[0]</code>，随后才把次数增加到2。若先增加再查询，就会得到2，其中多出来的一次是用“读完这个元素后的前缀”减去它自己，实际上没有选中任何元素。</p>
<p>空前缀和空子数组也需要区分：<strong>空前缀是位于数组开头、尚未读取元素的一个合法边界；空子数组则是起止边界相同、长度为0的区间。</strong>前者参与初始化，能和后面的右边界组成非空答案；后者不符合题目条件，通过先查询再记录将它排除。</p>
<p>以<code>[0,0,0]、k=0</code>为例，三个右端分别能得到1、2、3个有效起点，总数为6。频次表中的0依次从1增加到4，但每一步查询使用的是增加前的次数。</p>
<p><strong>循环不变量是：查询当前前缀时，表中恰好记录所有更早前缀的出现次数，答案已包含此前各右端对应的合法区间。</strong>当前右端新增的区间数由一次频次查询给出，随后记录当前前缀，供下一轮使用。每个区间只会在它自己的右端被统计一次。</p>
<h3 id="section-560的时间空间与适用边界">2.3 子数组计数的复杂度与输入条件</h3>
<p>每个元素只进行一次累计、一次哈希查询和一次频次更新。在哈希操作平均O(1)的前提下，<strong>总时间为平均O(n)，辅助空间最坏为O(n)</strong>。如果所有前缀都不同，表中最多保存n＋1个键；前缀重复时，对应键的次数增加，键的总数可以少一些。因此，<strong>辅助空间按最多n＋1条记录分析，为O(n)</strong>。</p>
<p>这里无需另外保存完整的前缀数组，只维护当前累计和及旧频次。与前缀枚举法相比，省掉的是枚举旧起点的工作。用大整数时还需考虑整数运算成本，本文按题目范围采用常见的单位操作复杂度口径。</p>
<p>负数和0都可以正常处理，因为<strong>等值哈希查询不依赖前缀的单调性</strong>。没有满足条件的区间返回0；k为负也不影响关系式。原题输入非空，代码额外兼容空列表并返回0。</p>
<p>这份解法通过<strong>旧前缀的频次</strong>保留所有可用起点，当前右端只负责查询并累计答案。遇到负数后，区间延长可能让总和减小，删去左端也可能让总和增大，大小关系无法像209那样直接决定移动方向；但“两个前缀相减等于k”仍然始终成立。因此，<strong>通用的等值计数方案保留旧前缀频次，付出最坏O(n)空间，换取平均O(n)时间，并能够处理负数和0</strong>。如果题目只给正数，可能还有利用单调性的方案，那是额外条件带来的选择。</p>
<h2 id="section-与两数之和的联系查询关系式需要的旧信息">三、前缀查询与两数之和补数查询的联系</h2>
<p>前面的<a href="/blog/two-sum/">两数之和</a>也会把配对条件改写成查询：当前元素为x，就寻找旧元素<code>target-x</code>。560复用了这一步思考，但配对对象已经变成两个前缀。</p>























<table><thead><tr><th>问题</th><th>当前已知量</th><th>需要查询的旧量</th><th>哈希表保存什么</th></tr></thead><tbody><tr><td>两数之和</td><td>元素x</td><td>target−x</td><td>旧元素值→下标</td></tr><tr><td>560子数组计数</td><td>当前前缀running</td><td>running−k</td><td>旧前缀和→次数</td></tr></tbody></table>
<p><strong>先把关系式整理成一次旧信息查询，再根据输出要求决定表中保存什么。</strong>两数之和要返回位置，所以存下标；560要统计数量，所以存频次。两题的查询值都来自各自的关系式：两数之和由<code>x+need=target</code>得到<code>need=target-x</code>，子数组计数由<code>running-old=k</code>得到<code>old=running-k</code>。<strong>先写等式，再移项确定要查的键</strong>，减法方向就有了依据。</p>
<p>如果对字典的查询方式还不熟悉，可以回看<a href="/blog/hash-table-introduction/">哈希表介绍</a>。这里关心的是如何把区间关系转换成键，以及对应值为什么必须是次数。</p>
<h3 id="section-与209和差分数组的区别">3.1 前缀和、滑动窗口与差分的适用条件</h3>
