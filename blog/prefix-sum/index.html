区域和检索：用累计结果消除重复求和

303. 区域和检索—数组不可变力扣原题 ↗

题目要求

输入整数数组nums，此后数组内容保持不变，需要多次回答指定区间的元素总和。

实现NumArray类：NumArray(nums)接收并初始化数组；sumRange(left,right)返回nums[left]到nums[right]的和，包含两个端点，下标从0开始。

示例1

输入：操作 = ["NumArray","sumRange","sumRange","sumRange"] 参数 = [[[-2,0,3,-5,2,-1]],[0,2],[2,5],[0,5]]

输出：[null,1,-1,-3]

先创建对象，构造步骤在输出序列中记为null。随后三次查询分别计算-2+0+3=1、3-5+2-1=-1，以及整个数组的和-3。

约束条件

  • 1 ≤ nums.length ≤ 10⁴
  • −10⁵ ≤ nums[i] ≤ 10⁵
  • 0 ≤ left ≤ right < nums.length
  • sumRange最多被调用10⁴次。

数组不变，却需要多次查询不同区间的和。如果只查一次，直接循环相加就可以；但题目允许多次查询，重叠部分就会被反复累加。例如先查询下标0到2，再查询0到5，前面三个元素又会完整加一次。若还要查询2到5，其中一些元素还会继续重复参与计算。

因此可以先考虑把已经算过的结果保存下来。不过，保存所有区间的和需要对应O(n²)个区间，空间太多。更方便的一种选择是：只保存从数组开头到各个位置的累计和，再用较长的一段减去前面多出来的一段。两段的起点都是0，被减掉的部分完全相同，剩下的就是需要查询的区间。这种累计结果就叫作前缀和。

前缀下标表示已累计的元素数量

令P[0]=0，P[i]表示原数组前i个元素之和。原数组长n，前缀表就有n＋1项：

P[i+1]=P[i]+nums[i]P[i+1]=P[i]+nums[i]

对于从0开始的闭区间[l,r]，P[r+1]包含下标0到r，减去包含0到l−1的P[l]，恰好留下所需部分：

sum⁡(nums[l:r+1])=P[r+1]−P[l]\operatorname{sum}(nums[l:r+1])=P[r+1]-P[l]

P的下标是前缀长度，并不等于正在加入的元素下标。空前缀0使从数组开头出发的区间也能用同一条公式，无需给l＝0另写分支。

这里的r+1和l可以根据包含了多少个元素分别确定，不必把公式单独背下来。要包含原数组下标r，前缀必须有r+1项；要删除l之前的部分，正好删除前l项。因此，保留到r用P[r+1]，去掉l之前用P[l]。如果左右两边都随意加1，就会连下标l处需要保留的元素也一起删去。

例如nums=[2,-1,3]，前缀表为[0,2,1,4]。原数组区间[1,2]的和是P[3]-P[1]=4-2=2。前缀和允许负数，前缀表也可能下降；构造和相减都不要求表有序。

前缀位置累计了哪些元素值
P[0]尚未包含元素0
P[1][2]2
P[2][2,-1]1
P[3][2,-1,3]4

查询下标1到2时，P[3]先包含了整段[2,-1,3]，再减去P[1]对应的[2]，剩下的正是[-1,3]。如果查询从0开始，就减P[0]；如果只查下标1这一个数，就用P[2]-P[1]=1-2=-1。这几种边界都能用同一套定义处理。

在NumArray中预处理一次，之后直接查询

python
class NumArray:

    def __init__(self, nums: list[int]):
        self.prefix = [0]  # prefix[i]表示前i个数之和，prefix[0]是空前缀。
        for value in nums:
            self.prefix.append(self.prefix[-1] + value)

    def sumRange(self, left: int, right: int) -> int:
        # 题目是闭区间[left,right]，对应前缀下标right+1与left。
        return self.prefix[right + 1] - self.prefix[left]

初始化需要扫描n项，花O(n)时间、O(n)额外空间。每次sumRange只读取两项并相减，是O(1)时间；q次查询加上初始化，总时间为O(n+q)。

预处理放在构造函数里，是为了让后续查询复用同一张表。假如每次调用sumRange时重新创建前缀表，虽然最后的相减仍然只有一步，整个查询却还包含O(n)的建表成本，重复查询的优势就消失了。一次准备、多次使用，是303中前缀和节省时间的前提。

直接使用sum(nums[left:right+1])时，每次都要重新扫描，还会创建切片，最坏总时间为O(nq)。前缀表省去的就是这部分重复加法与切片，不会把初始化本身也变成O(1)。

单点区间返回该元素，整段查询返回最后的前缀值。题目保证0<=left<=right<n；这份代码没有另外提供非法下标检查。数组不可变也是前提：原数组改变后，这张静态表不会自动更新。

560和为K的子数组：把区间关系改写成旧前缀查询

560. 和为K的子数组力扣原题 ↗

题目要求

输入整数数组nums和整数k，统计其中元素总和恰好等于k的连续、非空子数组数量，返回这个数量。

这里的子数组由原数组相邻位置组成。不同的起止位置对应不同子数组，即使它们的元素内容相同，也需要分别统计。

示例1

输入：nums = [1,1,1], k = 2

输出：2

下标区间[0,1]与[1,2]的和都是2，因此统计为两段。

示例2

输入：nums = [1,2,3], k = 3

输出：2

满足条件的是[1,2]和单独的[3]。

约束条件

  • 1 ≤ nums.length ≤ 2 × 10⁴
  • −1000 ≤ nums[i] ≤ 1000
  • −10⁷ ≤ k ≤ 10⁷

303已经给定区间两端，560需要找出所有满足条件的区间。即使每个区间的和都能O(1)计算，n个元素仍然有n(n+1)/2个非空连续区间，逐一枚举的时间还是O(n²)。

这个数量可以按起点算出来：从下标0出发有n种终点，从下标1出发有n−1种，依次减少到最后一个起点只剩1种。前缀和只是把每一对边界的求和变快了，并没有自动减少边界组合的数量。要继续优化，需要处理的瓶颈已经从“怎样求一段的和”，变成“怎样少枚举一些起点”。

展开前缀和＋枚举两端的推导版本
python
def subarray_sum_quadratic(nums: list[int], k: int) -> int:
    prefix = [0]
    for value in nums:
        prefix.append(prefix[-1] + value)
    answer = 0
    for end in range(1, len(prefix)):
        for start in range(end):
            if prefix[end] - prefix[start] == k:
                answer += 1
    return answer

进一步固定当前右边界。用半开区间[start,end)表示子数组，所需条件可以改写成：

P[end]−P[start]=k⟹P[start]=P[end]−kP[end]-P[start]=k\quad\Longrightarrow\quad P[start]=P[end]-k

当前前缀P[end]已知后，需要的旧前缀值就确定了，剩下的是查它以前出现过多少次。因此可以用哈希表保存旧前缀和→出现次数，不再逐个枚举起点。

这个变形可以先用数值理解。假设当前从头累计到右端的总和是10，希望截出和为3的一段，就需要在前面找到累计和为7的位置，把那一段前缀去掉。所有累计和为7的旧位置都可以作为截断点，不需要再检查累计和为6、8或其他值的位置。固定当前右端后，合法起点虽然可能不止一个，但它们需要满足的前缀值只有一个：当前累计和减k。

这正好适合哈希查询：扫描时把更早的前缀值记录下来，以后直接根据这个值查数量。没有命中就增加0个答案，命中几次就增加几个答案。前缀和负责把连续区间变成两个边界值的关系，哈希表负责省去逐个查找旧边界的过程，两部分各自解决了一个问题。

旧前缀频次对应所有合法起点

不同起点可能有相同的前缀和。例如[1,-1,1]中，空前缀为0，读完前两个元素后的前缀也为0。它们分别对应起点0和起点2，都能与最后的前缀1组成和为1的子数组。

集合只能回答有没有这个旧前缀，最后一个下标只能保留一个起点；统计所有合法区间时，需要把相同前缀对应的起点数量全部加进答案。

对于[1,-1,1]，前缀表若完整写出来就是[0,1,0,1]。最后一个前缀是P[3]=1，需要找旧前缀0。P[0]=0对应从原数组下标0开始，P[2]=0对应从下标2开始，因此得到[0,3)与[2,3)这两段。它们用了同一个右边界，却有不同起点，所以不能因为前缀数值相同就合并成一个答案。

python
def subarray_sum_hash(nums: list[int], k: int) -> int:
    frequency = {0: 1}  # 空前缀出现一次，允许统计从下标0开始的子数组。
    running = answer = 0
    for value in nums:
        running += value
        # P[end]-P[start]=k，因此需要以前出现过的P[start]=running-k。
        answer += frequency.get(running - k, 0)
        # 先查询再加入，防止k=0时把当前前缀与自身配对成空子数组。
        frequency[running] = frequency.get(running, 0) + 1
    return answer

这张表按“查询时看到什么”来写，是为了把当前前缀与旧前缀区分开。当前元素已经加入running，说明右端已经确定；但当前running还没有加入频次表，所以表中记录的都是位于它之前的截断位置。

空前缀初始化与先查询再记录的顺序

初始frequency={0:1}表示数组还没读入任何元素时，累计和0已经出现一次。这样，从下标0开始、恰好和为k的区间也能被查询到。这里不是预先记录了一个答案，而是记录一个可用起点。

每轮先查询running-k，再把当前running加入表中。这个顺序保证查到的前缀都来自以前，即start<end，区间至少包含一个元素。如果先记当前前缀，在k＝0时就会把当前前缀与自身配对，错误计入空区间。

最小的检查例子是nums=[0]、k=0。开始时表里只有空前缀{0:1}；读入这个0后，running仍为0，查询得到1，对应唯一的非空子数组[0]，随后才把次数增加到2。若先增加再查询，就会得到2，其中多出来的一次是用“读完这个元素后的前缀”减去它自己，实际上没有选中任何元素。

空前缀和空子数组也需要区分：空前缀是位于数组开头、尚未读取元素的一个合法边界；空子数组则是起止边界相同、长度为0的区间。前者参与初始化，能和后面的右边界组成非空答案；后者不符合题目条件，通过先查询再记录将它排除。

以[0,0,0]、k=0为例，三个右端分别能得到1、2、3个有效起点，总数为6。频次表中的0依次从1增加到4，但每一步查询使用的是增加前的次数。

循环不变量是：查询当前前缀时，表中恰好记录所有更早前缀的出现次数，答案已包含此前各右端对应的合法区间。当前右端新增的区间数由一次频次查询给出，随后记录当前前缀，供下一轮使用。每个区间只会在它自己的右端被统计一次。

560的时间、空间与适用边界

每个元素只进行一次累计、一次哈希查询和一次频次更新。在哈希操作平均O(1)的前提下，总时间为平均O(n)，辅助空间最坏为O(n)。如果所有前缀都不同，表中最多保存n＋1个键；许多前缀重复时，键数会更少，但不能因此把一般空间复杂度写成O(1)。

这里无需另外保存完整的前缀数组，只维护当前累计和及旧频次。与前缀枚举法相比，省掉的是枚举旧起点的工作。用大整数时还需考虑整数运算成本，本文按题目范围采用常见的单位操作复杂度口径。

负数和0都可以正常处理，因为等值哈希查询不依赖前缀的单调性。没有满足条件的区间返回0；k为负也不影响关系式。原题输入非空，代码额外兼容空列表并返回0。

这里也没有尝试根据总和大小移动某个左边界。遇到负数后，区间延长可能让总和减小，删去左端也可能让总和增大，大小关系无法像209那样直接决定移动方向；但“两个前缀相减等于k”仍然始终成立。因此，通用的等值计数方案保留旧前缀频次，付出最坏O(n)空间，换取平均O(n)时间，并能够处理负数和0。如果题目只给正数，可能还有利用单调性的方案，那是额外条件带来的选择。

与两数之和的联系：查询关系式需要的旧信息

前面的两数之和也会把配对条件改写成查询：当前元素为x，就寻找旧元素target-x。560复用了这一步思考，但配对对象已经变成两个前缀。

问题当前已知量需要查询的旧量哈希表保存什么
两数之和元素xtarget−x旧元素值→下标
560子数组计数当前前缀runningrunning−k旧前缀和→次数

先把关系式整理成一次旧信息查询，再根据输出要求决定表中保存什么。两数之和要返回位置，所以存下标；560要统计数量，所以存频次。两个式子的减法方向也不同，不能把560写成查询k-running。

如果对字典的查询方式还不熟悉，可以回看哈希表介绍。这里关心的是如何把区间关系转换成键，以及对应值为什么必须是次数。

与209和差分数组的区别

209最短达标子数组要求的是和至少为target，前缀关系为P[end]-P[start]>=target。只查询running-target会漏掉超过目标的窗口，例如target＝7、nums=[8]的答案应为1。560的等值查询适用于“恰好等于k”，不能直接代替209的最短区间搜索。

差分数组则保存相邻元素的变化量，对这些变化进行前缀累加，就恢复原值。303用两个累计值相减来查询，1109用两个边界修改来记录更新；它们都利用了区间两端，但方向和用途不同。
