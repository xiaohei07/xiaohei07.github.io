一、题目一：合并两个有序链表

21. 合并两个有序链表力扣原题 ↗

题目要求

给定两条单链表的头节点list1和list2，两条链表的节点值都按非递减顺序排列。请把它们合并为一条同样有序的链表，并返回合并后链表的头节点。

合并时使用输入链表的已有节点，调整节点之间的连接，把两条链表的节点全部接到结果中。

示例1

输入：list1 = [1,2,4], list2 = [1,3,4]

输出：[1,1,2,3,4,4]

两条链表的6个节点全部保留，合并后仍按非递减顺序连接。

示例2

输入：list1 = [], list2 = []

输出：[]

两条链表都为空，结果也为空。

示例3

输入：list1 = [], list2 = [0]

输出：[0]

第一条链表为空，直接返回第二条链表。

约束条件

  • 每条输入链表分别包含0到50个节点。
  • 每个节点的值在−100到100之间。
  • list1和list2各自按非递减顺序排列。

我最开始考虑的是以第一条链表为基础，把第二条链表的节点逐个插进去。两条链表本来就有序，只要一边比较一边向后移动，就不用每插入一个节点都重新从头寻找位置。这条思路是可以做对的，不过真正写代码时，头节点的处理比中间位置多了一层问题：插到当前节点前面，需要修改它的前驱；但原来的头节点并没有前驱。

下面先沿着这几次修改看清问题，再引出哑节点。后面的“移除链表元素”和“删除链表的倒数第N个结点”，也会用到同一个前驱关系。

1.1 链表中的节点、变量和next连接

单链表里的每个节点保存一个值val，以及指向下一个节点的next。head或list1保存的是入口节点的引用；从入口开始不断读取next，才能沿链表向后访问。最后一个节点的next为None，表示后面没有节点。

节点对象、指向对象的变量、对象自身的next连接，需要分别看。例如pre=list1只会让两个变量引用同一个节点；pre.next=list2则会修改这个节点的next，让链表连接发生变化。这也是Python关于名称与对象的说明中所说的多个名称绑定同一个对象。

语句实际改变的内容
pre=list1pre与list1指向同一个现有节点，没有新建节点
list1=list1.nextlist1变量移到后继节点，节点的next没有因此改动
pre.next=list2pre所指节点的next改为指向list2所指节点
dummy=ListNode(0,head)创建一个独立节点，并将它的next接到head

图中的A1、A2和B1等是节点身份。两个节点的值都为4，它们仍然是两个对象，合并时都要保留。如果还不熟悉这种表示，可以先看链表（一）：节点、引用与next连接，其中把访问、插入和删除单独整理了一遍。

1.2 首次插入：pre为空时无法修改前驱的next

先看最短的头插例子：第一条只有节点A1，值为2；第二条只有节点B1，值为1。B1应该排在A1前面。

首版先令pre=None，表示还没有经过前面的节点。发现1小于2后，先执行list2_pos.next=list1_pos，建立B1→A1；接下来执行pre.next=list2_pos，想让前驱接向B1。问题就在第二步：A1原本是头节点，pre确实没有可以指向的前驱，所以访问None.next会报错。

顺序操作已经得到的结构
1pre=NoneA1前面没有节点
2B1.next=A1B1→A1→None
3pre.next=B1pre为None，无法完成这次连接

在普通位置插入时，修改前驱的next确实能把新节点接进来。但要把同样的操作用到头部，就必须先解决前驱是否存在，以及结果入口是否需要改变这两个问题。

展开首版错误代码：pre为空时仍访问next
python
# 错误版V1：头前没有前驱
class Solution:
    # 沿用力扣方法接口，节点类型由题目提供
    def mergeTwoLists(self, list1: ListNode | None, list2: ListNode | None) -> ListNode | None:
        # 尚无已处理节点，当前位置暂时没有前驱
        pre=None
        # 用工作指针访问第一条链表，list1仍保存原始入口
        list1_pos = list1
        # 用工作指针访问第二条链表，list2仍保存原始入口
        list2_pos = list2
        # 两边均有待处理节点时继续比较
        while list1_pos!=None and list2_pos!=None:
            # 修改当前list2节点的next之前，保存其原后继
            list2_then = list2_pos.next
            # 第二条当前节点更小，尝试将它插到第一条当前节点前
            if list2_pos.val < list1_pos.val:
                # 先将待插入节点接向第一条当前节点
                list2_pos.next = list1_pos
                # 修改前驱连接；V1未处理pre为空的头插情形，会在此报错
                pre.next = list2_pos
                # 插入后把新节点记为当前list1节点的前驱
                pre=list2_pos
                # 恢复第二条链表尚未处理部分的入口
                list2_pos = list2_then
            # 第二条当前节点不更小，考虑保留当前第一条节点或在其后插入
            else:
                # 第一条当前节点已经位于末尾，准备连接剩余部分
                if list1_pos.next is None:
                    # 保留V1错误：接回第二条原始头，可能把已插入节点接成环
                    list1_pos.next = list2
                    # 连接完成后退出循环，不再逐个处理剩余段
                    break
                # 第二条当前节点可以放在第一条当前节点与其后继之间
                if list2_pos.val <= list1_pos.next.val:
                    # 保存第一条当前节点原后继，避免插入时丢失
                    list1_then = list1_pos.next
                    # 将前面的节点接向待插入节点
                    list1_pos.next = list2_pos
                    # 将插入节点接回第一条原后继
                    list2_pos.next = list1_then

                    # 保存插入位置前面的节点
                    pre = list1_pos
                    # 把刚插入节点设为新的当前位置，继续向后比较
                    list1_pos = list2_pos
                    # 恢复第二条链表尚未处理部分的入口
                    list2_pos = list2_then

                # 第二条当前值比第一条后继还大，继续向后寻找插入位置
                else:
                    # 保存插入位置前面的节点
                    pre = list1_pos
                    # 沿第一条当前连接继续向后寻找位置
                    list1_pos = list1_pos.next

        # 返回第一条链表的入口；V1未处理第一条为空而第二条非空的情形
        return list1

1.3 第二次修改：pre指向当前节点后形成了环

之后我把pre初始化为list1，希望让它先指向一个真实节点，同时增加了第一条为空时直接返回另一条的处理。空输入这一处补上了，但pre=list1没有补出前驱：它只是让pre和list1都指向A1，A1不会因为变量名叫pre就变成自己的前驱。

仍用A1（值2）和B1（值1）来看：

顺序执行语句连接变化
1pre=list1pre、list1和保存入口的head都指向A1
2list2.next=list1B1.next由None变为A1
3pre.next=list2实际修改A1.next，使它指向B1
4list2=list2_thenlist2移到None，函数循环可以结束
5return head返回A1，沿next会反复经过A1→B1→A1

这一版当时遇到的是“超出内存限制”。把节点关系展开后，可以明确看到返回链表里有环：后续如果一直沿next遍历，就不会遇到None。函数本身能够返回，与返回的链表能否正常遍历，是两件不同的事。这里复现的是成环结构，不据此猜测平台具体在哪个内部步骤耗尽了内存。

展开第二版错误代码：非空引用没有解决前驱关系

# 错误版V2：别名使连接成环
class Solution:
    # 沿用力扣方法接口，节点类型由题目提供
    def mergeTwoLists(self, list1: ListNode | None, list2: ListNode | None) -> ListNode | None:
        # 第一条链表为空时，直接处理另一条链表即可
        if list1 is None:
            # 返回第二条链表的入口
            return list2
        # 保存当前结果的头节点，避免移动工作指针后丢失入口
        head=list1
        # 记录当前list1节点；V2初始化时它不是头节点的前驱，不能据此直接头插
        pre=list1
        # 两条工作链表均非空时继续处理
        while list1!=None and list2!=None:
            # 在重连之前保存第二条链表的后续入口
            list2_then = list2.next
            # 第二条当前值更小，应插到第一条当前节点之前
            if list2.val < list1.val:
                # 让待插入节点指向当前第一条节点
                list2.next = list1
                # 将前驱接到第二条当前节点；V2初始化头插时pre其实等于list1，会成环
                pre.next = list2
                # 新插入节点成为当前list1节点的前驱
                pre=list2
                # 第二条工作指针前进到保存的后继
                list2 = list2_then
            # 第二条当前节点不更小，考虑保留当前第一条节点或在其后插入
            else:
                # 第一条当前节点已经到末尾，可以整段连接第二条剩余部分
                if list1.next is None:
                    # 将第一条当前节点接向第二条当前节点；需要保留的原后继已另行保存
                    list1.next = list2
                    # 连接完成后退出循环，不再逐个处理剩余段
                    break
                # 判断第二条当前值是否适合插入当前节点与其后继之间
                if list2.val <= list1.next.val:
                    # 保存第一条原后继，避免修改连接后失去入口
                    list1_then = list1.next
                    # 将第一条当前节点接向第二条当前节点；需要保留的原后继已另行保存
                    list1.next = list2
                    # 把新插入节点接回第一条原后继
                    list2.next = list1_then

                    # 记录当前list1节点；V2初始化时它不是头节点的前驱，不能据此直接头插
                    pre = list1
                    # 以刚插入的节点作为当前比较位置
                    list1 = list2
                    # 第二条工作指针前进到保存的后继
                    list2 = list2_then

                # 第二条当前值比第一条后继还大，继续向后寻找插入位置
                else:
                    # 记录当前list1节点；V2初始化时它不是头节点的前驱，不能据此直接头插
                    pre = list1
                    # 向后移动第一条工作指针；这行不修改任何节点的next
                    list1 = list1.next

        # 返回此前维护的结果头节点
        return head

1.4 区分头部与中间插入，先把原思路修正完整

这时再回头看，需要补的条件就清楚了：如果pre为空，新节点插在原头前面，应该更新head；如果pre非空，才通过pre.next把它接进去。这两种情况下，新节点自己的next都要接向当前节点，但接入结果链表的方式不同。

我接着按这个区别修改，得到下面的版本。当时的反馈是“好像通过了”；复盘时也用有限输入检查了它的结果。

展开原思路修正版：保留头插和中间插入的完整分支
python
# 原思路修正版：区分头部与普通插入
class Solution:
    # 沿用力扣方法接口，节点类型由题目提供
    def mergeTwoLists(self, list1: ListNode | None, list2: ListNode | None) -> ListNode | None:
        # 第一条链表为空时，直接处理另一条链表即可
        if list1 is None:
            # 返回第二条链表的入口
            return list2
        # 第二条链表为空时，第一条链表已是结果
        if list2 is None:
            # 返回第一条链表的入口
            return list1
        # 先将结果入口留空，第一次选定头节点时再设置
        head=None
        # 尚无已处理节点，当前位置暂时没有前驱
        pre=None
        # 两条工作链表均非空时继续处理
        while list1!=None and list2!=None:
            # 在重连之前保存第二条链表的后续入口
            list2_then = list2.next
            # 第二条当前值更小，应插到第一条当前节点之前
            if list2.val < list1.val:
                # 让待插入节点指向当前第一条节点
                list2.next = list1
                # 没有现成前驱时，必须单独维护结果头节点
                if pre is None:
                    # 插入节点成为结果的头节点
                    head=list2
                    # 新插入节点成为当前list1节点的前驱
                    pre=list2
                    # 连接到当前list1；在V3头插分支中，此连接刚刚已经设置过
                    pre.next = list1
                    # 第二条工作指针前进到保存的后继
                    list2=list2_then
                # 已有真实前驱，通过pre.next连接新插入节点
                else:
                    # 在pre确实存在的分支中，把前驱连接到新插入节点
                    pre.next = list2
                    # 新插入节点成为当前list1节点的前驱
                    pre=list2
                    # 第二条工作指针前进到保存的后继
                    list2 = list2_then
            # 第二条当前节点不更小，考虑保留当前第一条节点或在其后插入
            else:
                # 没有现成前驱时，必须单独维护结果头节点
                if pre is None:
                    # 保存当前结果的头节点，避免移动工作指针后丢失入口
                    head = list1
                    # 记录第一条当前节点，后续分支会完成插入、推进或尾部连接
                    pre = list1
                # 第一条当前节点已经到末尾，可以整段连接第二条剩余部分
                if list1.next is None:
                    # 将第一条当前节点接向第二条当前节点；需要保留的原后继已另行保存
                    list1.next = list2
                    # 连接完成后退出循环，不再逐个处理剩余段
                    break
                # 判断第二条当前值是否适合插入当前节点与其后继之间
                if list2.val <= list1.next.val:
                    # 保存第一条原后继，避免修改连接后失去入口
                    list1_then = list1.next
                    # 将第一条当前节点接向第二条当前节点；需要保留的原后继已另行保存
                    list1.next = list2
                    # 把新插入节点接回第一条原后继
                    list2.next = list1_then

                    # 记录第一条当前节点，后续分支会完成插入、推进或尾部连接
                    pre = list1
                    # 以刚插入的节点作为当前比较位置
                    list1 = list2
                    # 第二条工作指针前进到保存的后继
                    list2 = list2_then

                # 第二条当前值比第一条后继还大，继续向后寻找插入位置
                else:
                    # 记录第一条当前节点，后续分支会完成插入、推进或尾部连接
                    pre = list1
                    # 向后移动第一条工作指针；这行不修改任何节点的next
                    list1 = list1.next

        # 返回此前维护的结果头节点
        return head

这份代码比较长，是因为同时维护了头部变化、前插、当前与后继之间的插入、尾部接入等分支。不过，先把每个分支所依赖的节点关系处理正确，再考虑哪些分支可以合并，会比直接套一份短代码更容易看懂。

例如第一条为1→4，第二条为2→3：先经过1，当前节点到4时，把2插到4前面；4仍是尚待比较的节点，再把3插到4前面。这样就不必同时保留“插在当前节点前”和“插在当前与next之间”两套实现。后来参考的简化插入法就是沿着这个方向整理的。

展开补充写法：只保留前插与继续向后移动

# 补充：简化插入法
class Solution:

    def mergeTwoLists(self, list1: ListNode | None, list2: ListNode | None) -> ListNode | None:

        if list1 is None:
            # 直接返回第二条链表
            return list2
        # 第二条链表为空，无需插入
        if list2 is None:
            # 直接返回第一条链表
            return list1

        # 暂用原list1的头节点；发生头部插入时再更新
        head = list1
        # pre表示当前list1节点在合并链表中的前驱
        pre = None

        # 两边还有待处理节点时继续
        while list1 is not None and list2 is not None:
            # 当前list2节点应插到当前list1节点之前
            if list2.val < list1.val:

                list2_then = list2.next
                # 让待插入节点指向当前list1节点
                list2.next = list1
                # 当前list1节点仍是头节点，没有前驱
                if pre is None:
                    # 插入的节点成为合并链表的新头
                    head = list2
                # 当前list1节点前面已有处理好的节点
                else:
                    # 让原前驱接上新插入的节点
                    pre.next = list2
                # 新插入的节点成为当前list1节点的前驱
                pre = list2
                # 继续处理list2剩余部分，list1暂时不动
                list2 = list2_then
            # 当前list1节点更小或相等，可以保留在前面
            else:
                # 当前节点成为下一位置的前驱
                pre = list1
                # 走到下一节点，再判断是否需要在它前面插入
                list1 = list1.next

        # list1已走完，而list2还有剩余节点
        if list2 is not None:
            # 两条输入原先非空，循环已设置pre，可直接接上剩余段
            pre.next = list2
        # 返回始终维护的合并链表头节点
        return head

修改连接前保存list2_then也有明确用途：list2.next一旦被改成第一条链表的节点，第二条原来的后续入口就不能再从这个next读出来了。先保存它，处理完当前节点后才能继续第二条未处理的部分。

复盘补充：首版还混用了原始头和未处理入口

首版尾部接入写的是list1_pos.next=list2，这里的list2还是第二条的原始头。对[1,3]和[2,4]，2已经插到1与3之间；最后再把3接回旧头2，就会形成2→3→2的环。需要接入的是当前尚未处理的入口，而不是原来保存的整条链表头。

另外，首版遇到第一条为空、第二条非空时会直接返回空。这两处是这次回看旧代码时补充检查的边界，不能与当时逐次修改的过程混在一起。交互里的短例可以分别复现它们。

1.5 哑节点的推导：给第一次连接也提供一个前驱

原思路修正后，头部仍然需要单独判断。于是可以继续想：普通插入已经有pre.next这条操作，头部缺的恰好是一个前驱，能不能额外放一个不计入结果的节点，让真正的头节点也有前驱？

这个额外节点就是哑节点（dummy node），也是哨兵节点的一种用法：它是实际创建的辅助节点，用来提供稳定入口或头前位置，节点值不参与题目的数据处理。比如建立dummy→原头，以后更换或删除原头，就可以修改dummy.next；最终返回dummy.next，便不会把辅助节点算进结果。

构造合并结果时，dummy也可以先指向None，再把选中的节点逐个接到后面。OpenDSA链表教材也用辅助头节点处理边界，核心是补足普通操作需要的结构条件。

后来看到常见的dummy＋tail写法时，合并的组织方式也随之改变了：每轮从两条尚未处理的链表中选较小的头节点，接到已经选好顺序的前缀后面。dummy固定保存结果入口，tail负责连接，list1和list2各自保留未处理部分。

python
# 哑节点＋tail合并
class Solution:
    # 沿用力扣方法接口，节点类型由题目提供
    def mergeTwoLists(self, list1: ListNode | None, list2: ListNode | None) -> ListNode | None:
        # 创建固定的起点；它的值不参与比较，也不属于最终结果
        dummy = ListNode(0)
        # 开始时还没选中任何节点，尾指针先指向哑节点
        tail = dummy

        # 两条链表都还有未处理节点时进行比较
        while list1 is not None and list2 is not None:
            # list1的当前节点更小或相等，优先选择它
            if list1.val <= list2.val:
                # 把选中的节点接到已确定顺序的部分后面
                tail.next = list1
                # list1前进，指向这条输入链表下一个未处理节点
                list1 = list1.next
            # list2的当前节点更小，本轮选择它
            else:
                # 把选中的节点接到已确定顺序的部分后面
                tail.next = list2
                # list2前进，指向这条输入链表下一个未处理节点
                list2 = list2.next
            # 尾指针移动到本轮选中的节点
            tail = tail.next

        # list2已经耗尽，而list1还有剩余节点
        if list1 is not None:
            # 剩余部分本来就有序，直接整段接上
            tail.next = list1
        # list1已经耗尽；list2可能还有节点，也可能为空
        else:
            # 接上list2剩余部分；若也为空，就接上None
            tail.next = list2

        # 跳过哑节点，返回第一个真正的数据节点
        return dummy.next

1.7 合并方法的复杂度与边界

设两条链表长度分别为m、n。dummy版每轮都推进一条未处理输入，累计处理的节点数不会超过m+n，剩余段最后直接接入，所以时间复杂度为O(m+n)。原插入法的工作指针也持续向后移动，没有为每次插入重新从头搜索，因此同样可以达到线性时间。简化分支不会把它再降低一个复杂度等级。

额外使用固定数量的变量；dummy版再增加一个辅助节点，所以辅助空间都是O(1)。这里复用的是输入节点，合并后原来的next关系会改变；如果另外的接口要求保留两条原链表，就需要重新考虑是否复制节点。

双空时返回None；仅一条为空时返回另一条；相等值要保留不同对象；一条先耗尽时接入另一条未处理段。这些边界都可以从“入口指向谁、前驱能改哪条连接”继续核对。

2.1 保留时前驱跟上，删除时前驱留在原位

python
# 首版：保留时接入，删除时绕过
class Solution:
    # 沿用力扣方法接口，节点类型由题目提供
    def removeElements(self, head: ListNode | None, val: int) -> ListNode | None:
        # 创建辅助头节点，默认next为空；它不属于最终数据
        dummy = ListNode()
        # 从辅助头节点开始维护已保留部分的末端
        pre = dummy
        # 依次处理原链表中的每个节点
        while head!=None:
            # 当前节点的值等于待删除值，需要绕过它
            if head.val==val:
                # 让前驱直接连接当前节点的后继，pre本身不前进
                pre.next = head.next
            # 当前节点不需要删除，将它保留在结果中
            else:

                pre.next = head
                # 当前节点被保留后，它成为后续处理的前驱
                pre = head
            # 工作指针沿原后继前进；删除操作没有改动当前节点自己的next
            head=head.next
        # 跳过辅助头节点，返回真正的结果入口
        return dummy.next

# 补充：先连接dummy，减少重复写入
class Solution:
    # 保留用户的扫描与前驱思路，返回删除后的头节点
    def removeElements(self, head: ListNode | None, val: int) -> ListNode | None:
        # 预先把dummy接到原头，使保留节点时无需重复连接
        dummy = ListNode(0, head)
        # pre始终表示当前待处理节点前面的已保留节点
        pre = dummy
        # 每个原始节点按顺序处理一次
        while head is not None:
            # 当前节点匹配删除值时，将它从结果中绕过
            if head.val == val:
                # 前驱接到后继，pre不动，以便继续检查连续待删节点
                pre.next = head.next
            # 当前节点不需要删除，原连接已经存在
            else:
                # 只移动前驱，不重复写入同一条连接
                pre = head
            # 当前节点自己的next未被改动，可以继续沿它前进
            head = head.next
        # 结果可能为空，统一由dummy.next给出
        return dummy.next

2.3 连续删除的复杂度与边界

head每轮向后走一个节点，每个数据节点恰好接受一次是否等于val的判断，所以长度为L时，时间复杂度是O(L)，辅助空间是O(1)。循环内删除几个连续节点，并不会增加一层扫描。

全删时pre一直停在dummy，最终dummy.next为None；全保留时pre依次跟着head走到尾部；删除尾节点时，最后保留节点的next会被改成None。这几种情况都使用同一条连接操作，dummy的作用在这里就比较直观了。

3.1 计数法：从倒数位置推导前驱的步数

设链表长度为L，把dummy记为位置0，数据节点依次记为1到L。倒数第n个节点位于L−n+1，而删除语句要修改它前一个节点的next，因此要停在位置L−n。

目标位置=L−n+1,前驱位置=L−n\text{目标位置}=L-n+1,\qquad \text{前驱位置}=L-n

例如[1,2,3,4,5]、n=2，目标是位置4，前驱是位置3。从dummy出发，恰好走3步就能到达这个前驱。

python
# 计数法：先求长度，再定位前驱
class Solution:
    # 沿用力扣方法接口，节点类型由题目提供
    def removeNthFromEnd(self, head: ListNode | None, n: int) -> ListNode | None:
        # 创建辅助头节点，默认next为空；它不属于最终数据
        dummy = ListNode()
        # 定位指针从dummy开始，因此前进0步就能定位原头的前驱
        cur = dummy
        # 把辅助头节点接到原链表，使删除原头也能通过前驱完成
        cur.next = head
        # 初始化链表长度计数
        count = 0
        # 依次处理原链表中的每个节点
        while head!=None:
            # 计数用的工作指针前进；原链表入口仍由dummy.next保留
            head=head.next
            # 每经过一个数据节点，长度增加1
            count+=1
        # 目标前驱的位置为L-n，因此从dummy需要前进这么多步
        step = count - n
        # 走到待删除节点的前驱，而不是走到目标本身
        for i in range(step):
            # 定位指针向后移动一个next连接
            cur = cur.next
        # 从前驱绕过目标节点，连接目标的后继
        cur.next = cur.next.next
        # 跳过辅助头节点，返回真正的结果入口
        return dummy.next

这里先让head走完整条链表来计数，head最后会变成None，但dummy.next一直保存着原入口，所以第二阶段仍然能从dummy重新定位，不会丢掉整条链表。

3.2 固定间距：利用尾部终点确定前驱的位置

计数法需要先知道L，才能算出L−n。继续考虑单趟遍历时，可以换一种保存长度信息的方法：让两个指针先相隔一段固定距离，再一起向后移动；前面的指针到达约定终点时，后面的指针就停在所需位置。

这个距离按沿next前进的次数计算，也就是连接条数。例如A3→A4→A5→None需要3次next。它与“两个指针之间夹着几个节点”不是同一个计数口径，后者很容易让步数少算1。

我按照这个方向写了双指针版本，随后遇到的疑问就是：两者都从dummy出发，为什么先让fast走n+1步，而不是n步？要回答这个问题，需要把slow的目标和fast的终点一起标出来。

3.2.1 n+1步配合fast最终停在None

当前写法的循环条件是while fast!=None，所以fast最后会到尾节点之后的结束位置。为了推导，把这个位置记为L+1（None只是结束标记，不是一个额外的数据节点）。slow要停在前驱位置L−n，两者之差就是：

间距=(L+1)−(L−n)=n+1\text{间距}=(L+1)-(L-n)=n+1

因此，两者从同一个dummy出发时，fast先走n+1步，再每轮各走一步，才能在fast到None时让slow正好落到目标前驱。

python
# n+1步：fast最终停在None
class Solution:
    # 沿用力扣方法接口，节点类型由题目提供

        dummy = ListNode(0, head)

        cur = dummy

        fast, slow =  dummy, dummy
        # fast先走n+1条next连接，配合最终停在None的位置
        for i in range(n+1):
            # 快指针向后移动一步，不修改链表连接
            fast=fast.next
        # 继续到fast越过尾节点，停在None这一结束标记

            # 慢指针同步前进，恢复两指针的固定间距
            slow=slow.next

        slow.next=slow.next.next
        # 跳过辅助头节点，返回真正的结果入口
        return dummy.next

3.2.2 n步配合fast最终停在尾节点

如果希望只先走n步，也能写出正确算法，但fast的终点要相应改为最后一个真实节点。这个位置是L，与目标前驱L−n的差为：

间距=L−(L−n)=n\text{间距}=L-(L-n)=n

所以预走改成range(n)时，同步循环也要改成while fast.next is not None。主例中fast预走到A2；同步后依次到A3、A4、A5，slow则依次到A1、A2、A3，仍然落在节点4的前驱上。

3.4 计数与双指针的时间、空间及适用范围

计数阶段走L步，定位阶段走L−n步，两段相加是2L−n，因此计数法仍是O(L)时间，并不是O(L²)。双指针的fast和slow也只向后走，累计移动次数同样是线性的。三种正确写法都只用固定变量和一个dummy，辅助空间都是O(1)。

在没有额外长度信息的单链表中，最坏需要看到尾部才能确定倒数位置，因此这些方法都已达到线性的渐近时间界。进一步选择时，重点可以放在状态是否容易解释、边界是否清楚，以及接口是否已经提供长度信息。

四、知识点归纳：用辅助起点统一链表边界

这三题里，dummy的具体用法略有区别：21从空结果开始追加，203为连续删除保留前驱，19提供删除头节点时的位置0。它们共同解决的是第一次连接或删除原头时，普通操作缺少一个可供修改的前驱。

这种思考可以和前缀和中的空前缀P[0]=0联系起来：前缀和补一个初始累计状态，使从头开始的区间也能直接相减；链表补一个辅助节点，使头部也能使用修改前驱next的操作。两者的具体算法不同，但都先看清普通规则需要什么，再补足边界缺少的条件。

以后遇到反复判断“是不是第一个节点”的代码，可以先检查需要稳定入口，还是需要目标前驱，以及补一个固定节点能否统一操作。dummy提供了结构位置，具体指针仍要按各自职责移动；保存未处理入口、区分变量赋值与next修改，也仍然是连接正确的前提。
