检索之前，先保证读进来的内容正确

RAG会把文档切成片段用于检索，但这些片段首先要从原文件中正确提取出来。PDF页面看起来像两栏文章，内部存储顺序却可能先写标题、再写右栏、最后补左栏。直接拼接文本，会把原本连续的句子拆开。

解析结果应同时保留内容、结构和出处。至少包括文档ID、页码、标题层级、段落或表格位置。对于扫描页，需要OCR（光学字符识别）把图像转成文字；对于已有文本层的页面，则应避免重复识别后产生两份相同内容。PyMuPDF的文本提取说明也区分了原始顺序、按位置排序以及按块或词提取。PyMuPDF文本提取

表格还需要保留行列关系。例如“2025年，收入100，利润20”如果被拆成三个孤立数字，模型很难知道各自代表什么。可以把表头与当前行一起编码，同时保留表格原始位置供回看。合并单元格、跨页表格和脚注单位需要单独检查。

切片标识为什么不能只用序号

假设文档最初有三个片段A、B、C，对应编号0、1、2。在开头插入一段内容后，编号全部移动。如果只按编号比较，会误以为后面所有内容都被替换。

可以把身份拆成几个字段：

json
{
  "document_id": "manual-7",
  "revision": 4,
  "chunk_key": "chapter-2/paragraph-3",
  "content_hash": "hash-of-normalized-content",
  "parser_version": "p2",
  "embedding_version": "e1"
}

逻辑位置帮助追踪片段，内容哈希帮助判断文本有没有变化。哈希相同也只说明输入内容相同；如果Embedding模型、切片方式或文本规范化规则变了，原向量未必可以继续复用。

对没有稳定段落ID的文件，可以结合标题路径、邻近文本和内容摘要匹配。若切片使用滑动窗口，一处修改会影响相邻重叠片段，不能只更新包含修改字符的一个块。

一次局部更新怎样计算增删改

教学例子中，旧文档片段为A、B、C，新文档为A、B'、D。对比后：

  • A内容及编码配置未变，可以复用向量。
  • B变成B'，需要重新解析相关结构并生成向量。
  • C被删除，需要从检索可见集合中移除。
  • D为新增片段，需要生成向量和索引记录。

增量更新不仅包括添加新向量，也包括删除旧片段和更新元数据。如果旧C仍可被检索，回答可能引用已经废弃的说明；如果只更新文本却没更新向量，检索排序对应的语义仍然来自旧内容。

权限变化即使不改变正文，也需要及时影响查询。撤销某个用户的权限不应等待下一次Embedding任务，更不能让旧缓存继续返回原片段。

多个索引怎样切换到同一版本

实际系统可能同时维护全文索引、向量索引和文档元数据。只完成其中一个就对外开放，会出现全文检索命中新版、向量检索仍返回旧版的情况。

可以先构建新的文档revision，检查所有必要索引都准备好，再更新该文档的可见版本。查询携带可见版本过滤，旧版本暂时保留以便恢复，稍后清理。

整库重建时，也可以使用新索引加别名切换。Elasticsearch支持通过一次别名操作切换索引引用；这个原子性只覆盖其支持的别名操作，不会自动把另一个向量数据库或外部元数据表也纳入事务。Elasticsearch别名

跨存储的一致版本需要应用自己的发布协议。任务记录应保存每个阶段的完成状态，失败后重试相同revision，避免新建一批无法追踪的重复片段。

Embedding计算怎样节省，限制在哪里

可复用内容哈希与编码配置相同的向量；批量请求可以降低调度开销，但批次要受最大Token数、并发、内存和外部限额约束。对于大量文档，应流式读取、小批量写入，并保存进度。

如果新模型的向量维度或语义空间变化，不能把新旧向量直接混在同一个相似度空间里比较。应分别建索引或完成受控迁移，再用同一评测集比较检索质量。

本篇不生成大规模Embedding。一个三段文本样本就能验证增删改规划；再构造解析规则升级、权限撤销和索引写入中断，检查可见版本是否保持完整。真正的向量质量需要模型与领域样本验证，哈希测试无法替代。

面试追问：局部修改如何避免全量重建

文档发生局部更新时，如何做增量索引而不是全量重建？

回答：给文档与片段建立稳定身份，记录内容哈希、版本和处理配置。先比较新旧结构，找出新增、修改、删除及受重叠窗口影响的片段；只对需要变化的输入重新编码，同时传播删除和元数据变化。新版本的各类索引准备好后再切换可见版本，保留任务进度、幂等写入与失败恢复。模型或解析规则整体改变时，应重新评估复用范围。

自拟追问：正文没变，只撤销访问权限，需要重算向量吗？通常不需要，但权限过滤和缓存必须更新。计算复用与访问控制是不同的更新路径。

原问及来源见逐题映射。
