一、题目一：缺失的第一个正数

41. 缺失的第一个正数力扣原题 ↗

题目要求

输入一个没有排好序的整数数组nums，找出没有出现在数组中的最小正整数，并返回这个数。

要求算法的时间复杂度为O(n)，辅助空间复杂度为O(1)，其中n是数组长度。

示例1

输入：nums = [1,2,0]

输出：3

1和2都出现了，接下来的正整数3没有出现。0不属于要查找的正整数。

示例2

输入：nums = [3,4,-1,1]

输出：2

1已经出现，2没有出现；虽然数组中还有3和4，最小缺失值仍是2。

示例3

输入：nums = [7,8,9,11,12]

输出：1

最小的正整数1就没有出现，因此返回1。

约束条件

  • 1 ≤ nums.length ≤ 10⁵
  • −2³¹ ≤ nums[i] ≤ 2³¹−1

这道题需要判断哪些正整数出现过，而且只要其中最小的缺失值。单看返回结果并不复杂，真正限制解法的是O(n)时间与O(1)辅助空间必须同时满足。

我开始做的时候，一直在考虑怎样沿着数组找到一段连续的正整数，再把紧接着的数作为答案。后来想到用set保存出现过的数，查询会方便很多，但又遇到了空间要求：set中的元素个数会随着输入增长，不能把它算作O(1)。

下面先保留这段尝试和修正，再说明怎样复用原数组。后面的448“找到所有数组中消失的数字”和645“错误的集合”，也会沿着同一个“数值对应位置”的关系继续展开。三题需要保存的状态不完全相同，正好可以把交换、负数标记和加n计数放在一起比较。

1.1 从反复扫描候选到set：找到瓶颈所在

1.1.1 最早的计数尝试没有完整确认候选是否存在

最早的想法仍然是从1开始，找到已经出现的一段连续正整数，再检查紧接着的那个数。例如1、2都出现，下一候选就是3；但如果连1都没有出现，就应该直接返回1，后面有多大的数都不影响这个答案。

首版代码没有直接逐个确认候选，而是把数组中的数都减1，再通过0和1更新两个变量。先把它们在这份代码中的作用对应清楚：

变量或操作首版代码实际怎样使用
min_pos初始为1，作为准备返回的候选；遇到减1后为0的元素，就增加当前count
min_init每轮固定为1，是从每个数组元素中减去的值；并没有随着min_pos变化
count初始为1；遇到减1后为1的元素，就再加1，随后参与候选推进和返回分支判断
nums[i]减1原来的1会变成0，原来的2会变成1，因此两个判断分别对应“看见了1”和“看见了2”

例如输入[1,2]，这份代码碰巧能得到正确结果。下面按它实际执行的顺序看一次：

执行位置当前操作min_poscount
初始化候选从1开始，count也设为111
下标0原值1减1变成0，执行min_pos+=count21
下标1原值2减1变成1，执行count+=122
扫描结束count不等于1，进入else，返回min_pos+1返回32

但count并没有保存“从1开始的连续整数都已出现”这个事实。它增加的直接原因只是看到了原值2，而1可能根本没出现。因此，不能仅凭count的变化就把最小候选向后推。

把输入缩小为[2]，就能把这个缺口单独看出来：初始min_pos=1、count=1；唯一的2减1后成为1，代码只执行count+=1，所以min_pos仍为1、count变为2。扫描结束进入else，返回min_pos+1=2。原数组没有1，正确答案却应该是1；发现2存在，并不能说明1已经存在。

元素顺序也会影响这种推进方式：对[2,1]，先看到2会让count变为2，随后看到1时，min_pos就一次增加2而变成3，最后返回4。它与[1,2]包含相同的数，答案都应该是3。这进一步说明，候选能不能跳过，需要由存在性判断来决定，不能由遇见这些数的先后顺序决定。

另外，末尾两个分支都有return，外层while实际不会进入第二轮。因此，这一版也没有在后续循环里补查被跳过的候选。

错误版本：减1与计数的首次尝试
python
# 早期错误：减1与计数
class Solution:
    # 返回最小缺失正整数
    def firstMissingPositive(self, nums: list[int]) -> int:
        # 缓存数组长度，合法下标范围为[0, n)
        n = len(nums)
        # 从最小的正整数1开始检查
        min_pos = 1
        # 进入候选检查循环；具体能否终止取决于本版的返回和推进逻辑
        while True:
            # 本版每轮固定减去1，并不是随候选变化的偏移量
            min_init = 1
            # 初始化本版的计数，后续是否推进候选要结合存在性判断
            count = 1
            # 按下标顺序访问[0, n)
            for i in range(n):
                # 直接修改当前数；本版把原值1、2分别变成0、1
                nums[i]-=min_init
                # 减1后为0，说明原来的当前值是1
                if nums[i]==0:
                    # 按当前count推进候选；此处保留原版有问题的推进方式
                    min_pos+=count
                # 减1后为1，说明原来的当前值是2
                elif nums[i]==1:
                    # 增加count，但发现2并不能证明1出现过
                    count+=1
            # 按本版计数决定返回；min_init实际上始终为1
            if min_init==1 and count==1:
                # 返回本轮候选；错误版本仍保留原来的返回逻辑
                return min_pos
            # 本版另一路同样直接返回，所以外层while不会进入下一轮
            else:
                # 返回更大的候选；首版可能因此越过真正缺失的1
                return min_pos + 1

后面的修改便把这两件事分开处理：flag只回答“当前候选min_pos有没有出现”；min_future则尝试跟着已看到的连续整数向后移动。完整扫描后，如果当前候选没有出现，就可以返回它；只有确认它出现过，才更新下一轮候选。这样候选推进就有了明确依据，不再借助前一版含义混杂的count。

不过，这里又有一个推进问题。输入[1]时，本轮找到了1，flag变为0，但min_future仍是1。如果末尾写min_pos=min_future，下一轮又检查1，数组和候选都没有变化，便会一直重复。

1.1.2 增加反向扫描仍没有消除重复工作

min_future能前进多少，取决于连续整数在数组中的排列。例如扫描顺序对当前候选不利时，前面已经经过的元素不会因为候选刚刚变化就自动重读，只能留到下一轮。

我后来又尝试正向扫完再反向扫，希望一轮能确认更多连续值。最开始的反向范围写成了range(n-1,0,1)，但起点在右、步长却是正数，循环为空。输入[100000,3,4000,2,15,1,99999]时，正向结束后候选变成3，反向循环没有检查它，flag便一直为1，最后直接返回3；实际3存在，应该返回4。

1.1.3 set能保存出现记录，但需要额外空间

到了这里，我想到的办法是先把所有数放进set，再从1开始检查哪个数不在集合中。这个方向对应的就是保存一次出现记录，之后复用查询结果。在通常的哈希查询分析中，建集合和逐个查询合计为期望O(n)时间，但集合最多保存n个不同数，辅助空间也是O(n)。

之前的两数之和用字典保存已经出现的数及其下标，也是把重复搜索换成查询。还不熟悉这个变化时，可以先看哈希表与Python字典查找。不过41额外要求O(1)辅助空间，所以还要继续考虑这些记录存在哪里。

1.2 原地哈希的推导：把值v交给原数组下标v−1

1.2.1 答案范围让n个已有位置足够使用

想到set以后，查询这个方向其实已经清楚了：先记录出现过的数，再查询哪个正整数没有出现。卡住的是记录要额外占用O(n)空间。后来得到“可以复用输入数组”的提示，我才开始把这两件事分开看：需要保存出现情况，并不意味着一定要另外创建一个集合。

这里的O(1)限制针对辅助空间，输入数组已有的n个位置仍然可以使用。题目只要求返回最小缺失正整数，没有要求保留输入排列，因此可以修改这些位置，让它们承担记录任务。不过，nums里可能有负数、0和很大的正整数，n个位置究竟够记录哪些数，还需要先推导答案范围。

长度为n时，最小缺失正整数一定在[1,n+1]内。原因可以分两种情况看：

  • 如果1到n全部出现，n个位置已经被这n个不同的数占满，最小缺失值就是n+1。
  • 如果其中有数没出现，最小缺失值就在1到n之间，后面更大的数不会影响答案。

所以，真正需要逐个记录的是1到n，而不是输入中所有可能出现的整数。如果额外创建一个长度为n的记录数组seen，最直观的对应关系就是：seen[0]记录1有没有出现，seen[1]记录2有没有出现，依此类推。这样下标可以直接表示所查询的数，但新建seen仍要O(n)辅助空间。

原数组恰好也有n个位置，于是可以保留这套对应关系，把记录交给nums本身：值域是[1,n]，数组下标是[0,n)，因此值v对应的下标是v−1。n+1只可能作为最后的答案，不需要为它访问nums[n]。

接下来还差一步：位置已经对应好了，但每个位置里保存什么，才能表示“这个数出现过”？交换方案采用的约定是让出现过的v直接放到下标v−1。以值3为例，先把它送到下标2，整理结束后检查nums[2]==3，就能知道3出现过。这个约定需要经过整理才能成立，原始输入并不天然满足它。

这里所说的原地哈希，是利用受限整数值域，把值直接映射到输入数组已有的位置，再用这些位置保存出现情况等信息的做法。v→v−1属于直接寻址，和通用哈希表的实现方式不同：这里不需要计算复杂哈希函数、扩容或维护冲突链。多个相同的v对应同一个位置，是在处理同一个值的重复出现。

从set走到这里，保留下来的是“记录出现情况、之后直接查询”的思路；变化的是记录存在哪里，以及怎样通过一个位置读出它所代表的状态。不过，nums里的原值还没有全部处理完，搬动时必须保住它们，这就引出了接下来的交换与temp。

1.2.2 输入允许修改，修改后仍要保留未处理的信息

数组的位置原本保存输入值，现在还要用它记录出现情况，就必须说明原值会去哪。交换方案的约定是：如果v出现过，就尝试让nums[v−1]保存v。整理结束后，哪个位置没有放着它对应的数，哪个数就没有出现。

例如当前位置是3，它应该去下标2。但下标2原来可能是另一个还需要处理的数，直接覆盖会丢掉这部分信息。因此要先把目标旧值保存到temp，再把3写过去，最后把temp写回当前位置。

这一步可以结合Python列表的下标访问与修改理解：nums[pos]是当前位置的值；nums[nums[pos]-1]则是先读这个值，再用它算出另一个位置。两个访问层次要分别对应清楚。

1.3 交换归位的三次修正：范围、旧值和重复值

1.3.1 使用v−1映射，并在索引前检查范围

最早尝试复用原数组时，我直接把数值当作下标使用，也没有检查数值是否超过数组长度。输入[2]时，只有下标0可以访问，直接访问下标2就会越界。

除了上界，41还必须处理0和负数。假设当前值为0，value−1就是−1，而Python会把nums[-1]解释为最后一个元素。没有报错也可能访问了错误的位置，因此必须先确认1≤value≤n，再访问nums[value−1]。

1.3.2 目标已经有相同值时，继续交换不会推进

1.3.5 成功交换的总次数给出O(n)复杂度

这版有while，内部也可能在同一个pos反复交换，但不能直接把它当成O(n²)。需要数的是整个过程中最多会发生多少次成功交换。

每次真正交换，都会把当前值v送到目标v−1，而目标之前不等于v（等于时已经跳过）。所以，每次成功交换至少让一个此前未归位的位置完成归位。****已经归位的位置也不会再被破坏：其他值有自己的目标，同一个v再次出现时则会触发等值跳过。

数组只有n个位置，因此成功交换至多n次；pos只从0向右推进到n，推进次数也是n次。每轮要么完成一次有效交换，要么推进pos，最后再加一轮缺失检查，合计为O(n)时间。这也可以理解为把多轮while操作的成本摊到每个被归位的位置上。

辅助变量只有n、pos、temp和i，数量不随n增长，所以是O(1)辅助空间。原数组本身仍占O(n)空间，只是它属于输入；“原地”也意味着这个实现会改变输入排列，如果调用方需要保留原数组，就要另外考虑复制或其他方案。

1.3.6 缓存value和target减少重复读取，复杂度保持不变

主版通过以后，我还关心过它为什么运行得不够快。基于这份实现，后续的优化把本轮当前值保存为value，把目标下标保存为target，避免在同一轮重复写nums[pos]和nums[pos]-1。

例如成功交换这条路径，V7会多次读取nums[pos]，Cached版在循环开头读一次，后面的范围判断、判重和写入都复用value。这样也更方便给变量起明确的名字。

# 交换归位：缓存变量
class Solution:
    # 返回最小缺失正整数
    def firstMissingPositive(self, nums: list[int]) -> int:
        # 缓存数组长度
        n = len(nums)
        # 从下标0开始处理，遍历范围是[0, n)
        pos = 0
        # 当前下标仍在数组范围内时继续处理
        while pos < n:
            # 本轮只读取一次当前值，后续复用这个局部变量
            value = nums[pos]
            # 只处理位置不正确、且位于[1, n]的值
            if value != pos + 1 and value > 0 and value <= n:
                # 只计算一次目标下标，它一定在[0, n)内
                target = value - 1
                # 保存目标位置原来的值，避免交换时丢失
                temp = nums[target]
                # 目标已经有相同的数时，交换不会改变数组
                if temp == value:
                    # 跳过这个重复值，继续处理下一个位置
                    pos += 1
                    # 结束本轮，避免执行无效交换
                    continue
                # 将当前值放到它对应的正确位置
                nums[target] = value
                # 将目标位置原来的值放回当前位置；pos不变，下轮重新检查它
                nums[pos] = temp
            # 当前值已经归位，或者不在需要归位的范围内
            else:
                # 当前值无需处理，前进到下一个位置
                pos += 1
        # 按下标顺序检查[0, n)中的所有位置
        for i in range(n):
            # 下标i没有放着i+1，说明这个正整数缺失
            if nums[i] != i + 1:
                # 返回最先发现的缺失正整数
                return i + 1
        # 若1到n都存在，则缺失的第一个正整数为n+1
        return n + 1

                pos+=1
            # 当前值尚未归位且目标没有相同值，执行交换
            else:
                # 保存目标位置旧值，随后用来回填当前位置
                temp = nums[num-1]
                # 把当前数放到对应的目标位置
                nums[num-1] = num
                # 把temp中保存的数写回当前位置，下一轮继续检查这里
                nums[pos] = temp
        # 准备收集全部缺失值
        answer = []
        # 按[0, n)顺序检查所有位置
        for i in range(len(nums)):
            # 当前位置没有放着期望值，说明对应数缺失
            if i+1 != nums[i]:
                # 收集当前下标对应的正整数
                answer.append(i+1)
        # 返回已整理的结果列表
        return answer

2.1 保持负号：只记录出现过，不必把数搬到对应位置

448最后只关心某个值有没有出现，因此还可以让目标位置的符号保存这个状态。原值都为正数，最开始所有位置都是“未标记”；读到值v时，让下标v−1上的数保持为负数，表示v出现过。

这里必须区分两个对象：读取位置pos携带的原值，与被标记位置target代表的值。位置pos可能已经被前面的元素改成负数，所以读取时先用abs(nums[pos])恢复原值，再计算target。

例如主例处理到pos=3时，该位置已经被原来的4标记成−7。它的负号记录“值4出现过”，绝对值7仍保存“这个输入位置原来是7”。当前要处理的输入仍然是7，所以接着标记下标6。

python
# 保持负号
class Solution:
    # 返回全部缺失值
    def findDisappearedNumbers(self, nums: list[int]) -> list[int]:
        # 448保证数组非空，且原值都属于[1, n]
        n = len(nums)
        # 依次读取每个位置携带的原值
        for pos in range(n):
            # 标记只改变符号，绝对值仍是原值
            value = abs(nums[pos])
            # 值value使用下标value-1记录存在性
            target = value - 1
            # 无论第几次见到，都让标记保持负数
            nums[target] = -abs(nums[target])
        # 结果列表可能有多个值，不计入题目进阶要求的辅助空间
        answer = []
        # 按[0, n)检查所有标记位置
        for i in range(n):
            # 正数表示对应的值从未出现
            if nums[i] > 0:
                # 将下标转回正整数后加入结果
                answer.append(i + 1)
        # 返回全部缺失值
        return answer

标记使用-abs(nums[target])：目标无论原来为正还是为负，写入后都保持负数。重复遇到2或3时，不会把标记翻回正数。

处理完后，数组为[-4,-3,-2,-7,8,2,-3,-1]。下标4和5仍为正数，说明值5和6没有被任何输入元素标记，答案仍是[5,6]。两次线性扫描分别负责标记和收集，合计O(n)时间、O(1)辅助空间；如果缺失值有k个，返回列表本身占O(k)空间，按题目要求另计。

2.2 加n计数：把原值放在余数里，把次数放在商里

负号足以回答“有没有出现”，但如果希望从每个槽位直接读出出现次数，就需要更多状态。一个办法是：每遇到值v，就给nums[v-1]加n。

这样修改后，当前位置读到的数可能已经超过n，不能再把它直接当作原值。设位置i原来保存aᵢ，对应的计数槽位被命中了cᵢ次，那么当前存储值满足：

xi=ai+cinx_i=a_i+c_i n

这里aᵢ是位置i原来保存的输入值，cᵢ记录的却是“值i+1已经出现的次数”。它们不是同一个数的两个称呼。例如位置4原来保存8，但这个位置负责给值5计数。

因为原值的范围是1到n，为了得到从0开始的余数范围，先整体减1：

xi−1=(ai−1)+cin,0≤ai−1<nx_i-1=(a_i-1)+c_i n,\qquad 0\le a_i-1<n

因此，取模会去掉完整的n倍数，整除会去掉不足一个n的原值部分：

ai=(xi−1) mod n+1,ci=⌊xi−1n⌋a_i=(x_i-1)\bmod n+1,\qquad c_i=\left\lfloor\frac{x_i-1}{n}\right\rfloor

对应Python写法就是原值(x-1)%n+1，次数(x-1)//n。目标下标再由原值减1得到，也等于(x-1)%n。

减1不能省略。主例中n=8，下标4原来保存8，而值5根本没出现，所以这个槽位最终仍是8。直接算8//8会误判为出现1次；正确的(8-1)//8=0才表示没有出现。恢复原值也一样，8%8=0超出了原值1到8的含义，(8-1)%8+1=8才能恢复8。

python
# 加n计数
class Solution:
    # 返回全部缺失值
    def findDisappearedNumbers(self, nums: list[int]) -> list[int]:
        # n既是数组长度，也是计数编码的步长
        n = len(nums)
        # 扫描每个原始元素，它当前可能已叠加多次n
        for pos in range(n):

            stored = nums[pos]
            # 恢复[1, n]内的原值；减1处理原值等于n的边界

            if count == 0:

                answer.append(i + 1)
        # 返回结果，输入数组此时保留了编码后的数值
        return answer

645. 错误的集合力扣原题 ↗

题目要求

原本有一个包含1到n、每个数恰好一次的集合。由于其中一个数被另一个数替换，现在有一个数出现了两次，另一个数没有出现。数组nums记录的是替换后的数据。

找出重复的数和缺失的数，按[重复值,缺失值]的顺序返回。

示例1

输入：nums = [1,2,2,4]

输出：[2,3]

2出现了两次，3没有出现。返回时重复值在前，缺失值在后。

示例2

输入：nums = [1,1]

输出：[1,2]

原来应该有1和2，替换后两个数都是1。

约束条件

  • 2 ≤ nums.length ≤ 10⁴
  • 1 ≤ nums[i] ≤ 10⁴
  • 结合题意，合法输入来自1到n的一次替换：一个值出现2次，一个值出现0次，其余各出现1次。

本题没有强制要求O(1)辅助空间；下面继续以复用输入数组作为解法目标。

645除了找缺失值，还需要找重复值，而且重复值恰好出现两次。我最初使用的办法是：每读到一个原值，就把它对应位置的符号翻转一次；最后收集仍为正数的位置。

这和上面“保持负号”的含义不同。最开始为正数，第一次翻转变负、第二次又变正，因此反复取反记录的是出现次数的奇偶性。

出现次数最终符号在645中的含义
0正缺失值
1负正常出现一次的值
2正重复值

645保证只有一个0次、一个2次，所以正数位置确实能给出两个候选。这一段取反逻辑可以成立，接下来要判断两个候选谁重复、谁缺失，并按题目顺序返回。

3.2 保持负号：第二次遇到就确定重复值

后来我拿另一份AI给出的实现作了对照：目标第一次被访问时变成负数；再次访问时，如果目标已经为负，就直接记录重复值，并继续保持负号。这样最终的正数位置只表示缺失，不再同时承担“重复”这一含义。

python
# 保持负号：再次遇到即判重
class Solution:
    # 返回[重复值, 缺失值]
    def findErrorNums(self, nums: list[int]) -> list[int]:
        # 缓存数组长度，合法下标范围为[0, n)
        n = len(nums)
        # 初始化重复值；645条件保证之后能找到它
        dup = -1

        # 读取当前数组元素，它可能已被先前操作改变符号
        for x in nums:
            # 用绝对值恢复原数，再转换为[0, n)内的目标下标
            idx = abs(x) - 1
            # 目标已经为负，说明这个数此前出现过
            if nums[idx] < 0:
                # 记录本次再次出现的原数，目标位置继续保持负数
                dup = abs(x)
            # 首次遇到这个值，为其对应位置建立出现标记
            else:
                # 目标尚未标记时变为负数，记录首次出现
                nums[idx] = -nums[idx]

        # 初始化缺失值，随后查找唯一未标记的位置
        miss = -1
        # 按下标顺序访问[0, n)
        for i in range(n):
            # 保持负号的方案中，正数位置只表示没有出现
            if nums[i] > 0:
                # 将未标记下标转回对应的正整数
                miss = i + 1
                # 645只缺失一个数，找到后即可停止扫描
                break

        # 按题目要求返回[重复值, 缺失值]
        return [dup, miss]

仍以[2,1,1,3]为例：原值2先标记下标1，原值1再标记下标0；第三个输入仍是1，此时下标0已经为负，便记录重复值1；最后原值3标记下标2。终态为[-2,-1,-1,3]，只有下标3未标记，所以缺失值是4。

3.3 奇偶标记的适用条件不能直接推广到448

645只可能出现0、1、2次，两个正数槽位的含义可以结合题目条件确定。448却允许某个数重复很多次，例如[4,4,4,4]中4出现4次。如果每次都取反，4对应的位置最后也会变回正数，和出现0次的标记一样。

因此，需要判断是否出现时，保持负号更通用；反复取反只保存奇偶性，必须有足够的题目条件帮助解释这个状态。[4,4,4,4]是448的合法输入，不满足645“恰好一个值出现两次”的条件，不能拿它来证明645修正版错误。

四、知识点归纳：三种原地记录方法的复杂度与迁移范围

方法槽位i在整理完成后表示什么尚未处理的原信息如何保留主要限制
交换归位nums[i]==i+1表示值i+1出现过交换保留全部输入值；两次写入之间用temp保留旧值改变原顺序；需要判重并继续处理换回值
保持负号nums[i]<0表示值i+1出现过abs恢复当前位置原值要有可用的正数初始状态；单个符号不直接给出次数
加n计数(nums[i]−1)//n表示值i+1的次数(nums[i]−1)%n+1恢复当前位置原值原值需在[1,n]内；编码值变大，解码有取模与整除

在通常把整数读写与算术视为常数成本的算法模型下，三种方法都能做到O(n)时间、O(1)辅助空间。交换的依据是有效交换至多n次；标记与计数的依据是固定轮数的线性扫描。448输出k个缺失值，结果列表还需要O(k)空间；41和645的结果大小固定。

“原地”表示额外空间不随n增长，输入数组仍然在保存信息。选择哪一种方法，应当先看要查询的是归位情况、存在性还是次数，再看代码是否易于维护，而不是只比较有没有while或代码行数。这里没有三种方法在同一环境中的统一耗时测试，所以不按实际速度给它们排先后。

4.1 负号法迁移到41之前，要单独处理无效原值

41原本就可能含负数和0。如果直接把“负数”当作出现标记，原来的负数会混入记录；0取负也还是0，无法表示正负两种状态。

补充方案是先用一整轮扫描，把≤0或>n的原值都替换为正哨兵n+1，再开始建立负号标记。读取到哨兵时跳过，其他值仍按v−1映射。预处理与标记必须分成两轮，不能把前面刚产生的负号又当作无效输入清掉。

补充实现：41预处理后使用负号标记
python
# 补充：清理无效值后保持负号
class Solution:
    # 返回最小缺失正整数
    def firstMissingPositive(self, nums: list[int]) -> int:
        # 缓存长度；下标范围为[0, n)
        n = len(nums)
        # 先单独完成整轮清理，避免把标记产生的负数误当作原始无效值
        for i in range(n):
            # 只需为[1, n]内的正整数建立出现标记
            if nums[i] <= 0 or nums[i] > n:
                # 用正哨兵替换无效值，使所有位置都能用负号表示标记
                nums[i] = n + 1
        # 再读取清理后的原值并建立标记
        for i in range(n):
            # 前面的标记可能改变符号，用绝对值恢复当前所代表的值
            value = abs(nums[i])
            # 跳过哨兵n+1，它不对应数组中的合法下标
            if value <= n:
                # 把值域[1, n]映射为下标范围[0, n)
                target = value - 1
                # 始终保持负数，重复出现也不翻回正数
                nums[target] = -abs(nums[target])
        # 按从小到大的顺序检查每个值的标记
        for i in range(n):
            # 仍为正数，说明没有任何元素为值i+1建立标记
            if nums[i] > 0:
                # 第一个未标记的位置给出最小缺失正整数
                return i + 1
        # 1到n全部出现时，答案为n+1
        return n + 1

对于448和645，负号法使用后逐项取abs就能恢复原数组；41这份补充实现却已经把无效原值替换成哨兵，无法再通过abs完整恢复最初输入。交换方案保留所有值，但通常也不能恢复原顺序。这些区别在数组还要交给后续代码使用时需要考虑。

4.2 加n的边界与固定宽度整数

加n方案的公式依赖1≤aᵢ≤n，不能把41的任意负数、0或巨大整数直接代入，就当作完成了同一种编码。这里用448、645说明计数机制，41仍以交换版为主。

如果同一个值出现n次，某个槽位最多可能达到n+n×n=n(n+1)。448允许n达到100000，这个值会超过32位有符号整数的范围。Python整数能够表示这种结果；换到固定宽度整数的语言时，需要选择容量足够的类型。

进一步按位复杂度分析时，大整数运算也不是对任意位数都严格O(1)。本篇的O(n)比较采用常见算法题的整数操作模型，重点是遍历与交换次数，不把它当作所有语言和任意规模下的精确耗时结论。

4.3 645继续使用交换或加n的实现

交换整理结束后，645只会留下一个不匹配位置：该位置应该放的i+1是缺失值，实际留下的nums[i]就是重复值。加n则可以直接找次数为2和0的槽位。这两种实现作为补充，方便和前面的映射及计数公式对照。

补充实现：645交换归位后读取重复与缺失
python
# 补充：交换归位
class Solution:
    # 返回[重复值, 缺失值]
    def findErrorNums(self, nums: list[int]) -> list[int]:
        # 题意保证原值属于[1, n]，恰有一个重复值和一个缺失值
        n = len(nums)
        # 从下标0开始整理
        pos = 0
        # 交换后继续处理当前位置新换回来的数
        while pos < n:
            # 缓存当前待归位的数
            value = nums[pos]
            # 计算它应该占据的位置
            target = value - 1
            # 先保存目标位置旧值，既用于判重也用于交换
            temp = nums[target]
            # 已归位或目标已有同值时，不再进行等值交换
            if temp == value:
                # 当前值无需再处理，前进到下一个下标
                pos += 1
            # 当前值有一个尚未放对值的目标位置
            else:
                # 先将当前值放到它的位置
                nums[target] = value
                # 再把目标旧值放回当前位置，下一轮继续处理它
                nums[pos] = temp
        # 整理结束后查找唯一不匹配的位置
        for i in range(n):
            # 这里缺少期望值i+1，并留下了多出来的重复值
            if nums[i] != i + 1:
                # 先重复、后缺失，顺序由题目规定
                return [nums[i], i + 1]
        # 题目合法输入不会到达这里，仅保留完整的返回路径
        return []

# 补充：加n计数
class Solution:
    # 返回[重复值, 缺失值]
    def findErrorNums(self, nums: list[int]) -> list[int]:
        # 使用长度n作为计数编码的步长
        n = len(nums)
        # 遍历每个输入元素携带的原值
        for pos in range(n):
            # 当前值可能已经带有计数增量
            stored = nums[pos]
            # 去掉计数增量并恢复[1, n]内的原值
            value = (stored - 1) % n + 1
            # 找到该值的计数位置
            target = value - 1
            # 为这个值增加一次出现记录
            nums[target] += n
        # 初始化重复值，合法输入保证能找到
        duplicate = -1
        # 初始化缺失值，合法输入保证能找到
        missing = -1
        # 每个位置i的商部分记录值i+1的次数
        for i in range(n):
            # 准确读出次数，不能直接使用nums[i]//n
            count = (nums[i] - 1) // n
            # 645保证重复值恰好出现两次
            if count == 2:
                # 记录对应的重复值
                duplicate = i + 1
            # 没有计数增量的位置对应缺失值
            elif count == 0:
                # 记录对应的缺失值
                missing = i + 1
        # 按题目要求返回
        return [duplicate, missing]
