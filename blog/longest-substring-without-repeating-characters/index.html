一、题目：无重复字符的最长子串

3. 无重复字符的最长子串力扣题面 ↗
给定一个字符串 s ，请你找出其中不含有重复字符的 最长子串 的长度。
示例1输入: s = "abcabcbb"
输出: 3
示例2输入: s = "bbbbb"
输出: 1
示例3输入: s = "pwwkew"
输出: 3

提示：0 ≤ s.length ≤ 10⁵；s由英文字母、数字、符号和空格组成。

这道题首先要注意，子串必须连续，返回的是长度。例如"pwwkew"中的"wke"连续，长度为3；"pwke"虽然没有重复字符，但中间跳过了字符，不能作为本题的子串。

我最初想到的办法，是把所有子串按起点和终点放进一个下三角矩阵，再考虑能不能利用它们之间的关系，跳过一部分候选。最后写出的代码已经有左右边界，但窗口什么时候可以统计、旧字符是否还在窗口内，这两件事没有处理清楚。下面就沿着这次修改的顺序展开。

二、最初的思路：把所有连续子串放进三角矩阵

用l表示起点、r表示终点，矩阵的一个格子可以记为：

M[r][l]=s[l:r+1],0≤l≤r<nM[r][l]=s[l:r+1],\qquad 0\le l\le r<n

这里的r包含在子串中，所以Python切片的终点要写成r + 1。如果切片的起止范围还不熟悉，可以回看之前的切片笔记。

固定终点0只有1个候选，固定终点1有2个候选，依次累加，非空子串的数量就是：

1+2+⋯+n=n(n+1)21+2+\cdots+n=\frac{n(n+1)}2

这里统计的是不同位置上的子串。两个位置的内容同为"a"，也属于不同候选；这张矩阵只用来分析搜索范围，不必在程序中真的创建。

以"abca"为例，下面把起点放在列上、终点放在行上，行号从上往下增大。✓表示不含重复字符，×表示已经重复。

2.1 交互演示：子串矩阵与滑动窗口

展开逐步演示与算例切换

我当时想利用同一行、同一列的变化来减少搜索。这一方向可以保留，但要先说明是哪一个边界在移动，以及哪些候选可以一起排除。先看代码遇到的问题，后面再回到矩阵，把这些关系补清楚。

三、第一次修改：abc没有重复，答案却一直是0

最初的代码用mapping_str保存字符的位置，遇到重复时移动left，没有重复时推进right。问题出在下面这部分：

python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        left = 0
        right = 0
        max_length = 0
        length = 0
        mapping_str = {}
        while right < len(s):

                left = mapping_str[s[right]] + 1
                del mapping_str[s[right]]
            else:
                mapping_str[s[right]] = right

我最开始把更新答案放在遇到重复的分支里。经过提示再推一遍"abc"，三个字符都进入else，max_length从头到尾没有改变，最后就返回了0。

合法窗口正常增长时，也需要更新答案。因此，第一次修改是在else中补上一行：

python
max_length = max(right - left + 1, max_length)

此时right还没有加1，它指向本轮准备加入的字符；加上这个字符后的窗口长度是right - left + 1。

四、第二次修改：abcabcbb把已经重复的abca算成了4

给else补上更新后，"abc"能够得到3了，但if中的更新还保留着。处理"abcabcbb"的第二个a时，窗口发生了下面的变化：

此时left = 0、right = 3，计算出的长度4对应"abca"。它已经有两个a，却在移动左边界之前被写进了max_length。后面即使恢复了合法窗口，max()也不会把错误记录的4降回3。

展开第2版完整错误代码
python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        left = 0
        right = 0
        max_length = 0
        length = 0
        mapping_str = {}
        while right < len(s):
            if s[right] in mapping_str:
                max_length = max(right - left + 1, max_length)
                left = mapping_str[s[right]] + 1
                del mapping_str[s[right]]
            else:
                max_length = max(right - left + 1, max_length)
                mapping_str[s[right]] = right
                right += 1

所以这次删除了重复分支里的答案更新，先处理重复，等下一轮重新插入当前字符时再统计。真正需要保证的是“统计时窗口合法”，不只是把更新语句放进某一个固定分支。后面的简化写法会在两个分支汇合后统一统计，依据也是这个要求。

五、第三次修改：ccbbcc中的历史位置让left回退了

去掉错误的计长位置后，"ccbbcc"仍然返回了3，正确结果应该是2。这次问题出在：

python
left = mapping_str[s[right]] + 1

处理完下标3的第二个b后，left已经移动到3，但字典仍保留着c: 1。接着处理下标4的c，上面这行就会把left设成1 + 1 = 2，重新把下标2的b包括进来。

下一轮统计的区间变成"bbc"，于是错误地记录了长度3。字典中有这个字符，只能说明之前出现过，不能说明它现在还在窗口内。

展开第3版完整错误代码
python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        left = 0
        right = 0
        max_length = 0
        length = 0
        mapping_str = {}
        while right < len(s):
            if s[right] in mapping_str:
                left = mapping_str[s[right]] + 1
                del mapping_str[s[right]]
            else:
                max_length = max(right - left + 1, max_length)
                mapping_str[s[right]] = right
                right += 1
        return max_length

看到这个反例后，我想到应当把旧位置与left比较：只有旧位置大于等于left，它才属于当前窗口中的重复字符。如果旧位置已经在窗口外，就不应该再用它缩小left。因此把这一行改成了：

python
left = max(left, mapping_str[s[right]] + 1)

设旧位置为p，这句同时处理了两种情况：

旧位置与窗口的关系left怎样变化原因
p < left保持left旧字符已经离开窗口
p >= left移到p + 1排除窗口内的旧字符

改完这一行后，我的提交通过了。下面保留按这次修改整理出的完整版本，方便和后面的简化写法比较。

展开按最终修改整理的原版代码
python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        left = 0
        right = 0
        max_length = 0
        length = 0
        mapping_str = {}
        while right < len(s):
            if s[right] in mapping_str:
                left = max(left, mapping_str[s[right]] + 1)
                del mapping_str[s[right]]
            else:
                max_length = max(right - left + 1, max_length)
                mapping_str[s[right]] = right
                right += 1
        return max_length

六、窗口左边界：重复区域与单向移动

前三次修改都涉及同一个问题：当前记录的区间，究竟是否满足“没有重复字符”？把它放回最初的矩阵，就能进一步解释为什么边界可以跳，以及为什么不能回退。

先固定一列，也就是固定起点。随着终点增大，子串不断向后扩展。某个子串一旦已经重复，继续追加字符不会消除原有的重复。在前面的坐标方向下，无效的候选会延伸到该格子的下方；更短的子串仍可能合法，例如"abca"无效，但它上面的"abc"合法。这里应当根据起止位置判断，不能只用“上方”“下方”概括。

再固定一行，也就是固定终点。把起点向右移动，相当于删去一段前缀。无重复子串删去前缀后，仍然没有重复。于是同一行会呈现这样的关系：

text
起点从小到大：无效候选…… | 最靠左的合法候选 | 更短的合法候选……

每一行只需要保留最靠左的合法候选，因为它已经是这个终点下最长的合法子串。把这个起点记为L(r)，就有：

answer=max⁡0≤r<n(r−L(r)+1)\mathrm{answer}=\max_{0\le r<n}\bigl(r-L(r)+1\bigr)

终点向后走时，之前已经无效的起点仍然无效，所以L(r)只能保持或增大。这就把矩阵里的搜索，变成了追踪一条不向左退的合法边界。

用left和right表示这个连续区间，移动边界时复用已经得到的状态，这种方法叫作滑动窗口。这里两个边界都向前移动，也属于同向双指针。它不需要二维动态规划表；矩阵帮助说明候选之间的关系，实际只保存边界和必要记录即可。

不过，右边界每到一个新位置，仍要检查新字符与整个当前窗口是否冲突。"abc"后追加"a"时，虽然新字符与紧挨着的"c"不同，窗口中仍然出现了重复。

6.1 循环不变量：窗口内不重复的约束

写代码时，可以把必须维持的条件明确为：每次更新答案时，s[left:right+1]没有重复字符，且left是当前right对应的最小合法起点。

这种在循环的指定位置始终成立的性质，叫作循环不变量。前半句保证没有把错误窗口计入答案，后半句保证没有多删字符、漏掉更长的候选。

假设加入新字符ch之前，旧窗口已经没有重复。新加入的字符是唯一可能引入重复的来源。如果它上次出现的位置为p且仍在窗口内，那么：

  1. 起点不越过p，两个ch都还在，窗口一定无效。
  2. 起点移到p + 1，旧ch被排除，旧窗口剩余的部分仍然没有重复，已经足够。

所以max(left, p + 1)得到的正好是本轮最小的合法起点。每个终点都保留了最长合法子串，再取长度的最大值，就不会漏掉全局最优解。空字符串没有非空候选，直接保留答案0。

七、最终解法：用最后出现位置，一轮完成窗口修复与计长

原来的删除重插版本已经可以正确求解。复盘时再把每轮的动作整理一下，可以省去重复处理同一字符的过程。

这里规定：last[ch]保存字符ch在已扫描前缀中最后出现的位置。它记录历史位置，不要求恰好等于当前窗口的成员。

python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        left = 0
        best = 0
        last = {}  # 字符 -> 已扫描前缀中的最后出现位置

        for right, ch in enumerate(s):
            if ch in last:
                # 窗口内重复就跳过旧位置；窗口外的记录不会让left回退
                left = max(left, last[ch] + 1)

            last[ch] = right  # 修复边界后，再覆盖为本次位置
            best = max(best, right - left + 1)  # 此时窗口已合法

        return best

与原版本相比，这里直接覆盖字符的位置，right每轮自然前进。原来没有使用到的length也一并去掉了。

7.1 窗口外历史记录的保留与边界判定

我后来还有一个疑问：既然last保留了窗口外的字符，为什么不把它们清掉？原因就在于，字典回答“上次出现在哪里”，left负责说明“哪里才是当前窗口”。判断冲突时要把两者结合起来。

例如"abba"处理最后一个a之前，left = 2，旧记录是last['a'] = 0。它已经在窗口外，因此：

python
left = max(2, 0 + 1)  # 保持2，得到窗口"ba"
last['a'] = 3         # 随后记录这个新a的位置

保留历史索引本身不会破坏窗口，之前的问题是使用它时遗漏了有效范围的判断。这里与两数之和也能联系起来：同样是字典，那里保存“数值→原下标”，这里保存“字符→最后位置”；容器里每一项代表什么，必须由算法明确规定。哈希查找本身的机制可以接着看哈希表介绍。

八、另一种解法：用集合保存当前窗口，逐个移除重复

看到还有“双指针＋滑动窗口＋set”的写法后，我想知道它和自己的方法有什么区别。这几个词分别说明的是边界怎样表示、区间怎样维护、状态用什么容器保存。索引字典版同样使用双指针和滑动窗口，只是记录的内容不同。

集合set可以保存不重复的元素，并判断某个元素是否存在。本题用它回答的是：当前窗口里有没有ch？它不保存这个字符的位置，因此遇到重复时，要从左端逐个移除字符，直到旧ch被移出去。

python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        left = 0
        best = 0
        window = set()  # 加入ch之前，恰好对应s[left:right]中的字符

        for right, ch in enumerate(s):
            # 移除一个左端字符不一定能解决重复，需要持续检查
            while ch in window:
                window.remove(s[left])
                left += 1

            window.add(ch)  # 旧ch已不在窗口内，现在可以加入
            best = max(best, right - left + 1)

        return best

例如"abcb"处理最后一个b时，逐步变化如下：

第一次移除的是a，旧b还留在窗口里，所以这里必须用while持续收缩，直到重复被消除。索引字典知道旧b在下标1，就可以直接把left移动到2；集合版通过实际移除，最终到达同一个位置。

add与remove的语法可以回看旧集合笔记中的增删部分。本题调用remove时，旧窗口没有重复、集合与窗口同步，因此左端字符一定还在集合中。集合与映射的正式接口分别见Python文档中的set与dict。

九、时间复杂度：累计计算左右边界的移动次数

先约定n为字符串长度，k为整个字符串实际包含的不同字符数量，W为最大合法窗口长度，Σ为允许的字符种类数量。显然有：

W≤k≤min⁡(n,Σ)W\le k\le\min(n,\Sigma)

下面按字符访问和比较为常数成本、哈希分布正常时的平均查询成本分析；哈希插入的扩容成本按一串操作均摊。空间复杂度只统计辅助空间，不重复计算输入字符串。

9.1 从完整枚举到保留窗口：减少重复检查

方法时间上界辅助空间重复工作的来源或前提
每个区间重新检查是否重复O(n³)O(n)O(n²)个区间，每次最多扫描O(n)个字符
每个起点重新扩展，遇重复停止O(n²)O(k)每个起点维护集合，但不同起点仍会重扫
集合维护当前窗口平均O(n)O(W)每个位置最多入窗、出窗各一次
字典保存最后位置平均O(n)O(k)每个位置进行常数次查询与写入
有限字符集的索引数组O(n+Σ)O(Σ)先初始化Σ个位置，字符需能正确映射到数组

这些是便于比较的上界，前两种在字符集很小时还可进一步收紧。例如增量扩展遇到重复就停止，通常扫描不到字符串末尾。不过，矩阵有O(n²)个候选，不代表必须逐个访问它们；窗口算法利用合法性的关系，复用了不同候选之间的状态。

也不需要真的切出全部子串。长度为d的子串有n - d + 1个，若将所有内容都复制保存，总字符数为：

∑d=1nd(n−d+1)=n(n+1)(n+2)6=Θ(n3)\sum_{d=1}^{n}d(n-d+1)=\frac{n(n+1)(n+2)}6=\Theta(n^3)

正文里的切片用于说明范围，最终代码通过左右下标计算长度，没有在每轮创建窗口字符串。

9.2 集合版的内层循环，应该累计计算移动次数

外层循环让right走过n个位置。内层循环虽然可能一次删除多个字符，但left从0开始只向前走，所有轮次加起来最多移动n次。

因此，全程加入字符不超过n次，移除字符不超过n次，再加上每轮退出内层循环的检查，操作总数仍与n成正比。不能把“外层n次”直接乘上“某一次内层可能n次”，因为每一轮并不会重新从左端开始删除。

索引字典版则在每个right上直接计算新边界，进行常数次哈希操作。两者在上述条件下都是平均O(n)。严重哈希冲突时，单次操作可能退化，不能把这个平均结论写成任何输入与实现下都严格保证的线性时间。

原来的删除重插版本也是同样的量级：每个right最多经历一轮删除和一轮插入，不会无限停在同一个字符上。换成for后，省掉的是重复判断、删除和重插的常数开销，没有从O(n²)变成O(n)。

在通常把字符集也作为问题规模条件的模型下，最坏情形需要检查线性数量的输入字符，平均线性的窗口解法已经达到这一量级。对于本题，索引字典版是很合适的最终实现；它和集合版都可以作为线性解法，不能仅凭循环层数判定谁更优。

9.3 空间差别：当前成员与全部历史索引

集合只保存窗口里的字符，所需记录最多为W个；字典保留整个已扫描前缀中各字符的最后位置，最多有k项。因此二者分别为O(W)和O(k)。因为W ≤ k，集合维护的信息可能更少，但它每个元素的实际分配成本也要由实现决定。

如果字符集固定且很小，也可以把这些辅助空间写成相对于n的O(1)。不过，写出W、k和Σ，更容易看清不同方法到底保存了什么。索引数组还要支付O(Σ)的初始化成本；不能看到题目有英文字母，就擅自只准备26个槽位，数字、符号与空格同样属于输入范围。

十、set与dict方案的适用条件及扩展性

我在比较两种写法时，还需要弄清楚一个问题：是因为集合查找更快，所以更适合本题吗？从这里的复杂度看，set和dict的成员查询通常都按平均O(1)分析，选择的依据是算法需要直接查询什么信息。

需要回答的问题保存的状态能直接完成的动作
当前窗口里有没有这个字符？set保存成员判断重复，配合左端逐个删除
这个字符最后出现在哪里？dict保存字符→索引直接计算左边界跳到哪里
当前窗口里有多少个这个字符？dict保存字符→次数根据数量判断是否合法、增减计数

索引跳转利用了本题的特殊条件：旧窗口已经无重复，加入一个字符后，只需排除它的上一次出现。因此最后位置足够确定新的最小合法起点。

“维护当前窗口状态，边加入边修复”的方法更容易扩展，但扩展的并不是set这个容器本身。如果条件需要次数，就应改用计数字典。

条件怎样变化需要保留什么对原解法的影响
每个字符最多出现2次当前频次，或更丰富的出现位置记录只存一个最后位置，不能直接照搬本题更新式
最多K种不同字符各字符频次与不同字符种类数删除到计数为0时，才减少种类数
覆盖指定字符及其要求次数需求计数、窗口计数与满足情况合法之后还要尝试缩短，答案更新时机也改变

对于“求最长合法窗口，删去前缀不会破坏合法性”这一类问题，常见过程是：

text
加入右端元素，更新窗口状态
当窗口不合法时：
    移除左端元素，更新状态，推进left
窗口恢复合法后，更新最长长度

这个结构有条件，不能作为所有区间问题的万能模板。例如求最短覆盖时，需要在满足条件后记录候选并继续收缩；某些含负数的区间和问题，也不再具有移除左端就能按预期改变总和的单调关系。

所以，本题可以选索引字典直接跳转；想练习更一般的窗口状态维护，则可以继续理解集合版，再过渡到计数版。它们不是互相替代的知识，关键是分清本题有哪些信息可以省略，条件变化后又需要补回哪些信息。

十一、平台耗时与内存显示的影响因素

修改后我还关注过几种写法显示出来的时间和内存差异。不过，仅看一次结果，很难确定差异究竟来自哪一部分；这里没有同一环境下的多次测量，先从代码做定性分析。

原版本遇到字典里已有的字符，需要先删除，保持right不动，下一轮再判断并插入。简化字典版直接覆盖位置，确实减少了一些操作。集合版则会逐个移除左端字符，移除次数与输入的重复分布有关。因此，相同的O(n)并不保证实际耗时相同，也不能直接推出某个版本在所有输入上都更快。

空间上，原版本和简化字典版都保存字符及索引，仍为O(k)。去掉一个没有使用的length变量，只减少常数空间，无法据此解释很大的内存差距。平台内存还可能包含解释器、容器分配等成本，不能直接拿它当作“字典保存项数”的测量。

如果以后需要认真比较，应固定代码、解释器和输入，分别测试重复密集、字符分散等情况，多次运行后观察结果。平台的击败比例也只是相对统计，不能换算成“性能提升了多少倍”。本篇没有做性能基准，因此只保留操作数量与空间规模上的比较。
