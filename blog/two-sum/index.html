力扣1.两数之和：题目与输入要求

1. 两数之和力扣原题 ↗

给定一个整数数组 nums 和一个整数目标值 target，请你在该数组中找出 和为目标值 target 的那 两个 整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。

你可以按任意顺序返回答案。

示例 1：

text
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：因为 nums[0] + nums[1] == 9 ，返回 [0, 1] 。

示例 2：

text
输入：nums = [3,2,4], target = 6
输出：[1,2]

示例 3：

text
输入：nums = [3,3], target = 6
输出：[0,1]

提示：

  • 2 <= nums.length <= 104
  • -109 <= nums[i] <= 109
  • -109 <= target <= 109
  • 只会存在一个有效答案

进阶：你可以想出一个时间复杂度小于 O(n2) 的算法吗？

读完题目，我首先注意到了两个要求：返回的是原数组下标，而且两个下标必须不同。数值相同没有关系，例如[3, 3]中的两个3来自不同位置，就可以组成答案。

下面先用已有的循环知识把题目做出来，再沿着查找过程寻找优化的位置。哈希表用到的知识会在需要它时补上（如果你还不熟悉，可以配合哈希表介绍一起看）。

暴力枚举：固定一个下标，检查后面的所有元素

先固定第一个数，再把它后面的数依次拿来相加。外层下标是i，内层下标是j，检查条件就是nums[i] + nums[j] == target。

让j从i+1开始，就能保证两个位置不同，也不会在检查完(i, j)后再检查一次(j, i)。

python
def two_sum_brute(nums, target):
    n = len(nums)
    for i in range(n):
        # 只检查i后面的元素：不使用自身，也不重复检查同一对位置
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return [i, j]  # 返回原数组下标
    return []

例如[3, 2, 4]、target = 6，会依次检查3 + 2、3 + 4和2 + 4，最后得到[1, 2]。

这个方法能够找到答案，但第一个数最多比较n - 1次，第二个最多比较n - 2次，最坏情况下总共需要：

(n−1)+(n−2)+⋯+1=n(n−1)2(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}

所以，暴力枚举的时间复杂度是O(n²)，辅助空间是O(1)。接下来可以从内层反复查找的过程入手，看看怎样减少这部分工作。

优化的切入点：固定当前数后，另一个数已经确定

假设当前数是x，目标值是target，另一个数必须满足：

x+need=target⟹need=target−xx+\text{need}=\text{target} \quad\Longrightarrow\quad \text{need}=\text{target}-x

这个需要基于当前数x寻找的数，记为补数need。比如当前数是4、目标是6，那么接下来只需要找2，并不需要重新计算4与所有数的和。

不过，算出补数还没有解决查找的开销。如果仍然用need in nums在列表中寻找，每次查询还可能遍历整个列表，总时间依然是O(n²)。因此，还需要一种能够按数值快速查询、同时取出它的位置的结构。

这一步就需要补充哈希表的知识了。只用已有的循环和列表知识，可以得到暴力解，也可以把问题改写成寻找补数；要继续优化，还需要知道“按一个确定的值查询信息”可以交给哈希表来做。

引入字典：保存“已经出现的数值→原数组下标”

Python的字典dict可以保存一组对应关系。用于查询的内容叫键（key），与它关联的内容叫值（value）。CPython（常见的Python解释器实现）用哈希表实现字典，在正常散列分布下，按键查询的平均成本可以按O(1)分析。

本题需要用数值寻找原下标，因此可以把记录写成：

python
seen = {3: 0, 2: 1}
# 键3对应值0：数值3出现在原数组下标0
# 键2对应值1：数值2出现在原数组下标1

字典的value保存的是主动写入的原数组下标。字典本身负责维护键值对应关系，并不会根据数值自动知道它在nums中的位置。

为了只遍历一次数组，seen只保存前面已经遇到的数。每读到当前数x，先查它的补数；找到了就返回两个位置，还没找到就把x的位置记下来，供后面的数查询。

处理到4时，need = 6 - 4 = 2，字典中已经有2: 1。取出下标1，再配上当前下标2，得到的就是答案[1, 2]。

完整代码：先查询补数，再写入当前元素

下面是可以直接在本地调用的函数。enumerate(nums)会同时给出当前下标i和该位置的数x；need in seen检查的是字典中有没有这个键。

python
def two_sum(nums, target):
    seen = {}  # 已经出现的数值 -> 它在nums中的一个原下标

    for i, x in enumerate(nums):
        need = target - x

        # 查询时，seen里只保存i之前的位置
        if need in seen:
            return [seen[need], i]

        # 当前数留给后面的元素使用；同一个键再次出现时更新下标
        seen[x] = i

    return []  # 本地调用时约定无解返回[]；原题保证有解
python
print(two_sum([3, 2, 4], 6))  # [1, 2]
print(two_sum([3, 3], 6))     # [0, 1]

在力扣的Python模板中，把函数放进class Solution，改成def twoSum(self, nums, target):即可，函数主体不需要改变。

为什么查询必须放在写入前面

先查后存保证补数来自之前的位置。以[3, 3]、target = 6为例，第一个3查询时字典为空，随后写入3: 0；第二个3查询时才能取出下标0，返回[0, 1]。

如果交换这两步，第一个3会先写入seen[3] = 0，接着又通过查询3取出刚写入的0，返回[0, 0]。这就违反了不能重复使用同一元素的要求。

为什么只查前面的元素也不会漏掉答案

进入下标i这一轮时，seen中保存的下标都小于i，并且前面出现过的每种数值都有一条记录。这个每轮开始时都成立的条件，叫作循环不变量。

设答案对应p < q。处理到q时，nums[p]已经出现，而当前需要的补数恰好是nums[p]，所以一定能查到。重复数值可能更新记录中的下标，但留下的位置仍在q之前，且数值相同，仍然能组成有效答案。

本题只要求返回一组答案，因此不需要保存同一数值的所有位置。如果改成返回全部配对，记录方式和返回时机就需要一起调整。

边界情况：重复值、0、负数与原下标

输入与目标值有效结果需要检查的地方
[3, 3]，6[0, 1]数值可以相同，下标必须不同
[0, 4, 3, 0]，0[0, 3]下标0是有效位置；用in检查键是否存在
[-3, 4, 3, 90]，0[0, 2]负数照常作为键，不影响补数计算
[2, 7]，9[0, 1]长度为2时，第二轮也可以找到答案
[1, 2]，9[]不属于原题保证有解的输入，用来核对本地函数的无解约定

这份哈希解法不会排序或改写nums，返回的始终是原数组下标。Python整数也没有固定32位整数溢出的问题；换用其他语言时，需要结合输入范围选择整数类型。

时间与空间复杂度：期望O(n)，辅助空间O(n)

每个元素只会触发常数次字典查询和至多一次写入。在有界整数按固定字长成本分析、散列分布合理的条件下，查找为期望O(1)，插入为期望均摊O(1)，因此：

E[T(n)]=O(n),S(n)=O(n)\mathbb{E}[T(n)]=O(n),\qquad S(n)=O(n)

优化的代价是多保存一张字典，最多记录O(n)项。这也是本题“用空间换时间”的具体位置。

对于没有排序等额外结构的输入，要保证找到答案，最坏情况下需要读取线性数量的元素。因此，哈希解法的期望O(n)已经达到了这个读取量级。这里的期望仍依赖哈希性能；严重冲突时单次查询可能退化，整段算法的最坏时间仍可能达到O(n²)。哈希表的复杂度说明会继续解释“期望”和“均摊”。

进一步的问题：只用数组时，还能怎样优化

当时我还不知道有哈希表，所以一直在考虑怎样只用数组求解。后来经过分析和AI讨论，整理出了下面两种方法，可以根据值域和空间要求选择。

方法时间复杂度本文实现的辅助空间适用条件
排序＋双指针O(n log n)O(n)保存(数值, 原下标)，排序后仍能返回原位置
直接寻址数组O(n+V)O(V)值域V足够小，可以用x - lo作为记录数组下标

“只能用数组”还不足以确定唯一的最快方法。数组也能实现哈希表，直接寻址又依赖值域；这些条件说明清楚后，复杂度才有比较的依据。

排序与直接寻址的推导、代码和复杂度

排序＋双指针：保留原下标再排序

先把元素保存成(数值, 原下标)并按数值排序，再用两个位置分别指向最小值和最大值。和偏小时提高左侧值，和偏大时降低右侧值。

和偏小时，左侧这个数与当前范围内最大的数相加都不够，与更小的数配对也不会够，所以可以排除当前左端。右端的排除理由同理。

python
def two_sum_sorted(nums, target):
    # 排序改变的是配对数组，原下标跟着数值一起保留
    pairs = sorted((x, i) for i, x in enumerate(nums))
    left, right = 0, len(pairs) - 1
    while left < right:
        total = pairs[left][0] + pairs[right][0]
        if total == target:
            return [pairs[left][1], pairs[right][1]]
        if total < target:
            left += 1
        else:
            right -= 1
    return []

排序需要O(n log n)时间，指针移动需要O(n)时间，配对数组占O(n)空间。Python排序也可能使用O(n)临时空间，不能只根据“在原列表上排序”判断为O(1)辅助空间。

直接寻址：值域小时，用数值计算记录数组下标

如果所有数都在lo到hi之间，可以建立长度为V = hi - lo + 1的数组，用x - lo作为记录位置。减去lo既能让下标从0开始，也能处理负数。

python
def two_sum_direct(nums, target):
    if len(nums) < 2:
        return []
    lo, hi = min(nums), max(nums)
    # 仅适用于值域hi-lo+1足够小的输入
    positions = [-1] * (hi - lo + 1)
    for i, x in enumerate(nums):
        need = target - x
        # 先检查值域，避免need-lo超出记录数组范围
        if lo <= need <= hi and positions[need - lo] != -1:
            return [positions[need - lo], i]
        positions[x - lo] = i
    return []

用-1表示尚未出现，0要留给有效的原数组下标。初始化需要O(V)，遍历需要O(n)，总时间O(n+V)、空间O(V)。原题的数值范围很大，不适合按整个范围分配这张数组；这里只用于值域较小的输入。

我以后再遇到类似问题，可以先明确每一步要查询什么。两数之和需要查询“某个数是否出现、出现在哪”，所以保存数值→位置；统计频率可以保存数值→次数；只关心是否出现过，则可以用集合。至于键经过哈希计算后怎样取出对应的值，接着看哈希表（二）：键值映射与Python字典查找。

如果输入已经有序，两数之和II的相向双指针可以利用排序条件排除端点，用O(1)额外空间完成查找。而前缀和中的和为K的子数组会把区间和转为旧前缀查询，保留同样的“先查后存”顺序，但表里的值需要从下标换成出现次数。
