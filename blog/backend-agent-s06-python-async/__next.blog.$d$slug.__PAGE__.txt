26:T1ed1,<h2 id="section-调用async函数以后任务何时开始">调用async函数以后，任务何时开始</h2>
<p>假设要查三份相互独立的资料。如果每查完一份才开始下一份，等待时间会逐项累积；它们没有数据依赖时，就可以在等待网络响应的过程中交错推进。</p>
<p>Python调用<code>async def</code>函数会得到<strong>协程对象</strong>，这一步本身不代表函数体已经执行。<code>await</code>用于等待可等待对象；<code>asyncio.create_task</code>把协程包装为受事件循环调度的<strong>Task</strong>。调度以后何时获得执行机会，还取决于事件循环和其他任务的行为。<a href="https://docs.python.org/3.13/library/asyncio-task.html" rel="noopener noreferrer">Python3.13协程与Task</a></p>
<p><code>await</code>也不保证每次都发生切换。例如等待对象已经就绪时，任务可能继续执行。长时间纯计算如果没有让出控制权，仍可能占据事件循环线程。</p>
<h2 id="section-先建立依赖再决定哪些工具能同时调用">先建立依赖，再决定哪些工具能同时调用</h2>
<p>查订单和查物流可能都需要同一个订单号，若订单号已经确认，两者可以并发；如果必须先通过用户信息找到订单号，就不能把后续查询无条件同时发出。</p>
<p>工具副作用也会限制并行。两个读取可以独立完成，但“创建工单”和“关闭同一工单”有业务顺序；两个同时修改同一对象的工具则需要并发协议。<strong>能创建两个Task，不等于业务允许它们并发执行。</strong></p>
<p>结果还应通过调用ID或明确位置关联，不能根据返回先后猜测属于哪一个请求。较慢任务可能后完成，但输入与输出关系必须保持正确。</p>
<h2 id="section-用semaphore限制同时执行的工具数量">用Semaphore限制同时执行的工具数量</h2>
<p><strong>Semaphore（信号量）</strong>在这里用于限制同时进入调用区间的任务数量。下面只用<code>asyncio.sleep</code>模拟可让出执行权的等待，不访问外部服务。示例兼容Python3.11及以上，不依赖额外库。</p>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">import</span> asyncio

<span class="hljs-keyword">async</span> <span class="hljs-keyword">def</span> <span class="hljs-title function_">query_one</span>(<span class="hljs-params">name, slots</span>):
    <span class="hljs-keyword">async</span> <span class="hljs-keyword">with</span> slots:  <span class="hljs-comment"># 进入实际调用前占用一个并发名额</span>
        <span class="hljs-keyword">await</span> asyncio.sleep(<span class="hljs-number">0.01</span>)
        <span class="hljs-keyword">return</span> <span class="hljs-string">f"result:<span class="hljs-subst">{name}</span>"</span>

<span class="hljs-keyword">async</span> <span class="hljs-keyword">def</span> <span class="hljs-title function_">main</span>():
    slots = asyncio.Semaphore(<span class="hljs-number">2</span>)
    tasks = [asyncio.create_task(query_one(name, slots))
             <span class="hljs-keyword">for</span> name <span class="hljs-keyword">in</span> [<span class="hljs-string">"A"</span>, <span class="hljs-string">"B"</span>, <span class="hljs-string">"C"</span>]]
    <span class="hljs-comment"># gather按传入任务的位置组织结果，不按完成先后重新排序</span>
    results = <span class="hljs-keyword">await</span> asyncio.gather(*tasks)
    <span class="hljs-keyword">assert</span> results == [<span class="hljs-string">"result:A"</span>, <span class="hljs-string">"result:B"</span>, <span class="hljs-string">"result:C"</span>]
    <span class="hljs-built_in">print</span>(results)

<span class="hljs-keyword">if</span> __name__ == <span class="hljs-string">"__main__"</span>:
    asyncio.run(main())
</code></pre></div>
<p>三个Task都已经创建，但最多两个同时进入受限区间。第三个等待名额，直到前面的任务退出。真实工具应把并发限制覆盖到实际资源占用区间，而不是刚发出请求就提前释放。</p>
<p>这个例子只适合有限数量的任务。如果一次创建一百万个Task，信号量限制了正在执行的数量，却没有限制全部待处理Task占用的内存。更大的输入适合有界队列和固定工作者，让生产速度也受到约束。</p>
<h2 id="section-同步库失败和取消的边界">同步库、失败和取消的边界</h2>
<p>在事件循环线程里直接调用阻塞HTTP客户端，会让整个线程等待，其他Task也无法按预期推进。可以选择真正的异步客户端；对于适合转移的阻塞I/O，也可以使用<code>asyncio.to_thread</code>等方式。但把计算放进线程，不等于在所有CPython构建中都能并行执行Python字节码，具体还要看版本、GIL配置和扩展是否释放GIL。</p>
<p><code>gather</code>默认传播异常时，不应假定其他任务都会自动停止。若希望一组任务按结构化并发管理，可以考虑Python3.11开始提供的<code>TaskGroup</code>，并按其异常和取消规则设计清理。无论采用哪种方式，都要回收已经创建的任务，不把后台未决动作遗忘。</p>
<p><strong>取消通常是协作式的控制信号，不是任意位置强制回滚。</strong> 协程需要在合适的等待位置响应取消，通过<code>finally</code>或上下文管理器清理本地资源。已经交给线程或外部系统的工作，不一定随调用方停止等待而终止。</p>
<p>比如创建工单请求超时，协程结束并不能证明工单没有创建。外部状态仍按<a href="/blog/backend-agent-s01-recovery/">结果未知与幂等</a>处理；读取类任务与有副作用任务不能使用完全相同的重试策略。</p>
<h2 id="section-面试问答多个tool怎样异步并发">面试问答：多个Tool怎样异步并发</h2>
<p><span id="q-FQ-doxcninSKVYiM7bU9Rb4O6CAn6Y" class="legacy-anchor" aria-hidden="true"></span><a id="user-content-q-FQ-doxcninSKVYiM7bU9Rb4O6CAn6Y"></a></p>
<blockquote>
<p>Python 里多个 Tool 同时调用时，怎么做异步并发？</p>
</blockquote>
<p><strong>回答：</strong> 先根据数据依赖和副作用确定可并行工具，再使用异步客户端与Task调度，并通过信号量或工作队列限制实际并发。每个调用应关联ID、超时、错误类别和结果状态，不能仅创建Task后等待一个结果列表。</p>
<p>少量独立任务可以用<code>create_task</code>和<code>gather</code>组织；需要共同生命周期时，可按Python版本使用<code>TaskGroup</code>。阻塞库不能直接放在事件循环中执行长时间I/O，应更换异步接口或转移到合适的工作线程。大量任务还需要有界队列，避免全部Task先创建出来导致内存积压。</p>
<p>失败处理要区分一个结果失败是否影响其他任务。如果任务互相独立，可以保留已成功结果并单独报告失败；如果后续步骤需要所有结果，就应停止依赖步骤。取消后还要清理本地资源，并核对已经发出的外部副作用，不能把“调用方不再等”写成“远端已停止”。</p>
<p><strong>延伸追问（自拟）：async是否让CPU密集工具自动并行？</strong> 不会。协程主要帮助等待期间交错推进。CPU任务需要依据运行时与部署选择进程、合适的线程或其他执行资源，同时控制开销与数据传递。</p>
