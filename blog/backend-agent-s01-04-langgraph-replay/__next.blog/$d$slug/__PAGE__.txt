13:T1f01,<h2 id="section-先把报告任务表示成状态与节点">先把报告任务表示成状态与节点</h2>
<p>假设一个Agent负责整理报告，流程是“检索资料→生成草稿→人工确认→保存报告”。<strong>节点</strong>表示一次处理步骤，<strong>边</strong>表示下一步去哪里，<strong>状态</strong>保存各步骤需要继续使用的数据。</p>
<p>状态可以包含<code>request_id</code>、证据列表、草稿内容、草稿版本和审批结果。节点读取状态后返回更新；多个节点写入同一个字段时，需要预先定义怎样合并。这种合并规则在LangGraph中称为<strong>reducer</strong>。例如列表可以追加，单个草稿版本可以替换，不能把所有字段都默认相加。</p>
<p>LangGraph提供图式执行、条件分支和持久化等能力，适合需要追踪执行位置、暂停与恢复的流程。框架能够管理这些结构，具体业务的完成条件、权限与错误处理仍由应用定义。</p>
<h2 id="section-检查点保存了什么">检查点保存了什么</h2>
<p><strong>检查点（checkpoint）</strong>用于保存执行过程中可恢复的图状态与相关执行信息。通过同一个<code>thread_id</code>，应用可以找到对应任务的状态；历史检查点则可以区分任务在不同阶段的版本。</p>
<p>教学过程可以记为：</p>



































<table><thead><tr><th>检查点</th><th align="right">草稿版本</th><th>已完成内容</th><th>后续动作</th></tr></thead><tbody><tr><td>C1</td><td align="right">无</td><td>检索完成</td><td>生成草稿</td></tr><tr><td>C2</td><td align="right">1</td><td>草稿已生成</td><td>等待确认</td></tr><tr><td>C3</td><td align="right">1</td><td>审批通过</td><td>保存报告</td></tr><tr><td>C4</td><td align="right">1</td><td>保存结果已记录</td><td>结束</td></tr></tbody></table>
<p>持久化保存器应与运行要求匹配。内存保存器适合本地演示，进程退出后不能据此承诺仍可恢复。需要跨重启恢复时，要使用合适的持久化后端，并处理状态Schema升级、租户隔离和访问权限。</p>
<p><code>thread_id</code>也只是状态定位信息，不能直接当成鉴权凭证。知道某个任务ID，不应该就能读取或批准别人的任务。</p>
<h2 id="section-interrupt恢复时从节点开头重新执行">interrupt恢复时，从节点开头重新执行</h2>
<p>LangGraph的<code>interrupt()</code>可以把审批内容返回给外部，暂停等待输入；恢复时通过<code>Command(resume=...)</code>提交结果。关键细节是：<strong>恢复会重新进入发生中断的节点，中断之前的代码可能再次执行。</strong><a href="https://docs.langchain.com/oss/python/langgraph/interrupts" rel="noopener noreferrer">LangGraph中断说明</a></p>
<p>下面是节点逻辑示意，省略图的注册与保存器配置：</p>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">review_node</span>(<span class="hljs-params">state</span>):
    <span class="hljs-comment"># 这里只准备可重复计算的数据，不发送报告或扣费。</span>
    payload = {
        <span class="hljs-string">"draft"</span>: state[<span class="hljs-string">"draft"</span>],
        <span class="hljs-string">"draft_version"</span>: state[<span class="hljs-string">"draft_version"</span>],
    }
    answer = interrupt(payload)
    <span class="hljs-keyword">return</span> {<span class="hljs-string">"approval"</span>: answer}
</code></pre></div>
<p>这个片段依赖LangGraph的<code>interrupt</code>导入，展示的是节点结构，并非独立可运行程序。执行外部写入应放在明确的后续步骤，并为它设置业务幂等键。</p>
<p>例如用<code>request_id + draft_version + action</code>确定保存操作。如果第一次保存成功后进程退出，恢复后再次执行保存，可以查询相同操作的结果，而不是生成重复记录。<strong>检查点管理执行状态，幂等处理管理外部世界的重复副作用。</strong></p>
<h2 id="section-修改草稿以后旧审批还有效吗">修改草稿以后，旧审批还有效吗</h2>
<p>审批应该绑定用户实际看到的草稿版本。用户确认v1之后，如果Agent又把草稿改成v2，就不能沿用v1的批准去发布v2。</p>
<p>可以让审批记录保存草稿哈希、版本和操作类型。保存节点检查当前草稿是否仍与审批对象相同；不一致时重新进入确认流程。审批结果也要检查操作者身份、有效期及是否已经使用，不能只接受前端传来的<code>approved=true</code>。</p>
<p>这类条件应由业务代码验证。提示词可以说明审批规则，但不能代替真正的状态检查。</p>
<h2 id="section-重放与分支为什么不会撤销外部操作">重放与分支为什么不会撤销外部操作</h2>
<p>从旧检查点恢复，可以重新执行后面的节点。使用<code>update_state</code>修改旧状态会形成新的检查点分支，原历史仍然保留。修改时也会应用相应reducer，因此对列表字段的更新未必等同于直接覆盖。<a href="https://docs.langchain.com/oss/python/langgraph/use-time-travel" rel="noopener noreferrer">LangGraph时间旅行</a></p>
<p>假设C4对应的报告已经保存到外部系统，回到C2生成另一份草稿，只会改变新的执行分支。外部系统中的旧报告不会自动消失。模型调用也可能得到不同结果，所以重放不能被理解为完全相同的录像回放。</p>
<p>调试时应区分两种目的：查看已经记录的输入输出，只需读取历史；尝试另一条执行路径，才需要重新运行节点。后者可能产生新费用或写入，应使用隔离环境或模拟工具。</p>
<h2 id="section-怎样验证恢复行为">怎样验证恢复行为</h2>
<p>本篇未安装LangGraph或调用付费模型，代码仅展示节点结构。接入框架后可以用确定性函数代替LLM，准备四个小测试：中断前的计数是否在恢复时增加；拒绝审批是否跳过保存；草稿变更后旧审批是否失效；保存成功后模拟进程退出，再恢复是否只产生一个业务结果。</p>
<p>还要测试状态字段变化与历史检查点兼容。一个旧任务保存的是<code>draft</code>字符串，新代码却期待<code>draft</code>对象时，恢复需要迁移或明确拒绝，不能让任务在半路以难以理解的方式失败。</p>
