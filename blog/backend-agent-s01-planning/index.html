任务还没查清楚时，计划能确定到什么程度

在Agent执行循环中，下一步取决于已经获得的信息。假设用户要求“查询订单，符合售后规则就建工单，然后通知我”，开始时只知道订单号，还不知道商品是否发出、是否已经处理过售后。

这时可以确定“需要查询订单”，却不能把“工单将创建成功”当作事实。计划描述准备怎样达到目标，观察记录实际查到了什么，验收判断目标是否已经满足。 三者可以放在同一任务状态中，但需要分开保存。

比较不同Agent范式时，我更关注的是：哪些决定可以提前做，哪些必须等外部信息回来以后再做。沿着这个问题看，ReAct和计划执行就比较容易区分。

ReAct怎样根据观察选择下一步

ReAct将任务推理、外部行动和观察交替组织。一个动作带回新信息，后续决策再使用这些信息。原论文研究的是这种交替组织方式，并不意味着所有工程系统都要向用户展示完整推理文本。ReAct论文

售后例子可以这样推进：

当前已经确认的信息下一项动作新观察怎样改变后续任务
只有订单号查询订单得到商品、发货状态和归属
订单未发货查询适用规则与已有工单确定是否允许创建、是否已经创建
存在同一事项的有效工单返回已有工单原本可能需要的创建步骤不再执行
没有工单且允许创建提交创建请求依据真实结果继续查询或完成

每一步只选择当前有依据的动作，适合路径会随环境变化的任务。代价是决策与工具调用可能反复往返，容易出现局部选择合理、整体却绕路的情况。比如连续搜索同一关键词，却始终不处理已经找到的订单号，就需要检查状态是否推进。

运行日志应保存工具参数、调用ID、外部返回和状态变化。模型生成的解释不能替代这些执行证据。

Plan-and-Execute怎样组织较长任务

Plan-and-Execute（计划与执行）先拆出子目标及其依赖，再逐项推进。计划可以由模型生成，也可以结合固定模板与程序规则；执行过程中还可以重新规划。

例如生成一份售后统计报告，可以先安排：确定统计口径→读取订单与工单→清洗和关联→计算指标→检查结果→生成文件。读取两个独立数据源可以并行，计算指标则必须等口径和输入确认。

一个有用的计划节点，应说明输入、预期产物、完成条件和依赖。例如“统计问题”太含糊，“按已确认的订单ID关联工单，输出未匹配记录和重复关联记录”才便于执行和检查。计划中的文件路径只是预期输出，直到文件实际生成并通过检查，才能转成已完成记录。

如果读取时发现工单数据只覆盖近30天，原计划却要求统计整年，就要调整范围或补数据。继续生成全年结论会把输入缺口隐藏起来。重新规划时还要说明哪些旧产物仍有效：仅修改报告标题不一定需要重算数据，修改统计口径通常需要。

反馈修订怎样避免原地打转

反馈修订根据测试、外部检查或具体反例修改当前方案。反馈最好指向可观察的问题，例如“导出记录总数应为12，文件只有11条”，而不是只说“再认真想一遍”。

假设教学数据中有12条订单，其中一条没有工单。实现使用内连接，结果只剩11条；检查指出缺失订单后，才能判断是否应改成左连接，以及没有工单的字段如何表达。若业务本来就要求只导出已建工单订单，则11条可能正确，需要先回到统计口径。

有反馈也需要判断反馈是否可靠。 错误测试、过期规则或不完整的参考答案都会误导修订。没有新证据的反复自评，不一定增加正确性，还可能让原本正确的结果被改错。

终止条件怎样覆盖成功和失败

可以同时设置目标验收、调用预算、时间预算和无进展检测。成功由产物与规则决定；缺少必要输入时等待补充；工具结果未知时进入查询或对账；预算耗尽时明确记录尚未完成的部分。

例如连续三次得到同样的权限错误，且身份和任务范围没有改变，再试一次通常不会产生新信息。程序应停止这条调用路径。若返回的是“任务仍在处理”，则可按约定间隔轮询，但仍需要截止时间。

两种范式也可以组合：外层计划确定几个子目标，内层使用短ReAct循环处理每个子目标的未知信息。比较收益时固定任务集和工具条件，观察成功率、步骤数、延迟与成本，才能判断额外规划是否值得。

面试问答：ReAct与Plan模式有什么区别

ReAct 和 Plan 模式有什么区别？

回答： ReAct根据当前观察选择动作，动作返回后继续决策；Plan模式通常先生成子目标及依赖，再由执行阶段推进，并在需要时修订计划。区别主要在决策粒度和规划时机，不是一个有反馈、另一个完全没有反馈。

ReAct适合信息需要逐步获取、路径变化较多的任务，例如先查订单，再依据状态决定是否查售后规则。它能及时利用外部反馈，但调用轮次可能较多，也可能局部绕路。计划执行适合依赖明确、跨度较长的任务，例如资料汇总后计算指标再生成报告；它便于检查覆盖和安排并行，但初始计划可能建立在错误假设上。

实现时，两者都需要持久状态、工具校验、预算与验收。计划节点要给出输入输出和完成条件，执行结果必须有真实证据；发现前提变化后，要使受影响节点和产物失效，再重新规划。固定流程与模型决策也可以混用，权限检查仍由可信程序执行。

延伸追问（自拟）：怎样防止循环或反复改计划？ 记录动作、参数、状态版本和新信息，识别重复错误与无进展；为局部修订设置预算，并把缺输入、结果未知和成功分成不同终态。重复次数只是保护，真正的完成判定仍要对照目标。
