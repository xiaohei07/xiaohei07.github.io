C++ 类型转换：四种转换符

比较四种命名转换符的用途，结合对象类型、运行时检查和 const 限定说明使用边界

这篇文章整理自 2023 年的 C++ 学习笔记，介绍四种转换符的用途、约束和常见误用。

先看转换的目的

隐式转换由编译器在符合语言规则时完成；显式转换由程序员写出来。C++ 的命名转换符区分了转换目的，使用时还要核对源对象与目标类型的条件。

转换符常见用途需要特别留意
static_cast<T>明确的数值转换、已知类型关系的转换下行转换需要调用方确认对象的实际类型
dynamic_cast<T>多态类层次中需要运行时检查的转换指针与引用在失败时的行为不同
const_cast<T>调整指针或引用的 const / volatile 限定修改原本定义为 const 的对象会产生未定义行为
reinterpret_cast<T>特定的底层指针等转换转换结果能否被访问仍受类型、对齐等规则限制

Microsoft C++ 转换符说明提供了各操作符完整规则的文档入口。

static_cast：把转换意图写清楚

一个常见例子是明确将浮点数转换为整数：

cpp
double value = 3.14;
int whole = static_cast<int>(value);  // whole 为 3

这里的小数部分被舍弃。数值转换的结果受具体类型规则和目标类型可表示范围约束。

在类层次中，派生类指针通常可以隐式转成可访问、无歧义的基类指针。用 static_cast 做反方向的下行转换时，调用方需要事先确认 Base* 指向的确实是相应的 Derived 对象。 这种转换不做运行时类型检查。

dynamic_cast：检查实际对象

需要运行时检查的下行转换，可以在多态类层次中使用 dynamic_cast。下面以带虚析构函数的基类为例：

cpp
struct Base {
    virtual ~Base() = default;
};

struct Derived : Base {
    int value = 42;
};

Derived object;
Base* base = &object;

if (auto* derived = dynamic_cast<Derived*>(base)) {
    // 检查通过后，才能按 Derived 访问对应成员。
    int result = derived->value;
    (void)result;
}

对指针做运行时检查时，失败结果是空指针；对引用做对应检查时，失败会抛出 std::bad_cast。具体可转换关系还涉及继承的访问性与歧义等条件。dynamic_cast 官方说明

const_cast：区分访问限定与对象属性

const_cast 调整访问路径上的类型限定。能否修改还取决于对象最初是否被定义为 const。

cpp
int mutable_value = 10;
const int* view = &mutable_value;
int* writable = const_cast<int*>(view);
*writable = 20;  // 原对象并不是 const

const int fixed_value = 10;
const int* fixed_view = &fixed_value;
// *const_cast<int*>(fixed_view) = 20; // 不要这样做：未定义行为

上例中，mutable_value 原本可修改，通过去掉访问路径上的 const 后写入是合法的；fixed_value 原本定义为 const，对它写入会产生未定义行为。const_cast 官方说明

reinterpret_cast：保留给有依据的底层操作

reinterpret_cast 用于语言规则允许的特定底层转换。转换后的访问还需要满足对象类型、对齐、生命周期等要求；跨平台代码还应核对内存布局、指针宽度和函数调用约定。

阅读底层代码时，分别核对“转换本身允许吗”和“转换后的使用允许吗”。例如，通过不兼容的函数指针类型调用函数会产生未定义行为，即使一次实验碰巧输出了预期结果。

使用前的三个问题

  1. 能否通过更明确的参数类型或接口设计避免转换？
  2. 如果需要转换，源对象的真实类型、生命周期与限定是否明确？
  3. 转换失败、精度变化或类型不匹配时，调用方如何处理？
