<h2 id="section-先看转换的目的">先看转换的目的</h2>
<p>隐式转换由编译器在符合语言规则时完成；显式转换由程序员写出来。C++ 的命名转换符区分了转换目的，使用时还要核对源对象与目标类型的条件。</p>

<h2 id="section-static_cast把转换意图写清楚">static_cast：把转换意图写清楚</h2>
<p>一个常见例子是明确将浮点数转换为整数：</p>
<div class="code-block"><div class="code-toolbar"><span>cpp</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-cpp"><span class="hljs-type">double</span> value = <span class="hljs-number">3.14</span>;
<span class="hljs-type">int</span> whole = <span class="hljs-keyword">static_cast</span>&#x3C;<span class="hljs-type">int</span>>(value);  <span class="hljs-comment">// whole 为 3</span>
</code></pre></div>
<p>这里的小数部分被舍弃。数值转换的结果受具体类型规则和目标类型可表示范围约束。</p>
<p>在类层次中，派生类指针通常可以隐式转成可访问、无歧义的基类指针。用 <code>static_cast</code> 做反方向的下行转换时，<strong>调用方需要事先确认 <code>Base*</code> 指向的确实是相应的 <code>Derived</code> 对象。</strong> 这种转换不做运行时类型检查。</p>
<h2 id="section-dynamic_cast检查实际对象">dynamic_cast：检查实际对象</h2>
<p>需要运行时检查的下行转换，可以在多态类层次中使用 <code>dynamic_cast</code>。下面以带虚析构函数的基类为例：</p>
<div class="code-block"><div class="code-toolbar"><span>cpp</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-cpp"><span class="hljs-keyword">struct</span> <span class="hljs-title class_">Base</span> {
    <span class="hljs-keyword">virtual</span> ~<span class="hljs-built_in">Base</span>() = <span class="hljs-keyword">default</span>;
};

<span class="hljs-keyword">struct</span> <span class="hljs-title class_">Derived</span> : Base {
    <span class="hljs-type">int</span> value = <span class="hljs-number">42</span>;
};

Derived object;
Base* base = &#x26;object;

<span class="hljs-keyword">if</span> (<span class="hljs-keyword">auto</span>* derived = <span class="hljs-keyword">dynamic_cast</span>&#x3C;Derived*>(base)) {
    <span class="hljs-comment">// 检查通过后，才能按 Derived 访问对应成员。</span>
    <span class="hljs-type">int</span> result = derived->value;
    (<span class="hljs-type">void</span>)result;
}
</code></pre></div>
<p>对指针做运行时检查时，失败结果是空指针；对引用做对应检查时，失败会抛出 <code>std::bad_cast</code>。具体可转换关系还涉及继承的访问性与歧义等条件。<a href="https://learn.microsoft.com/en-us/cpp/cpp/dynamic-cast-operator?view=msvc-170" rel="noopener noreferrer">dynamic_cast 官方说明</a></p>
<h2 id="section-const_cast区分访问限定与对象属性">const_cast：区分访问限定与对象属性</h2>
<p><code>const_cast</code> 调整访问路径上的类型限定。能否修改还取决于对象最初是否被定义为 const。</p>
<div class="code-block"><div class="code-toolbar"><span>cpp</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-cpp"><span class="hljs-type">int</span> mutable_value = <span class="hljs-number">10</span>;
<span class="hljs-type">const</span> <span class="hljs-type">int</span>* view = &#x26;mutable_value;
<span class="hljs-type">int</span>* writable = <span class="hljs-keyword">const_cast</span>&#x3C;<span class="hljs-type">int</span>*>(view);
*writable = <span class="hljs-number">20</span>;  <span class="hljs-comment">// 原对象并不是 const</span>

<span class="hljs-type">const</span> <span class="hljs-type">int</span> fixed_value = <span class="hljs-number">10</span>;
<span class="hljs-type">const</span> <span class="hljs-type">int</span>* fixed_view = &#x26;fixed_value;
<span class="hljs-comment">// *const_cast&#x3C;int*>(fixed_view) = 20; // 不要这样做：未定义行为</span>
</code></pre></div>
<p>上例中，<code>mutable_value</code> 原本可修改，通过去掉访问路径上的 const 后写入是合法的；<code>fixed_value</code> 原本定义为 const，对它写入会产生未定义行为。<a href="https://learn.microsoft.com/en-us/cpp/cpp/const-cast-operator?view=msvc-170" rel="noopener noreferrer">const_cast 官方说明</a></p>
<h2 id="section-reinterpret_cast保留给有依据的底层操作">reinterpret_cast：保留给有依据的底层操作</h2>
<p><code>reinterpret_cast</code> 用于语言规则允许的特定底层转换。转换后的访问还需要满足对象类型、对齐、生命周期等要求；跨平台代码还应核对内存布局、指针宽度和函数调用约定。</p>
<p>阅读底层代码时，分别核对“转换本身允许吗”和“转换后的使用允许吗”。例如，通过不兼容的函数指针类型调用函数会产生未定义行为，即使一次实验碰巧输出了预期结果。</p>
<h2 id="section-使用前的三个问题">使用前的三个问题</h2>
<ol>
<li>能否通过更明确的参数类型或接口设计避免转换？</li>
<li>如果需要转换，源对象的真实类型、生命周期与限定是否明确？</li>
<li>转换失败、精度变化或类型不匹配时，调用方如何处理？</li>
</ol>
