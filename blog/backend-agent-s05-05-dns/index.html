浏览器需要的地址由谁提供

打开https://notes.example.test时，URL中的主机名是notes.example.test。建立连接之前，客户端通常需要得到它的IP地址。DNS（Domain Name System，域名系统）负责查询域名对应的资源记录：A记录提供IPv4地址，AAAA提供IPv6地址，CNAME表示别名。DNS还承载其他记录，所以它的职责比“域名转IP”更广。

本文的域名和地址都用于教学，不要求实际解析成功。以A记录为例，客户端最后拿到192.0.2.10，只是获得了一个连接目标；端口来自URL或协议默认值，路径/posts属于后续HTTP请求，不交给DNS查询。

递归解析器替客户端完成查找并缓存结果，通常由网络配置或浏览器设置指定；权威服务器负责给自己管理的域提供答案。两者的区别在于职责，不能简单理解为某一台机器永久只能做其中一种工作。DNS基本结构

没有缓存时，查询怎样逐级推进

先简化为解析器没有可复用记录，域名也没有别名跳转：

步骤请求对象需要得到的信息
客户端请求递归解析器请给出目标名称的A记录或明确错误
查根区域根服务器哪些服务器负责下一层区域
查下级区域对应区域服务器目标名称所在区域由谁负责
查目标区域权威服务器目标A记录，或该名称/类型不存在
返回递归解析器到客户端答案、剩余TTL或错误信息

这是递归解析器代为迭代查询的过程。客户端请求它完成查找，不意味着根服务器会替客户端跑完全部后续请求。现实中，解析器往往已缓存区域委派信息，因此一次查询不必每次从根重新开始。

遇到CNAME时，要继续解析别名指向的名称；别名链上的各条记录有自己的TTL。区域边界也不总与域名每一个点一一对应，应根据实际委派前进。委派回答中可能携带glue地址记录，帮助找到被委派服务器，不能把所有附带地址都当成目标域名的最终答案。RFC1034查询与委派

TTL怎样决定旧地址还能被使用多久

TTL（Time to Live，存活时间）表示一条记录允许被缓存的时长。假设权威A记录的TTL为300秒，递归解析器在12:00拿到旧地址：

  • 12:02再次查询时，解析器可以返回旧地址，剩余TTL约180秒。
  • 权威服务器在12:02改成新地址，不会自动通知所有既有缓存立即清除。
  • 在不考虑特殊过期服务策略的模型中，这份缓存到12:05到期，后续查询才重新取得新记录。

这里最容易漏掉的是TTL从缓存取得记录时开始消耗。如果先把权威TTL从300降到30，再立即切地址，已经缓存的300秒记录仍可能有效。迁移通常要先降低TTL，等旧TTL窗口过去，再切换并保留旧端服务一段过渡时间。

客户端可能还有浏览器、操作系统或应用自己的缓存；连接池也可能继续使用已经建立的连接。因而“DNS查到新IP”和“所有请求已到新服务器”是两个观察点。检查切换时要同时看解析答案、实际连接地址与旧服务流量，不能只截一条成功查询就结束。

名称不存在的回答也会缓存

NXDOMAIN表示查询的名称不存在；NODATA表示名称存在，但没有所查询类型的记录。比如一个域名只有A记录，查询AAAA没有结果，不等于域名本身不存在。

负缓存避免每个失败查询都访问权威服务器。RFC2308规定相应否定答案的缓存期限与SOA记录有关，基本取SOA自身TTL和SOA.MINIMUM中的较小值。假设两者是600和60秒，这份否定答案按60秒缓存。刚创建一个先前不存在的名称后，旧负缓存仍可能让部分用户暂时查不到它。负缓存与期限

因此，排查“已经加了记录却打不开”时，需要区分旧正缓存、负缓存、记录类型不匹配与解析器故障。SERVFAIL表示解析失败，不能直接解释成域名不存在。

怎样做一次有证据的DNS排查

先保留查询时间、名称、类型、所用解析器、答案和TTL。Windows可用Resolve-DnsName或nslookup查询；Linux环境常用dig。命令是否可用取决于本机工具，本篇没有以教学域名发起真实查询。

对比同一递归解析器连续两次返回的TTL，可以判断是否看见同一份缓存；再与权威答案比较，识别“源数据已更新，缓存仍有效”的情况。多个网络返回不同结果，还可能来自分地域解析策略，并不能直接归因于缓存污染。

如果DNS结果正常但连接失败，下一步检查端口、路由、TLS身份和服务状态，接着读TLS验证。DNSSEC用于验证DNS数据的来源与完整性，DoH/DoT保护到解析器的传输，两者解决的问题不同，也都不能代替HTTPS服务器身份验证。

面试问答：DNS查询流程

DNS 流程。

回答： 客户端根据自己的解析配置查询递归解析器。命中有效缓存时直接返回；未命中时，解析器沿区域委派查询相应服务器，最终获得权威记录或否定回答，再按TTL缓存并返回。目标可能经过CNAME链，查询类型也可能是A、AAAA等，过程不保证每次都从根开始。

例如旧A记录在12:00被缓存300秒，12:02权威地址变更，递归解析器仍可能在12:05之前返回旧地址。记录变更不会推送清除所有缓存；已建立连接又有自己的生命周期。名称不存在的负缓存也可能使新加的记录暂时不可见。

延伸追问（自拟）：把TTL改成0能不能保证所有请求立即切换？ TTL控制缓存复用，但无法撤销已有缓存或已建立连接，也要考虑客户端行为、重试与权威服务容量。需要结合提前降TTL、连接切换和旧端过渡，而不是把一个字段当作即时全局开关。

原问与出处见逐题映射。本篇查询时序为教学推演，未声称观测了用户站点的DNS。
