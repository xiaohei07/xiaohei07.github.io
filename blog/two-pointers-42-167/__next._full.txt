1c:T7bfc,<h2 id="section-接雨水题意与逐列水量计算">接雨水：题意与逐列水量计算</h2>
<section class="problem"><div class="problem-heading"><strong>42. 接雨水</strong><a href="https://leetcode.cn/problems/trapping-rain-water/" rel="noopener noreferrer">力扣原题 ↗</a></div><p><strong>题目要求</strong></p><p>输入高度数组height，其中每个非负整数代表一根柱子的高度，各柱宽度均为1，柱子按数组顺序排列。</p><p>计算下雨后这些柱子之间总共能存住多少单位的水。水会从缺少足够高挡板的一侧流走，最后返回各个位置积水量的总和。</p><div class="examples"><p><strong>示例1</strong></p><p>输入：<code>height = [0,1,0,2,1,0,1,3,2,1,2,1]</code></p><p>输出：<code>6</code></p><p>从左到右各列积水为[0,0,1,0,1,2,1,0,0,1,0,0]，相加得到6。</p></div><div class="examples"><p><strong>示例2</strong></p><p>输入：<code>height = [4,2,0,3,2,5]</code></p><p>输出：<code>9</code></p><p>各列积水为[0,2,4,1,2,0]，相加得到9。下文的柱状图会展示这一组输入。</p></div><p><strong>约束条件</strong></p><ul><li>n = height.length</li><li>1 ≤ n ≤ 2 × 10⁴</li><li>0 ≤ height[i] ≤ 10⁵</li></ul></section>
<p>前面做过的<a href="/blog/longest-substring-without-repeating-characters/">无重复字符的最长子串</a>，以及<a href="/blog/sliding-window-209-438/">长度最小的子数组、找到字符串中所有字母异位词</a>，都是让左右边界向右移动来维护窗口。连续按这个方向做题后，遇到接雨水，我也先沿着从左往右处理的思路考虑：先记住左边最高的柱子，再向右寻找能够挡水的柱子，找到后把中间的水算出来。这条思路可以得到正确解法，但分段范围和继续搜索的位置都需要处理清楚。</p>
<p>要判断找墙的逻辑是否正确，可以先把问题缩小到其中一列。假设当前位置的高度为0，左边最高的柱子为4，右边最高的柱子为5。水位可以升到4；如果继续升高，水就会越过左边的墙流走，所以右边再高也无法让这一列存到5。</p>
<p>这里找的是一侧范围内的最高柱，不一定是紧邻的柱子。比如高度<code>[4,2,0,3,5]</code>中，0旁边虽然只是2和3，两侧更远处的4和5仍然能够挡住水，中间较矮的柱子只是被水覆盖了一部分。<strong>某一列能存多少水，要看两侧各自最高的墙，再由其中较低的一侧决定水位。</strong></p>
<p>设<code>L[i]</code>是从开头到i的最高柱，<code>R[i]</code>是从i到末尾的最高柱，<strong>两个范围都包含当前柱子本身</strong>。水位减去已经由柱子占据的高度，就是这一列的积水量：</p>
<span class="katex"><math xmlns="http://www.w3.org/1998/Math/MathML" display="block"><semantics><mrow><mi>w</mi><mi>a</mi><mi>t</mi><mi>e</mi><mi>r</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo>=</mo><mi>min</mi><mo>⁡</mo><mo stretchy="false">(</mo><mi>L</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo separator="true">,</mo><mi>R</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo stretchy="false">)</mo><mo>−</mo><mi>h</mi><mi>e</mi><mi>i</mi><mi>g</mi><mi>h</mi><mi>t</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo></mrow><annotation encoding="application/x-tex">water[i]=\min(L[i],R[i])-height[i]</annotation></semantics></math></span>
<p>因为L、R都不低于当前柱，差值不会小于0。柱宽为1，总水量就是各列水量之和。端点也适用这个定义：其中一侧最高只有它自己，所以无法存水。</p>
<figure class="explain-figure"><figcaption>每一列的积水＝受两侧限制的水位−当前柱高</figcaption><div class="chart-scroll" tabindex="0" aria-label="柱高和已结算水量"><img src="/media/algorithm-window-prefix/water.svg" alt="各列柱高与水量，数值表见图下方" width="440" height="230" loading="lazy" decoding="async" referrerpolicy="no-referrer"></div><div class="table-scroll" tabindex="0"><table><thead><tr><th scope="col">下标</th><th scope="col">0</th><th scope="col">1</th><th scope="col">2</th><th scope="col">3</th><th scope="col">4</th><th scope="col">5</th></tr></thead><tbody><tr><td>柱高</td><td>4</td><td>2</td><td>0</td><td>3</td><td>2</td><td>5</td></tr><tr><td>积水</td><td>0</td><td>2</td><td>4</td><td>1</td><td>2</td><td>0</td></tr></tbody></table></div><p>下方数字为数组下标；绿色为柱子，蓝色为水。逐列积水0＋2＋4＋1＋2＋0＝9。</p></figure>
<h2 id="section-第一次尝试右侧最后一个更高的柱子未必是最高柱">第一次尝试：右侧最后一个更高的柱子，未必是最高柱</h2>
<p>第一版在右边发现比当前柱高的柱子，就直接覆盖<code>right_max</code>。用<code>[5,0,4,1]</code>看这个问题最清楚：处理高度0时，先找到4，后面又找到1，最后保留下来的是1。</p>
<details class="extra">
<summary>展开第一次寻找右墙的错误逻辑</summary>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">rain_bug_last_taller</span>(<span class="hljs-params">height: <span class="hljs-built_in">list</span>[<span class="hljs-built_in">int</span>]</span>) -> <span class="hljs-built_in">int</span>:
    total = left_max = <span class="hljs-number">0</span>

        <span class="hljs-keyword">if</span> left_max &#x3C;= height[i]:
            left_max = height[i]
            <span class="hljs-keyword">continue</span>
        j, right_max = i + <span class="hljs-number">1</span>, <span class="hljs-number">0</span>
        <span class="hljs-keyword">while</span> j &#x3C; <span class="hljs-built_in">len</span>(height):
            <span class="hljs-keyword">if</span> height[j] > height[i]:
                right_max = height[j]  <span class="hljs-comment"># 错误：后面更矮但仍高于当前的柱会覆盖。</span>
            j += <span class="hljs-number">1</span>
        <span class="hljs-keyword">if</span> right_max > height[i]:
            total += <span class="hljs-built_in">min</span>(left_max, right_max) - height[i]
    <span class="hljs-keyword">return</span> total

<p><strong>高度1虽然高于当前柱，却低于已经找到的4，不能覆盖右侧最高值。</strong>因此这段逻辑只算出1单位水，正确结果是4。修正时需要持续取最大值：<code>right_max=max(right_max,height[j])</code>。</p>
<p>这次错误对应着两个不同的问题：“新柱子能不能挡住一点水”和“新柱子是否改变已经知道的最高挡板”。高度1对当前的0来说确实更高，但已经找到的4仍然存在，水位不会因为后面又出现一根矮柱而降低。<strong>每扫描一个新位置，都应该把它与已知最高值比较，保留两者较大者。</strong>这样right_max才始终表示已扫描范围的最高柱。</p>
<p>代码为便于运行整理成了独立函数，错误版保留对应的算法分支；下面的逐柱版本是按这个修正补充的对照实现。</p>
<details class="extra">
<summary>展开修正后的逐柱扫描基准</summary>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">rain_column_scan</span>(<span class="hljs-params">height: <span class="hljs-built_in">list</span>[<span class="hljs-built_in">int</span>]</span>) -> <span class="hljs-built_in">int</span>:
    total = left_max = <span class="hljs-number">0</span>
    <span class="hljs-keyword">for</span> i, value <span class="hljs-keyword">in</span> <span class="hljs-built_in">enumerate</span>(height):
        left_max = <span class="hljs-built_in">max</span>(left_max, value)
        right_max = value
        <span class="hljs-keyword">for</span> j <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(i + <span class="hljs-number">1</span>, <span class="hljs-built_in">len</span>(height)):
            right_max = <span class="hljs-built_in">max</span>(right_max, height[j])  <span class="hljs-comment"># 真正维护最大值。</span>
        total += <span class="hljs-built_in">min</span>(left_max, right_max) - value
    <span class="hljs-keyword">return</span> total

<p>左边最高值可以随遍历更新，右边最高值仍然每次重新扫描。扫描次数最多接近<code>(n-1)+(n-2)+…+1</code>，所以<strong>逐柱扫描的最坏时间为O(n²)，额外空间为O(1)</strong>。</p>
<h2 id="section-分段结算的第一次修改记住右墙的真实位置">分段结算的第一次修改：记住右墙的真实位置</h2>
<p>逐列计算的问题比较明显：相邻两列往右寻找时，会反复经过同一批柱子。我当时想，既然已经找到了右墙，能不能把两道墙之间的水一次算完，然后直接跳到右墙后面？这样已经结算的区域就不用再逐列重复寻找。</p>
<p>于是开始尝试分段结算。不过，一次向右搜索同时产生了两个位置：一个是扫描最后停下来的位置，另一个是已经找到的最高右墙的位置。起初直接沿用了扫描终点，后面的修改才把右墙位置单独保存下来。</p>
<p>例如<code>[5,0,4,0,3]</code>，从第一个低点向右扫描，没有找到高度达到左墙5的柱子，于是一直扫到末尾。扫描结束位置为<code>j=5</code>，实际找到的最高右墙却在下标2，高度为4。</p>
<details class="extra">
<summary>展开把扫描终点当作结算终点的版本</summary>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">rain_bug_range</span>(<span class="hljs-params">height: <span class="hljs-built_in">list</span>[<span class="hljs-built_in">int</span>]</span>) -> <span class="hljs-built_in">int</span>:

<p>如果把下标1到末尾都按水位4计算，得到<code>4+0+4+1=9</code>，就把右墙后面的区域也灌到了4。实际上，后面的低点只有高度3的右墙，那里只能接3单位水，<strong>总量应当是4+3=7</strong>。</p>
<figure class="explain-figure"><figcaption>扫描到末尾后，结算终点仍是实际右墙</figcaption><div class="chart-scroll" tabindex="0" aria-label="柱高和已结算水量"><img src="/media/algorithm-window-prefix/rain-range.svg" alt="各列柱高与水量，数值表见图下方" width="370" height="230" loading="lazy" decoding="async" referrerpolicy="no-referrer"></div><div class="table-scroll" tabindex="0"><table><thead><tr><th scope="col">下标</th><th scope="col">0</th><th scope="col">1</th><th scope="col">2</th><th scope="col">3</th><th scope="col">4</th></tr></thead><tbody><tr><td>柱高</td><td>5</td><td>0</td><td>4</td><td>0</td><td>3</td></tr><tr><td>积水</td><td>0</td><td>4</td><td>0</td><td>3</td><td>0</td></tr></tbody></table></div><p><b>下标1：左最高5、右最高4，水量4。</b>下标3的右最高只有3，水量3。下标2的墙把两段水位区分开，总量7。</p></figure>
<p>因此需要另存一个<code>wall</code>，记录最高右墙的实际下标，<strong>只结算当前起点到这道墙之前的区域</strong>。扫描可以越过它去寻找更高的墙，结算范围却不能跟着扫描终点一起扩大。</p>
<p>按修正后的范围走一次：先以高度5为左侧限制，找到下标2的高度4作为右墙，只给下标1结算4单位水；接着继续处理下标3，它右边最高只有3，于是再结算3单位。两段相加为7。虽然第一次搜索为了确认右墙已经读过后面所有柱子，后半段仍然有自己的水位限制，不能把“搜索过”当成“已经结算过”。</p>
<h2 id="section-分段结算的第二次修改当前无水也要继续检查后面">分段结算的第二次修改：当前无水，也要继续检查后面</h2>
<p>补上右墙位置后，还有提前返回的问题。</p>
<p>在<code>[5,3,2,1,2]</code>中，处理高度3时，右边没有更高的墙，这一列确实没有水。但后面的高度1夹在两个高度2之间，仍然能接1单位水。<strong>当前列没有积水，只能跳过当前列，不能结束整个函数。</strong></p>
<p>另一种情况是<code>[5,1,3,1,2]</code>：先用左墙5和右墙3算出第一个低点的2单位水，右墙后的低点还可以接1单位。如果结算第一段后直接返回，结果就会从3漏成2。</p>
<details class="extra">
<summary>展开记录右墙后仍然提前返回的版本</summary>

                left_max = right_max
        <span class="hljs-keyword">else</span>:
            <span class="hljs-keyword">return</span> total  <span class="hljs-comment"># 错误：右墙后的更低盆地仍可能存水。</span>
    <span class="hljs-keyword">return</span> total
</code></pre></div>
</details>
<p>这部分当时已经把我卡住了。原本想通过一次算完一段减少重复工作，实际却需要同时考虑右墙在哪里、当前段是否结束、后面是否还有低处能积水。修好一段的结算范围，并没有同时解决后续遍历的问题。经过AI解释后，最后采用的分段写法保留了原来的结构：当前列没有水就继续；找到一段可以结算的区域，就算到真实右墙，再处理墙后面的部分。</p>
<details class="extra">
<summary>展开修正后的完整分段解法</summary>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">rain_segment_fixed</span>(<span class="hljs-params">height: <span class="hljs-built_in">list</span>[<span class="hljs-built_in">int</span>]</span>) -> <span class="hljs-built_in">int</span>:
    total = i = left_max = <span class="hljs-number">0</span>
    <span class="hljs-keyword">while</span> i &#x3C; <span class="hljs-built_in">len</span>(height):
        <span class="hljs-keyword">if</span> left_max &#x3C;= height[i]:
            left_max = height[i]
            i += <span class="hljs-number">1</span>
            <span class="hljs-keyword">continue</span>
        j, right_max, wall, flag = i + <span class="hljs-number">1</span>, height[i], i, <span class="hljs-number">0</span>
        <span class="hljs-keyword">while</span> j &#x3C; <span class="hljs-built_in">len</span>(height):
            <span class="hljs-keyword">if</span> height[j] >= right_max:
                right_max, wall, flag = height[j], j, <span class="hljs-number">1</span>
                <span class="hljs-keyword">if</span> right_max >= left_max:
                    flag = <span class="hljs-number">2</span>  <span class="hljs-comment"># 找到足够高的墙；左最高已经决定这段水位。</span>
                    <span class="hljs-keyword">break</span>
            j += <span class="hljs-number">1</span>

            i += <span class="hljs-number">1</span>  <span class="hljs-comment"># 当前位置没水，仍须继续检查后面。</span>
            <span class="hljs-keyword">continue</span>
        <span class="hljs-keyword">for</span> k <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(i, wall):
            <span class="hljs-comment"># 若未找到足够高的墙，wall就是所扫描后缀的最高墙。</span>
            total += <span class="hljs-built_in">min</span>(left_max, right_max) - height[k]
        <span class="hljs-keyword">if</span> flag == <span class="hljs-number">2</span>:
            left_max = right_max
        i = wall + <span class="hljs-number">1</span>  <span class="hljs-comment"># 右墙本身不计水；之后仍可能有低盆地。</span>

<p>扫描时有两种停止结果：如果找到不低于<code>left_max</code>的墙，这段的水位已经受左墙限制，可以提前停止；如果一直没有找到，就用整个剩余范围的最高墙作为右墙。</p>
<p>这两种情况为什么可以这样处理，也能回到逐列公式来看。找到不低于左最高的右墙时，两边较小值已经确定为左最高，再向后寻找更高墙不会改变当前段的水位。反过来，如果整段后缀都没有墙达到左最高，决定水位的就是后缀最高墙本身，而它的位置决定了这一段能够结算到哪里。<strong>结束搜索的条件、用于计算的高度、可以跳过的区间，需要分别对应清楚。</strong></p>
<p>等高柱也可以围住低点，例如<code>[2,0,2]</code>。不过，<strong>是否需要改成<code>>=</code>要结合后续移动逻辑看</strong>，不能仅改一个比较符号就认为所有提前退出和范围问题都解决了。</p>
<h3 id="section-正确分段法的瓶颈还在重复扫描后缀">正确分段法的瓶颈：还在重复扫描后缀</h3>
<p>分段后跳过了部分位置，并不代表总扫描次数一定降到了线性。</p>
<p>考虑递减高度<code>[5,4,3,2,1]</code>。左最高一直为5，处理4时扫描右边的3、2、1；处理3时又扫描2、1；处理2时再扫描1。每次都没有水可以结算，但右侧搜索被反复执行。</p>
<p>推广到长度n，后缀检查次数形成等差和，因此<strong>修正分段法最坏仍为O(n²)时间、O(1)额外空间</strong>。已结算区间的求和不重复覆盖，累计至多O(n)，真正的瓶颈在寻找右墙。</p>
<p>递增数组可以很快跳过，所以分段法的实际工作量会随输入改变。这里没有同环境计时，不能根据复杂度直接写成“快几倍”。</p>
<h2 id="section-用左右最大值数组复用扫描结果">用左右最大值数组复用扫描结果</h2>
<p>避免重复搜索的一种直接办法，是把每个位置两侧最高值先算好。</p>
<p>以右侧最高值为例，若已经知道下标i+1到末尾的最高值，计算下标i到末尾就只多出了height[i]这一根柱子。因此，把它与已经保存的结果取较大值即可，不需要再看一遍后面的所有柱子。这也决定了右表要从右往左计算：先得到较短后缀的结果，才能复用它计算前一个位置。</p>
<span class="katex"><math xmlns="http://www.w3.org/1998/Math/MathML" display="block"><semantics><mrow><mi>L</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo>=</mo><mi>max</mi><mo>⁡</mo><mo stretchy="false">(</mo><mi>L</mi><mo stretchy="false">[</mo><mi>i</mi><mo>−</mo><mn>1</mn><mo stretchy="false">]</mo><mo separator="true">,</mo><mi>h</mi><mi>e</mi><mi>i</mi><mi>g</mi><mi>h</mi><mi>t</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo stretchy="false">)</mo><mo separator="true">,</mo><mspace width="2em"></mspace><mi>R</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo>=</mo><mi>max</mi><mo>⁡</mo><mo stretchy="false">(</mo><mi>R</mi><mo stretchy="false">[</mo><mi>i</mi><mo>+</mo><mn>1</mn><mo stretchy="false">]</mo><mo separator="true">,</mo><mi>h</mi><mi>e</mi><mi>i</mi><mi>g</mi><mi>h</mi><mi>t</mi><mo stretchy="false">[</mo><mi>i</mi><mo stretchy="false">]</mo><mo stretchy="false">)</mo></mrow><annotation encoding="application/x-tex">L[i]=\max(L[i-1],height[i]),\qquad
R[i]=\max(R[i+1],height[i])</annotation></semantics></math></span>
<p>左表从左向右构造，右表从右向左构造，最后套用逐列水量公式。<strong>每次都复用前一个位置的结果，不再从当前位置重新扫描整个后缀。</strong></p>
<p>对<code>[4,2,0,3,2,5]</code>，这三组状态是：</p>


















































<table><thead><tr><th>下标i</th><th>0</th><th>1</th><th>2</th><th>3</th><th>4</th><th>5</th></tr></thead><tbody><tr><td>当前柱高</td><td>4</td><td>2</td><td>0</td><td>3</td><td>2</td><td>5</td></tr><tr><td>左侧最高L[i]</td><td>4</td><td>4</td><td>4</td><td>4</td><td>4</td><td>5</td></tr><tr><td>右侧最高R[i]</td><td>5</td><td>5</td><td>5</td><td>5</td><td>5</td><td>5</td></tr><tr><td>min(L[i],R[i])−height[i]</td><td>0</td><td>2</td><td>4</td><td>1</td><td>2</td><td>0</td></tr></tbody></table>
<p>原来每处理一列，都要临时寻找的两个数，现在可以直接从表中读取。优化的关键在于<strong>相邻位置的最高值可以递推复用</strong>，所以这一版已经把寻找右墙的重复工作消除了。</p>
<details class="extra">
<summary>展开左右最大值预处理代码</summary>

<p>两次预处理加一次求和，总时间为O(n)，两张表占O(n)额外空间。这里存的是<strong>前缀最大值和后缀最大值</strong>，不是前缀和。</p>
<p>接着可以继续问：算当前这一列时，另一侧最高墙的准确高度是否一定要知道？如果已经发现的墙足够高，剩下更高的墙还会改变结果吗？</p>
<h2 id="section-相向双指针只结算水位已经确定的一侧">相向双指针：只结算水位已经确定的一侧</h2>
<p>让<code>left</code>从开头、<code>right</code>从末尾向中间移动，它们之间是尚未结算的区域。每轮先更新：</p>
<ul>
<li><code>left_max</code>：从开头到left已经见到的最高柱。</li>
<li><code>right_max</code>：从right到末尾已经见到的最高柱。</li>
</ul>
<p>当<code>left_max&#x3C;=right_max</code>时，右边已经有一道至少为<code>right_max</code>的墙，它不低于左最高。即使中间还有更高的右墙，也不会改变两侧取较小值的结果。因此<strong>left这一列的水位已确定为left_max，可以准确结算并右移left</strong>。</p>
<p>当<code>left_max>right_max</code>时，对称地结算right这一列，再左移right。这里比较的是两侧累计最大值，代码与证明使用同一个判断条件。</p>
<p>可以用一个具体状态理解“右边足够高”是什么意思。假设left列高2，左边最高已经确定为4，而右端已经发现高度5的墙。此时中间尚未处理的区域可能有6、8，也可能都很低，但无论哪种情况，left列的真实右最高都至少为5。两侧取较小值时，结果必然是4，因此这列的水量一定为<code>4−2=2</code>。<strong>未知的右侧最高值可以更大，却不再影响当前这一列的答案。</strong></p>
<p>如果反过来，左最高是5，右最高只有3，情况就不同了：此时还不能用3限制left列，因为中间可能有一根更高的右墙。不过right列的右侧最高已经完整知道为3，左侧又已经有5作保障，因此可以先处理right列。这说明选择哪一侧移动，并不是固定先左后右，而是选择目前已经有足够信息确定水量的一侧。</p>
<p>每次只结算端点这一列，并没有把未处理的中间一整段直接算完。端点移入下一列后再更新累计最高值，重复同样的判断。这样既保留了逐列计算的清晰含义，也不再需要为每一列保存完整的左右最大值表。</p>

<h3 id="section-时间空间以及容易遗漏的边界">时间、空间以及容易遗漏的边界</h3>
<p>每轮left加1或right减1，区间长度减少1，至多执行n轮；更新最大值和水量都是常量操作。所以<strong>相向双指针为O(n)时间、O(1)额外空间</strong>。它与最大值预处理版同为线性时间，进一步节省的是两张表。</p>

<h2 id="section-两数之和ii有序输入下的相向指针">两数之和II：有序输入下的相向指针</h2>
<section class="problem"><div class="problem-heading"><strong>167. 两数之和II—输入有序数组</strong><a href="https://leetcode.cn/problems/two-sum-ii-input-array-is-sorted/" rel="noopener noreferrer">力扣原题 ↗</a></div><p><strong>题目要求</strong></p><p>输入已经按非递减顺序排列的整数数组numbers和目标值target。选择其中两个不同位置，使对应数值之和等于target。</p><p>结果为[index1,index2]，这里使用从1开始的题目下标，并满足1 ≤ index1 &#x3C; index2 ≤ numbers.length。每个输入保证只有一组答案，同一位置不能使用两次。算法只允许使用O(1)额外空间。</p><div class="examples"><p><strong>示例1</strong></p><p>输入：<code>numbers = [2,7,11,15], target = 9</code></p><p>输出：<code>[1,2]</code></p><p>第1个数2与第2个数7相加为9。</p></div><div class="examples"><p><strong>示例2</strong></p><p>输入：<code>numbers = [2,3,4], target = 6</code></p><p>输出：<code>[1,3]</code></p><p>第1个数2与第3个数4相加为6。</p></div><div class="examples"><p><strong>示例3</strong></p><p>输入：<code>numbers = [-1,0], target = -1</code></p><p>输出：<code>[1,2]</code></p><p>两个不同位置上的-1与0组成唯一答案。</p></div><p><strong>约束条件</strong></p><ul><li>2 ≤ numbers.length ≤ 3 × 10⁴</li><li>−1000 ≤ numbers[i] ≤ 1000</li><li>−1000 ≤ target ≤ 1000</li><li>numbers已按非递减顺序排列；保证恰好一组有效答案。</li></ul></section>
<p>这个题作为相向双指针的补充例子。与前面的<a href="/blog/two-sum/">两数之和</a>相比，关键新增条件是<strong>数组已经按非递减顺序排列，并且要求常量额外空间</strong>。</p>
<p>如果沿用普通两数之和的思路，哈希表仍然可以查询补数，但需要保存此前出现的数，不符合这里的常量额外空间要求。已经有序的条件提供了另一种判断依据：固定一个数后，搭档向右移动只会让总和不减，向左移动只会让总和不增。于是可以尝试从两个端点开始，每次排除一个不可能再参与答案的位置。</p>
<p>取剩余范围的最左端和最右端。如果两数和偏小，那么对当前left而言，即使用最大的right作搭档也不够，更靠左的搭档只会更小。因此可以排除当前left的所有组合，直接把left右移。</p>
<p>如果两数和偏大，对当前right而言，即使用最小的left作搭档也太大，更靠右的搭档只会更大。因此排除right，再左移right。</p>
<p>这里排除的是一个端点与当前范围内其他所有元素的组合，所以一次比较才能省去一整批候选。如果输入没有排序，仅凭当前和偏大就删除右端并不成立。例如<code>[3,1,2]、target=3</code>中，两端之和为5，但右端的2其实可以与中间的1组成答案。<strong>有序条件保证当前两端确实是剩余范围的最小值和最大值，排除证明才成立。</strong></p>
