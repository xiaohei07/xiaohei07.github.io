1d:T4aa2,<span id="一动态联编" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-一动态联编">（一）动态联编：</h3>
<span id="1-概念" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-1-概念">1. 概念：</h4>
<p>动态联编是根据调用时对象的实际类型，选择相应的虚函数实现，也称晚期联编。这里讲的是语言规定的调用行为；编译器如果能够确定目标，也可能把调用优化为直接调用。</p>
<p>通过指针或引用调用虚函数时，可以体现这种动态选择。显式写出类名的限定调用（如 <code>p->Base::fun()</code>）会抑制虚调用。</p>
<span id="2-使用" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-2-使用">2. 使用：</h4>
<p>可以通过基类指针或引用调用虚函数，调用目标由对象的实际类型决定。派生类可以重写虚函数，也可以直接继承基类已有的实现；没有重写时，会使用继承的版本。这里的基类转换还要满足可访问、无歧义等条件。</p>
<span id="3-优点" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-3-优点">3. 优点：</h4>
<p>调用方可以使用统一的基类接口处理不同派生类对象。虚调用可能增加间接调用等开销，具体影响还取决于实现和编译器优化。</p>
<span id="二虚函数" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-二虚函数">（二）虚函数：</h3>
<h4 id="section-1-概念-1">1. 概念：</h4>
<p><strong>虚函数</strong>是在类中使用 <code>virtual</code> 声明的非静态成员函数。派生类对它进行重写后，通过基类接口调用时可以执行派生类版本。</p>
<p><code>virtual</code> 写在类内的成员声明中；在类外给出函数定义时不再重复写。</p>
<p>派生类中符合重写条件的函数仍然是虚函数，即使省略 <code>virtual</code>。仅仅函数名相同还不够，参数列表、成员函数的 cv 限定和引用限定等也必须符合重写规则。C++11 起可以使用 <code>override</code> 让编译器检查。</p>
<p>普通虚函数不要求每一层派生类都重写，继承的实现可以继续使用。</p>
<ul>
<li>
<p>虚函数重写：派生类声明与基类虚函数对应的成员函数。函数名、参数列表及成员函数的限定条件需要匹配；返回类型通常相同，也可以满足协变返回类型的规则。析构函数的重写由析构函数自身的规则确定。</p>
<p>协变返回类型：重写函数可以返回更具体的类类型指针或引用。例如基类函数返回 <code>Person*</code>，派生类函数返回 <code>Student*</code>，且 <code>Student</code> 公开、无歧义地派生自 <code>Person</code>。这仍然是重写；返回类型还须满足对应的指针/引用类别及 cv 限定要求。</p>
<p>重写的访问限定符可以不同。</p>
<p>除合法的协变返回类型外，不能只改变返回类型来重写基类虚函数。</p>
<p>只有函数名相同、参数列表等不匹配时，派生类声明可能隐藏基类的同名函数，但不会取消基类函数原有的虚特性。</p>
</li>
<li>
<p>隐藏：不局限于虚函数，但需要和虚函数概念结合理解。</p>
<p>隐藏是指派生类的函数屏蔽了与其同名的基类函数。</p>
<p>如果派生类的函数与基类的函数同名，但是参数不同。此时，不论是否为虚函数，基类的函数将被隐藏（注意不是重载，重载是在同一个类中发生）。</p>
<p>如果派生类的函数与基类的函数同名，并且参数也相同，但是基类函数没有virtual 关键字。此时，基类的函数被隐藏（注意不是重写，重写有virtual关键字）。</p>
</li>
</ul>
<p>——在参数及其他限定条件可比较的简单情形下，可以这样区分；下面的 <code>virtual</code> 指基类函数是否为虚函数：</p>
<ol>
<li>签名匹配、基类函数为虚函数：重写；</li>
<li>签名匹配、基类函数非虚：隐藏；</li>
<li>参数不同、基类函数为虚函数：隐藏，不构成重写；</li>
<li>参数不同、基类函数非虚：隐藏。</li>
</ol>
<span id="2-限制" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-2-限制">2. 限制：</h4>
<ul>
<li>
<p>虚函数必须是非静态成员函数。友元非成员函数、全局函数不能声明为虚函数；一个类即使暂时没有派生类，也可以声明虚函数。</p>
</li>
<li>
<p>静态成员函数不能是虚函数，因为静态成员函数不受限于某个对象。</p>
</li>
<li>
<p>虚函数可以声明为 <code>inline</code>。是否把某一次调用实际展开，由编译器决定，不能单凭 <code>inline</code>、对象调用或指针调用就断言一定内联或一定不内联。</p>
</li>
<li>
<p>构造函数不能是虚函数：</p>
<p>C++ 不允许把构造函数声明为虚函数。创建对象时选择构造函数，随后按规则构造基类和成员子对象；构造期间的虚函数调用还有下述限制。</p>
</li>
<li>
<p>析构函数可以是虚函数。需要通过基类指针删除派生类对象时，本文这种普通 <code>delete</code> 用法要求基类有虚析构函数。</p>
<p>基类析构函数是虚函数时，派生类析构函数也保持虚特性，无须重复写 <code>virtual</code>。通过基类指针删除派生对象，会先执行派生类析构函数，再依次析构其成员和基类。</p>
<p>构造或析构期间，如果对正在构造或析构的对象调用虚函数，调用的是当前构造函数或析构函数所属类中的最终重写版本，不会分派到更下层的派生类。这个规则不能解释成“虚析构函数仍是静态联编”。</p>
</li>
<li>
<p>不建议把赋值运算符重载作为虚函数。</p>
</li>
</ul>
<span id="3-工作原理" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-3-工作原理">3. 工作原理：</h4>
<p>常见实现使用虚函数表（vtable）和虚表指针（vptr）完成虚调用：对象保存相关表指针，表中记录该类型的虚函数入口，调用时据此选择实现。派生类重写函数后，对应入口使用重写版本；未重写时可以继续使用继承的实现。</p>
<p>这是实现层面的理解方式。具体有几个表指针、放在对象的什么位置、表中还有哪些信息，由 ABI（应用二进制接口）及继承结构决定。例如 <a href="https://itanium-cxx-abi.github.io/cxx-abi/abi.html#vtable" rel="noopener noreferrer">Itanium C++ ABI 的虚表布局</a> 就有具体规则。不能把“总在第一个数据成员之前”“每个对象固定多出 8 字节”推广为 C++ 规则。</p>
<p>虚表、对象中的相关指针以及间接调用可能带来存储和执行开销。对象大小还包含对齐填充，调用也可能被优化；下面用 <code>sizeof</code> 观察当前环境的结果。</p>
<span id="4-c11-override-ampamp-final" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-4-c11-override--final">4. C++11 override &#x26;&#x26; final</h4>
<p>C++11新增了两个关键字override和final。</p>
<p>被override修饰的虚函数，编译器会检查这个虚函数是否重写。如果没有重写，编译器会报错。</p>
<p>用final修饰的虚函数无法重写。用final修饰的类无法被继承。final像这个单词的意思一样，这就是最终的版本，不用再更新了。</p>
<span id="5-表现" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-5-表现">5. 表现：</h4>
<ul>
<li>
<p>通过基类指针调用基类和派生类中的同名虚函数时:</p>
<ol>
<li>若该指针指向一个基类的对象，那么被调用的是基类的虚函数；</li>
<li>若该指针指向派生类对象，调用该派生类中的最终重写版本；如果它没有重写，就使用继承的版本。</li>
</ol>
<p>这种机制就是实际上的“多态”——调用哪个虚函数，取决于指针对象指向哪种类型的对象。</p>
</li>
<li>
<p>通过基类引用调用基类和派生类中的同名虚函数时:</p>
<ol>
<li>若该引用引用了一个基类的对象，那么被调用的是基类的虚函数；</li>
<li>若该引用绑定派生类对象，调用该派生类中的最终重写版本；如果它没有重写，就使用继承的版本。</li>
</ol>
<p>调用哪个虚函数，取决于引用绑定的实际对象类型。</p>
</li>
</ul>
