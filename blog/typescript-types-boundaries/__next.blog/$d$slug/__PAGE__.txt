12:T23d8,<p>本站前端文件中有不少<code>.ts</code>和<code>.tsx</code>。它们使用TypeScript，也就是在JavaScript的基础上增加类型表达和检查能力。<code>.tsx</code>还允许写JSX，用来描述React界面。</p>
<p>如果已经会JS，可以先从“函数期待收到什么、最后返回什么”开始看类型，不必一上来就研究很复杂的泛型。</p>
<h2 id="section-给文章对象写清楚形状">给文章对象写清楚形状</h2>
<div class="code-block"><div class="code-toolbar"><span>ts</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-ts"><span class="hljs-keyword">type</span> <span class="hljs-title class_">Article</span> = {
  <span class="hljs-attr">id</span>: <span class="hljs-built_in">string</span>;
  <span class="hljs-attr">title</span>: <span class="hljs-built_in">string</span>;
  <span class="hljs-attr">tags</span>: <span class="hljs-built_in">string</span>[];
  <span class="hljs-attr">date</span>: <span class="hljs-built_in">string</span> | <span class="hljs-literal">null</span>;
};

<span class="hljs-keyword">function</span> <span class="hljs-title function_">articleLabel</span>(<span class="hljs-params"><span class="hljs-attr">article</span>: <span class="hljs-title class_">Article</span></span>): <span class="hljs-built_in">string</span> {
  <span class="hljs-keyword">return</span> <span class="hljs-string">`<span class="hljs-subst">${article.title}</span>（<span class="hljs-subst">${article.tags.length}</span>个标签）`</span>;
}
</code></pre></div>
<p><code>string[]</code>表示字符串数组；<code>string | null</code>允许日期是字符串，也允许明确没有日期。函数参数的类型告诉调用者应该传什么，返回类型说明结果是字符串。</p>
<p>这里没有把日期写成可选字段<code>date?: string</code>，是因为“字段不存在”与“字段存在，但日期暂时未知”可以表达不同含义。项目中是否需要区分它们，取决于数据约定。</p>
<p>如果把<code>tags</code>写成一个字符串，编辑器和类型检查就能提醒。类型检查发生在开发和构建阶段，编译后的浏览器代码主要仍是JS；类型标注不会自动变成运行时的检查语句。<a href="https://www.typescriptlang.org/docs/handbook/2/everyday-types.html" rel="noopener noreferrer">TypeScript基础类型</a>可以作为这些写法的语法参考。</p>
<h2 id="section-联合类型怎样限制状态">联合类型怎样限制状态</h2>
<p>反馈类型只有三种，可以写成：</p>
<div class="code-block"><div class="code-toolbar"><span>ts</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-ts"><span class="hljs-keyword">type</span> <span class="hljs-title class_">FeedbackKind</span> = <span class="hljs-string">"correction"</span> | <span class="hljs-string">"question"</span> | <span class="hljs-string">"other"</span>;

<span class="hljs-keyword">type</span> <span class="hljs-title class_">SubmitState</span> =
  | { <span class="hljs-attr">status</span>: <span class="hljs-string">"idle"</span> }
  | { <span class="hljs-attr">status</span>: <span class="hljs-string">"sending"</span> }
  | { <span class="hljs-attr">status</span>: <span class="hljs-string">"success"</span>; <span class="hljs-attr">receiptId</span>: <span class="hljs-built_in">string</span> }
  | { <span class="hljs-attr">status</span>: <span class="hljs-string">"error"</span>; <span class="hljs-attr">message</span>: <span class="hljs-built_in">string</span> };
</code></pre></div>
<p><code>status</code>让这几个对象有了明确区别。检查<code>state.status === "success"</code>之后，TypeScript知道当前分支有<code>receiptId</code>。这样可以减少“状态显示成功，但编号字段根本没有”的组合。它也让代码里应该处理哪些状态更清楚。<a href="https://www.typescriptlang.org/docs/handbook/2/narrowing.html" rel="noopener noreferrer">类型收窄</a>说明了检查条件怎样影响后续类型。</p>
<p>本站表单目前用多个<code>useState</code>变量表示等待、输入和提示。上面是另一种教学组织方式，不代表项目已经改成了这个联合状态对象。</p>
<h2 id="section-泛型说明返回类型却不会校验网络数据">泛型说明返回类型，却不会校验网络数据</h2>
<p><a href="/images/website-series/trust-boundary.svg" target="_blank" rel="noopener noreferrer" class="article-image-link" aria-label="查看图片原图：TypeScript静态约束、网络JSON与运行时校验的不同位置"><img src="/images/website-series/trust-boundary.svg" alt="TypeScript静态约束、网络JSON与运行时校验的不同位置" width="1100" height="395" loading="lazy" decoding="async" referrerpolicy="no-referrer"></a></p>
<p><a href="/images/website-series/trust-boundary.svg">查看图中细节</a></p>
<p>本站有这样的调用：</p>
<div class="code-block"><div class="code-toolbar"><span>ts</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-ts"><span class="hljs-keyword">const</span> receipt = <span class="hljs-keyword">await</span> apiRequest&#x3C;{ <span class="hljs-attr">id</span>: <span class="hljs-built_in">string</span>; <span class="hljs-attr">status</span>: <span class="hljs-built_in">string</span> }>(
  <span class="hljs-string">"/feedback"</span>,
  { <span class="hljs-attr">method</span>: <span class="hljs-string">"POST"</span>, <span class="hljs-attr">body</span>: <span class="hljs-title class_">JSON</span>.<span class="hljs-title function_">stringify</span>(payload) },
);
</code></pre></div>
<p>尖括号中的类型传给了泛型参数<code>T</code>。调用者因此能获得属性提示，但目前<code>apiRequest</code>内部最后使用<code>response.json() as Promise&#x3C;T></code>，这个断言只告诉TypeScript按该类型处理结果。</p>
<p>假设服务器意外返回<code>{"id": 12}</code>，<code>as</code>不会把12变成字符串，也不会自动报格式错误。如果这个边界需要强保证，就应把未知输入先视为<code>unknown</code>，检查之后再使用：</p>
<div class="code-block"><div class="code-toolbar"><span>ts</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-ts"><span class="hljs-keyword">function</span> <span class="hljs-title function_">isReceipt</span>(<span class="hljs-params"><span class="hljs-attr">value</span>: <span class="hljs-built_in">unknown</span></span>): value is { <span class="hljs-attr">id</span>: <span class="hljs-built_in">string</span>; <span class="hljs-attr">status</span>: <span class="hljs-string">"pending"</span> } {

  <span class="hljs-keyword">return</span> <span class="hljs-string">"id"</span> <span class="hljs-keyword">in</span> value &#x26;&#x26; <span class="hljs-keyword">typeof</span> value.<span class="hljs-property">id</span> === <span class="hljs-string">"string"</span>
    &#x26;&#x26; <span class="hljs-string">"status"</span> <span class="hljs-keyword">in</span> value &#x26;&#x26; value.<span class="hljs-property">status</span> === <span class="hljs-string">"pending"</span>;
}
</code></pre></div>
<p>这个函数是教学示例，检查的是回执对象，不包含UUID格式等全部业务约束。生产代码若需要更严格的契约，还应明确字段格式、错误处理和兼容策略。</p>
<h2 id="section-typescript与pydantic为什么都需要">TypeScript与Pydantic为什么都需要</h2>
<p>TypeScript帮助前端开发者在写代码时发现错误，Pydantic检查后端实际收到的数据。用户可以通过脚本直接发送HTTP请求，因此不能认为前端通过类型检查，后端就能省略校验。</p>
<p>数据库还有自己的约束。例如反馈状态的允许值、内容外键和消息长度，数据库也会检查。三者处在不同阶段：开发时约定、请求到达时校验、数据最终落库时约束。后两层会在<a href="/blog/pydantic-validation/">Pydantic输入模型</a>和<a href="/blog/postgresql-tables-queries/">PostgreSQL表与查询</a>中展开。</p>
