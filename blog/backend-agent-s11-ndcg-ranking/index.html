排序评价同时考虑相关程度与位置

推荐或搜索已经找到候选后，还需要比较它们的顺序。DCG（折损累计增益）对靠后位置的相关性增益打折，NDCG再用理想排序的DCG归一化。

本文采用非负相关性等级rel和线性增益g(rel)=rel，位置i从1开始：

DCG@K=∑i=1min⁡(K,n)g(reli)log⁡2(i+1),NDCG@K=DCG@KIDCG@KDCG@K=\sum_{i=1}^{\min(K,n)} \frac{g(rel_i)}{\log_2(i+1)},\qquad NDCG@K=\frac{DCG@K}{IDCG@K}

IDCG是在同一评价候选集合上按相关性从高到低排列得到的理想值。若IDCG=0，本文约定返回0。另一种常见增益为2^rel−1，它更强调高等级差异，两种口径算出的数不能直接混用。scikit-learn的线性增益口径

三件商品怎样算出不同分数

假设同一个query下，A、B、C的相关性分别为3、2、0，计算NDCG@3：

顺序DCG计算DCGNDCG
A、B、C3+2/log₂3+0/2约4.26191
B、A、C2+3/log₂3+0/2约3.8928约0.9134
C、B、A0+2/log₂3+3/2约2.7619约0.6480

把无关的C放在第1位，不仅浪费最显眼的位置，还把A推到更大的折扣下。若只看这3件商品是否都在候选中，无法区分这三种顺序。

K也会改变评价范围。NDCG@1只看首位，不能说明第2到第10位是否合理。一个query的NDCG再高，也不能替代对不同query分别计算后的整体分析。

可直接复算的Python实现

输入是一条query的全部评价候选对应的标签和预测分数，两个列表长度一致。下面约定同分时保持输入顺序，便于复现；它不是所有库默认的并列平均语义。K超过候选数就按实际数量截断，空输入返回0，负标签或非有限数值拒绝处理。

python
import math


def ndcg_at_k(labels, scores, k=10):
    if len(labels) != len(scores):
        raise ValueError("labels and scores must have equal length")
    if isinstance(k, bool) or not isinstance(k, int) or k <= 0:
        raise ValueError("k must be a positive integer")
    if any(not math.isfinite(x) or x < 0 for x in labels):
        raise ValueError("labels must be finite and nonnegative")
    if any(not math.isfinite(x) for x in scores):
        raise ValueError("scores must be finite")

    # Python排序稳定；同分时按原输入次序。
    order = sorted(range(len(scores)), key=lambda i: -scores[i])
    ranked = [labels[i] for i in order[:k]]
    ideal = sorted(labels, reverse=True)[:k]

    def dcg(values):
        return sum(rel / math.log2(pos + 2)
                   for pos, rel in enumerate(values))

    best = dcg(ideal)
    return dcg(ranked) / best if best > 0 else 0.0


if __name__ == "__main__":
    labels = [3, 2, 0]  # 候选始终按A、B、C存储
    print(round(ndcg_at_k(labels, [3, 2, 1], 3), 4))
    print(round(ndcg_at_k(labels, [2, 3, 1], 3), 4))
    print(round(ndcg_at_k(labels, [1, 2, 3], 3), 4))

预期输出依次为1.0、0.9134、0.648。函数只计算指标，没有训练排序模型。对多个query应先分组计算，再按事先确定的权重汇总；不能把所有商品拼成一张总榜。

完整排序使用O(n log n)时间与O(n)辅助存储。实际候选规模较大、只需TopK时可以优化选择过程，但必须保留理想排序口径和同分规则。

从query与商品特征建立一个可检查的打分基线

最小输入包括query、商品ID、商品特征和训练标签。特征可包含关键词匹配、语义相似度、类目或属性是否满足，以及请求时可用的商品质量信号。库存、地区等硬资格应先明确处理，不能靠一个高分把违规商品带回结果。

假设只展示手工线性基线，使用已经归一化到0到1的(文本匹配, 属性匹配, 质量)，权重为(0.6,0.3,0.1)：

商品特征分数
A(1,1,0.5)0.95
B(0.8,1,0.9)0.87
C(0.1,0,1)0.16

这是说明特征到分数的教学计算，没有通过真实数据学习，也不能据此宣称NDCG提升。实际可先建立线性或树模型基线，采用点式、成对或列表式训练目标，再在独立验证集选择配置。模型输出的排序分数也未必是已校准的点击概率。

提高NDCG时要排除哪些假改善

评价先固定query分组、标签定义、候选范围、K和增益函数。只把已召回的候选拿来算IDCG，可能掩盖相关商品没有被召回的问题，因此召回覆盖要另外报告，必要时使用更完整的标注池评估端到端效果。

训练数据应按业务时点切分，避免把后来的销量、购买或测试标签带进特征。改了候选集或标注口径后，不能只比较新旧两个平均数。还应检查长尾query、冷启动商品、同义表达和属性约束，而不仅是热门样本。

NDCG关注已有标签下的排序，不直接表示延迟、库存可用、长期满意度或公平性。离线分数上升后，仍需受控线上实验和相应保护指标。

面试问答：搭建电商搜索排序链路

AI Coding：电商搜索排序题，给你 query 和商品特征，输出排序分数，提升 NDCG@10，你会怎么搭链路。

回答： 先核对输入字段、query分组、相关性标签和NDCG@10的增益及并列规则。对候选执行库存、地区等资格检查，构造query与商品的文本匹配、语义相似度、类目属性交互及请求时可用的质量特征，再建立可复现的简单打分基线。

有标注数据时，按时间和必要的实体边界切分训练、验证与测试集，避免同query样本被随意拆散后形成泄漏。可从线性或树排序模型开始，根据数据采用成对或列表目标；验证集调参，冻结测试集做最终比较。实现中统一缺失值和特征版本，输出商品ID与排序分数，并保留稳定的同分处理。

评价按query计算NDCG@10，再汇总并检查细分任务，同时单独报告召回覆盖、延迟和资格错误。上面的Python函数可作为线性增益、稳定同分规则下的指标基线，和目标评测器口径一致后才能使用。不能凭手工权重和单个算例声称提升，应展示固定数据上的基线、改动和独立结果。

若使用编码工具辅助实现，应先固定指标边界测试，再检查分组、数据泄漏和接口契约。上线前验证训练与服务特征一致性，离线改善后用受控实验确认业务收益。

延伸追问（自拟）：AUC提高，NDCG@10为何下降？ 两者关心的排序范围和标签使用方式不同，整体正负区分改善可能同时伴随顶部次序变差。还要检查分组口径与候选变化，不能用一个指标推定另一个必然改善。
