“页面在服务器生成”这句话还不够明确：是在发布前的构建机器上生成，还是每次收到读者请求后生成？Next.js可以支持不同方式，本站使用的是前一种。

除了生成时间，还要看生成后的页面怎样获得交互。先把这两条关系分开，再理解Server Component与Client Component。

一、SSG、SSR、CSR与hydration各自描述什么

名称主要回答的问题在本站怎样理解
SSG，静态生成HTML能否提前生成正文在构建时生成，发布后直接读取
SSR，请求时服务端渲染是否收到请求后再生成HTML当前公开文章没有常驻Next服务执行这一步
CSR，客户端渲染哪些界面由浏览器中的JS计算更新搜索结果、表单提示和主题设置会更新
hydration，交互接管React怎样接管已有HTML客户端初始化组件逻辑，让事件与状态开始工作

SSG页面可以继续运行客户端交互，SSR页面也可以进行hydration。它们分别描述不同阶段，不适合当成四种完全排斥的站点类型。

本站的直接证据是配置中的output: "export"。构建时生成HTML及客户端导航需要的数据，部署后由静态服务器提供。Next官方说明了静态导出中的生成过程和能力限制。

二、Server Component与Client Component怎样分工

App Router默认的Server Component适合读取服务端或构建环境中的数据、组织界面。本站从磁盘读取Markdown的工作在这一侧完成；这个模块不应该连同文件系统访问能力一起送进浏览器。

需要state、事件处理、Effect和浏览器API的部分使用Client Component。在模块顶部写"use client"，建立客户端边界；其导入的客户端依赖也会影响浏览器代码量。没有必要把每个只负责显示标题的组件都单独标一次。use client参考说明了边界和传递数据的约束。

Client Component仍可能参与初始HTML预渲染，因此直接在渲染代码里访问window或localStorage可能出问题。客户端能力与“只在浏览器执行每一步”不能直接画等号。需要浏览器环境的同步操作，通常应放在合适的Effect或事件回调里。

三、为什么初始状态需要对应

假设构建时生成按钮文字“亮色”，浏览器首次渲染却立即按本机存储生成“暗色”，两侧输出不同，就可能出现hydration不一致。随机值、当前时间、仅浏览器可用的数据，也需要留意这个问题。

一种处理思路是先让两侧使用一致的初始结构，再在客户端读取偏好并更新；主题是否会闪烁还涉及首次绘制前的主题设置和CSS策略，需要结合具体工程检查。不要为了消除警告就把所有内容都延迟到客户端显示，那会影响原本可以提前提供的正文。

本站颜色偏好采用更具体的分工：首屏入口脚本先解析localStorage并设置根元素的配色属性，后续客户端交互使用同一解析函数。共享规则减少“刷新使用一套色板，切页又算成另一套”的差异。存储仍是外部输入，需要验证；这一做法也不能单独保证所有组件都没有hydration问题。作用范围、复制和恢复的例子见栏目配色状态。

本站FeedbackForm在客户端Effect执行后才将ready设为true，随后开放发送按钮，并提供noscript说明。这样读者先看到正文和表单结构，交互准备好后再提交；这只是局部行为，不是全站无JS体验已经完成全面验收的证明。

四、数据更新后为何还看到旧文章

静态导出时，Markdown内容已经进入生成的HTML。之后仅修改源文件，线上文件不会自行变化；需要重新构建并发布。浏览器还可能使用缓存，因此要继续确认取得的是哪一个版本。

假设后端数据库停机，已发布文章仍可由Nginx读取，但反馈写入与管理查询会受影响。如果Nginx或整台服务器停机，静态正文同样不能访问。依赖减少与系统完全不会故障是两件事。

Server Component、SSR也不等于相同概念：Server Component描述组件执行与传输模型，SSR描述生成HTML的时机。静态导出中的Server Component在构建时执行，便是一个直接例子。服务端与客户端组件进一步解释了两者怎样组合。

五、客户端切页为什么还会请求分段文件

静态导出除了首次打开所需HTML，还生成客户端导航使用的数据。React Server Components的传输数据通常称为Flight payload，可以先把它理解成框架用于重建路由组件关系的数据，并不是数据库查询结果的同义词。

因此，从列表点击文章时，浏览器可能请求已导出的分段资源；它仍然可以由Nginx返回静态文件。出现额外请求不等于每次都在SSR，应继续看该URL返回什么、由谁生成、什么时候生成。

本站Windows构建曾出现嵌套__next段路径与客户端请求的点分文件名不一致，处理脚本生成同字节路径别名，并拒绝已有别名与源字节冲突。这个问题说明首页HTML返回200还不够，直接刷新、客户端跳转和需要的分段文件应分别验证。旧标签页还可能请求旧hash资源，所以它又与发布保留策略相连。

六、需要登录才能阅读的内容应放在哪里

如果全文已经进入公共HTML，再通过客户端判断登录状态隐藏它，用户仍可能从响应中取得正文。受限内容应在真正受控的服务端或内容接口中判断权限，并检查缓存是否会泄露其他用户的结果。

本站管理页可以静态提供界面外壳，管理数据由受鉴权保护的FastAPI返回。静态外壳可访问，不代表获得管理权限；正文是否公开与接口是否授权，要在各自的数据边界检查。

后续如果确实需要按每次请求生成个性化页面，就要评估Node服务、缓存、资源占用和发布恢复，而不是只删掉output: "export"。当前个人主页的主要阅读内容还没有这一要求。
