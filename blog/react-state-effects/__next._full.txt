<h2 id="section-usestate保存的是哪一轮状态">useState保存的是哪一轮状态</h2>
<div class="code-block"><div class="code-toolbar"><span>tsx</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-tsx"><span class="hljs-string">"use client"</span>;
<span class="hljs-keyword">import</span> { useState } <span class="hljs-keyword">from</span> <span class="hljs-string">"react"</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">Counter</span>(<span class="hljs-params"></span>) {
  <span class="hljs-keyword">const</span> [count, setCount] = <span class="hljs-title function_">useState</span>(<span class="hljs-number">0</span>);
  <span class="hljs-keyword">return</span> <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">button</span> <span class="hljs-attr">onClick</span>=<span class="hljs-string">{()</span> =></span> setCount(count + 1)}>{count}<span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span></span>;
}
</code></pre></div>
<p><code>count</code>是本轮渲染读取到的值，<code>setCount</code>安排新的状态。调用它之后，当前函数里的<code>count</code>不会立刻变成新值；React后续渲染时才会把更新后的状态交给组件。<a href="https://react.dev/learn/state-as-a-snapshot" rel="noopener noreferrer">状态快照</a>说明了事件处理函数为何会保留某一轮的值。</p>
<p>例如同一个点击处理里连续执行三次<code>setCount(count + 1)</code>，三次计算用的可能都是同一份<code>count</code>。如果目标是基于前一次待处理值累加三次，可以写三次<code>setCount(value => value + 1)</code>。更新函数接收队列中的前一个值，不能简单把两种写法看成完全等价。<a href="https://react.dev/learn/queueing-a-series-of-state-updates" rel="noopener noreferrer">状态更新队列</a>有对应过程。</p>
<h2 id="section-输入框怎样保持值与界面一致">输入框怎样保持值与界面一致</h2>
<div class="code-block"><div class="code-toolbar"><span>tsx</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-tsx"><span class="hljs-keyword">const</span> [message, setMessage] = <span class="hljs-title function_">useState</span>(<span class="hljs-string">""</span>);

<span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">textarea</span>
  <span class="hljs-attr">value</span>=<span class="hljs-string">{message}</span>
  <span class="hljs-attr">onChange</span>=<span class="hljs-string">{event</span> =></span> setMessage(event.target.value)}
/></span>
</code></pre></div>
<p>输入触发<code>onChange</code>，把新的字符串存入state；下一轮渲染再把这个字符串传给<code>value</code>。这种输入由组件状态管理，通常称为受控输入。</p>
<p>本站反馈表单在等待期间禁用输入与按钮，成功后清空字符串，失败则保留。因此处理成功与失败时需要分别更新对应状态，不能在提交函数末尾无条件清空。</p>
<p>数组和对象也应产生新值，例如<code>setTags(tags => [...tags, "React"])</code>，而不是直接对原数组<code>push</code>后继续复用原引用。这样更容易保持每轮状态清楚，也能避免修改其他地方仍在使用的对象。</p>
<h2 id="section-effect何时需要何时不需要">Effect何时需要，何时不需要</h2>
<p><code>useEffect</code>适合将组件状态与React外部系统同步，例如事件监听、计时器、浏览器存储和观察器。若只是根据已有props筛选列表，通常可以直接在渲染时计算，不必额外存一份state再用Effect同步。</p>
<div class="code-block"><div class="code-toolbar"><span>tsx</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-tsx"><span class="hljs-title function_">useEffect</span>(<span class="hljs-function">() =></span> {

<p>这个教学示例订阅浏览器事件，并在清理函数里取消订阅。依赖数组为空，表示没有随组件渲染变化、需要重新同步的响应式依赖；并不适合概括成“任何环境都保证只执行一次”。开发阶段的Strict Mode会额外进行建立与清理检查，组件重新挂载也会重新执行。<a href="https://react.dev/learn/synchronizing-with-effects" rel="noopener noreferrer">Effect说明</a>解释了同步、依赖与清理的关系。</p>
<p>如果Effect使用了变化中的值，就应正确声明依赖。为了消掉重复执行而随意删依赖，可能让计时器一直读取旧值。遇到这类问题，先确认Effect究竟要同步什么，再考虑重组代码。</p>
<h2 id="section-横幅切换为什么要保留上一张图">横幅切换为什么要保留上一张图</h2>
<p>本站横幅维护<code>current</code>、<code>previous</code>和<code>ready</code>。切换时先保存上一张图，再请求下一张；新图成功加载后才进入过渡，过渡结束再释放旧图。</p>

<p>工程曾记录<code>onError</code>与<code>onLoad</code>共用成功处理，导致失败也被当作“可以结束旧图保留”。修正后将失败回调分开。这个问题要看的是状态转移条件：触发了图片事件，并不一定意味着图片成功显示。</p>
<p>轮播还需要考虑页面是否可见、横幅是否在视口内、用户是否选择减少动态效果。本站通过这些条件决定是否继续计时，并在依赖变化时清理计时器，避免离开页面后仍积累后台任务。</p>
<h2 id="section-useref与state怎样选择">useRef与state怎样选择</h2>
