27:T26c8,<h2 id="section-写查询前先确定要返回哪些对象">写查询前，先确定要返回哪些对象</h2>
<p>“查出客户和订单”还不足以确定SQL。结果可以每个客户一行，也可以每笔订单一行；没有下单的客户要不要出现，也会改变连接方式。<strong>结果的粒度，就是一行代表什么对象。</strong> 先把这个问题说明白，后面的JOIN、聚合和去重才有依据。</p>
<p>本文使用MySQL8.4支持的SQL语义。为了让算例容易复查，查询只使用常见的聚合和窗口函数；本地验证采用SQLite检查这些具体算例的结果，不代表运行了MySQL执行计划或锁行为。</p>
<h2 id="section-left-join保留客户订单数量要数哪一列">LEFT JOIN保留客户，订单数量要数哪一列</h2>
<p>假设客户表有A、B两人，订单表中A有两笔订单10、11，B没有订单。执行客户到订单的LEFT JOIN，结果为：</p>





















<table><thead><tr><th>客户</th><th align="right">订单ID</th></tr></thead><tbody><tr><td>A</td><td align="right">10</td></tr><tr><td>A</td><td align="right">11</td></tr><tr><td>B</td><td align="right">NULL</td></tr></tbody></table>
<p>LEFT JOIN为没有匹配订单的B保留一行，并把订单侧字段补为NULL。于是按客户分组后，A的<code>COUNT(*)</code>为2，B的<code>COUNT(*)</code>为1；如果订单ID保证非空，<code>COUNT(order_id)</code>才分别得到2和0。</p>
<p><strong>COUNT(*)数结果行，COUNT(表达式)数该表达式非NULL的行。</strong> NULL表示缺失或未知等情况，条件判断需要使用<code>IS NULL</code>，不能把<code>= NULL</code>当成普通等号比较。<a href="https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html" rel="noopener noreferrer">MySQL聚合函数</a></p>
<p>连接后再加<code>WHERE orders.status = 'paid'</code>，B那一行不会通过条件。如果目标是“保留所有客户，只统计已支付订单”，可以把订单状态限制放在LEFT JOIN的ON条件里，再数订单ID。条件放在哪里，改变的是哪些行在连接和过滤后留下来，不能只按SQL长得是否相似判断。</p>
<p>同样需要注意一对多的连续连接。如果A有2笔订单、3个独立标签，直接同时连接可能生成6行。此时对订单金额求和会重复累计。应分别按目标粒度聚合，再连接汇总结果；<code>DISTINCT</code>也不能随意修复，因为两笔真实订单可能金额相同。</p>
<h2 id="section-第二高要先确定重复值怎样参与排名">“第二高”要先确定重复值怎样参与排名</h2>
<p>假设薪资依次为100、100、90、80。只说“第二高”，可能指排序后的第2个人，也可能指第2种不同薪资；这两种要求的答案分别可能为100和90。</p>



































<table><thead><tr><th align="right">薪资（降序）</th><th align="right">ROW_NUMBER</th><th align="right">RANK</th><th align="right">DENSE_RANK</th></tr></thead><tbody><tr><td align="right">100</td><td align="right">1</td><td align="right">1</td><td align="right">1</td></tr><tr><td align="right">100</td><td align="right">2</td><td align="right">1</td><td align="right">1</td></tr><tr><td align="right">90</td><td align="right">3</td><td align="right">3</td><td align="right">2</td></tr><tr><td align="right">80</td><td align="right">4</td><td align="right">4</td><td align="right">3</td></tr></tbody></table>
<p><strong>ROW_NUMBER给每行不同序号；RANK给并列项相同名次，并跳过被并列占用的后续名次；DENSE_RANK的名次连续。</strong> 若要区分两个100属于谁，ROW_NUMBER的排序应补充唯一ID，避免并列行的顺序未定义。<a href="https://dev.mysql.com/doc/refman/8.4/en/window-function-descriptions.html" rel="noopener noreferrer">MySQL窗口排名函数</a></p>
<p>这里把“第二高薪资”明确解释为<strong>第二种不同的非NULL薪资</strong>，并约定不存在时返回一行NULL。一个直接写法是：</p>
<div class="code-block"><div class="code-toolbar"><span>sql</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-sql"><span class="hljs-keyword">SELECT</span> <span class="hljs-built_in">MAX</span>(salary) <span class="hljs-keyword">AS</span> second_salary
<span class="hljs-keyword">FROM</span> employee
<span class="hljs-keyword">WHERE</span> salary <span class="hljs-operator">&#x3C;</span> (<span class="hljs-keyword">SELECT</span> <span class="hljs-built_in">MAX</span>(salary) <span class="hljs-keyword">FROM</span> employee);
</code></pre></div>
<p>内层先得到100，外层保留所有低于100的薪资，再从90和80中取最大值90。重复的100不会影响结果；只有100或表为空时，外层聚合仍返回一行，其值为NULL。</p>
<p>窗口函数也能表达同一要求：</p>
<div class="code-block"><div class="code-toolbar"><span>sql</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-sql"><span class="hljs-keyword">WITH</span> ranked <span class="hljs-keyword">AS</span> (
    <span class="hljs-keyword">SELECT</span> salary,
           <span class="hljs-built_in">DENSE_RANK</span>() <span class="hljs-keyword">OVER</span> (<span class="hljs-keyword">ORDER</span> <span class="hljs-keyword">BY</span> salary <span class="hljs-keyword">DESC</span>) <span class="hljs-keyword">AS</span> salary_rank
    <span class="hljs-keyword">FROM</span> employee
    <span class="hljs-keyword">WHERE</span> salary <span class="hljs-keyword">IS</span> <span class="hljs-keyword">NOT NULL</span>
)
<span class="hljs-keyword">SELECT</span> <span class="hljs-built_in">MAX</span>(salary) <span class="hljs-keyword">AS</span> second_salary
<span class="hljs-keyword">FROM</span> ranked
<span class="hljs-keyword">WHERE</span> salary_rank <span class="hljs-operator">=</span> <span class="hljs-number">2</span>;
</code></pre></div>
<p>外层MAX把多个并列的第二高值收成一行，也统一了不存在时的返回形式。若题目要返回所有第二高薪资的员工，就应该保留员工ID并直接筛选第2名，不能再只聚合薪资。</p>
<h2 id="section-分页为什么需要稳定排序还需要考虑数据变化">分页为什么需要稳定排序，还需要考虑数据变化</h2>
<p>按<code>created_at DESC</code>展示订单时，同一时间可能存在多笔订单。加上<code>id DESC</code>形成唯一的排序次序，才方便确定一页最后一行的位置。</p>
<p>例如上一页末尾是<code>(created_at, id) = (T, 105)</code>，下一页可查：</p>
<div class="code-block"><div class="code-toolbar"><span>sql</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-sql"><span class="hljs-keyword">SELECT</span> id, created_at
<span class="hljs-keyword">FROM</span> orders
<span class="hljs-keyword">WHERE</span> created_at <span class="hljs-operator">&#x3C;</span> :<span class="hljs-type">time</span>
   <span class="hljs-keyword">OR</span> (created_at <span class="hljs-operator">=</span> :<span class="hljs-type">time</span> <span class="hljs-keyword">AND</span> id <span class="hljs-operator">&#x3C;</span> :id)
<span class="hljs-keyword">ORDER</span> <span class="hljs-keyword">BY</span> created_at <span class="hljs-keyword">DESC</span>, id <span class="hljs-keyword">DESC</span>
LIMIT :page_size;
</code></pre></div>
<p><code>:time</code>等是示意参数，实际占位符取决于数据库驱动。这个方法按<strong>游标记录的位置继续查</strong>，避免深度OFFSET先跳过大量行的成本，也减轻前面新增记录导致的位置漂移。它要求索引、排序方向和比较条件相互匹配。</p>
<p>但游标分页没有自动提供跨请求快照。若旧订单的排序字段被修改，或权限条件改变，后续页面仍可能出现遗漏或重复。需要严格的一次性导出时，还要设计一致性快照或固定的数据版本；普通动态列表则应明确刷新和去重策略。</p>
<h2 id="section-面试问答查询第二高薪资">面试问答：查询第二高薪资</h2>
<p><span id="q-FQ-doxcnE7SgCCO2PyqAY4jF1gOsVb" class="legacy-anchor" aria-hidden="true"></span><a id="user-content-q-FQ-doxcnE7SgCCO2PyqAY4jF1gOsVb"></a></p>
<blockquote>
<p>SQL：一张表 id、薪资，查询薪资第二高的员工的薪资。</p>
</blockquote>
<p><strong>回答：</strong> 先确认“第二高”是第二个员工还是第二种不同薪资，以及不存在时的返回约定。按第二种不同的非NULL薪资解释，可先用MAX查出最高薪资，再查询低于它的最大薪资。100、100、90、80会得到90；只有100或没有数据时，聚合结果为NULL。</p>
<p>使用窗口函数时应选DENSE_RANK，因为RANK在最高薪资并列时会跳过第2名。先过滤NULL、按薪资降序生成密集排名，再选排名2，即可找到第二档薪资。题目只要薪资时可以收成一个值；若要全部对应员工，应保留这些员工的行。</p>
<p>性能还要结合数据规模和薪资索引验证。两种SQL语义上能表达目标，不表示它们在任意数据分布下有相同执行成本。数据量大时应查看实际执行计划及扫描量。</p>
