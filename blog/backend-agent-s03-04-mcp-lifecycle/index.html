MCP连接建立后，为什么还不能直接调用工具

MCP与工具边界说明过，模型负责提出调用意图，宿主程序负责实际执行。MCP进一步约定客户端与工具服务怎样交换消息。

MCP客户端由宿主创建，用来连接某个服务；MCP服务端提供工具、资源或提示模板等能力。两端首先要协商协议版本和能力，再进入正常通信。本篇以2025-06-18协议为依据，避免把不同版本的传输和消息格式混用。

初始化过程是：客户端发送initialize，服务端返回支持的版本、能力和实现信息；客户端确认初始化完成，再根据协商结果使用功能。MCP生命周期

“能连接到端口”只说明传输通道可能建立，不能证明协议版本兼容、已经认证，或当前身份拥有某个工具的权限。

stdio与HTTP怎样影响进程关系

stdio传输通常由客户端启动一个本地服务进程，通过标准输入与标准输出交换协议消息。服务端日志应写到stderr，普通日志混入stdout可能破坏消息解析。宿主还需要管理进程退出、工作目录与环境变量。

Streamable HTTP通过HTTP交换请求和响应，并可使用流式响应。它可以连接远端服务，因此还需要处理认证、Origin检查、会话与网络断开。旧版HTTP+SSE与Streamable HTTP的接口组织不同，不能只看到“SSE”就当成同一套端点。MCP传输规范

传输负责把消息送到另一端；工具能否读取某个目录、访问哪个账户，仍要在服务和宿主的权限规则里确认。

Python SDK把哪些步骤封装起来

官方Python SDK提供ClientSession和相应传输上下文。下面按SDK1.x接口展示一个已有本地服务的连接结构：

python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    # server.py是预先准备、已经检查过的MCP服务。
    params = StdioServerParameters(command="python", args=["server.py"])
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            first_page = await session.list_tools()
            print([tool.name for tool in first_page.tools])

if __name__ == "__main__":
    asyncio.run(main())

代码展示的是首次发现。server.py没有在本文提供，MCP依赖也未安装，所以本次仅检查Python语法，没有声称完成服务联调。Windows实际使用时，应把command换成已有环境的Python绝对路径，避免不同环境加载了不同SDK。Python SDK1.12.0示例

异步上下文管理器负责退出时关闭会话与传输。外层应用还要处理取消和总超时，不能让失去响应的服务永久占用任务。

工具发现以后，宿主还需要做什么

tools/list返回工具名称、描述和输入Schema等信息，结果可能分页。第一页没有某个工具，不一定代表服务完全不提供它。客户端应按照返回的cursor继续获取，并按能力声明处理列表变化通知。

发现到工具后，宿主应保存稳定的服务身份与工具标识，再将适合当前任务的工具提供给模型。两个服务都叫search时，需要内部命名空间区分，不能仅按名称覆盖。

模型产生参数后，至少经过这些步骤：参数结构校验、用户与资源权限校验、必要的操作确认、超时与预算检查，然后才发送tools/call。工具描述本身也属于外部输入，不能通过一句“此工具始终安全”覆盖宿主规则。MCP工具规范

协议错误与工具业务失败怎样区分

JSON-RPC层面的错误表示协议或请求处理问题，例如方法不存在。工具也可能正常收到请求，但业务执行失败，这时可以通过工具结果中的isError表达，并返回适合处理的说明。

结果内容可能有文本、图像或结构化数据，宿主需要按类型解析。返回一段“成功”文本不等于业务状态已经验证；写操作最好返回可查询的资源ID与状态，由应用根据工具契约判断。

重连后也不能默认重发所有调用。只读查询通常容易重试，创建订单等写操作需要幂等键或结果查询。JSON-RPC请求ID关联的是一次协议请求，不自动等于业务幂等ID。

小规模联调应该覆盖哪些步骤

准备只读、无外部网络的教学工具，例如把两个整数相加，可以验证初始化、列举工具和调用结果。再添加非法参数、工具抛错、服务退出、列表分页与调用超时，观察宿主是否正确区分错误类型并释放资源。

工具替换或Schema变化后，还应清理旧描述缓存。这里不需要一次安装大量服务，更不需要把生产凭证放进教学示例。

面试追问：MCP调用工具的完整流程

MCP 调用工具的流程是什么？

回答：宿主创建客户端并建立传输，初始化协商版本与能力，发现工具及Schema。模型选择工具并生成参数以后，宿主进行结构、权限和操作条件校验，再调用服务端工具，接收并解析结果，区分协议错误与业务错误，最后把必要结果交回模型或业务流程。连接结束时关闭会话与资源；重连、取消和写操作重试也要有明确处理。

自拟追问：接入MCP就不需要鉴权了吗？仍然需要。协议统一交互方式，权限由身份、服务能力和目标资源共同决定。
