一、题目一：航班预订统计

1109. 航班预订统计力扣原题 ↗

题目要求

有n个航班，编号依次为1到n。预订记录bookings[i]=[firstᵢ,lastᵢ,seatsᵢ]表示：从firstᵢ到lastᵢ的每个航班都预订了seatsᵢ个座位，范围包含两端。不同预订需要累加。

返回长度为n的数组answer，其中answer[i]对应编号为i+1的航班，记录该航班最终预订的座位总数。

示例1

输入：bookings = [[1,2,10],[2,3,20],[2,5,25]], n = 5

输出：[10,55,45,25,25]

三条记录分别贡献[10,10,0,0,0]、[0,20,20,0,0]和[0,25,25,25,25]，按航班相加得到输出。

示例2

输入：bookings = [[1,2,10],[2,2,15]], n = 2

输出：[10,25]

第1个航班只得到10；第2个航班同时得到10和15。

约束条件

  • 1 ≤ n ≤ 2 × 10⁴
  • 1 ≤ bookings.length ≤ 2 × 10⁴
  • 每条bookings[i]恰好包含3个整数。
  • 1 ≤ firstᵢ ≤ lastᵢ ≤ n
  • 1 ≤ seatsᵢ ≤ 10⁴

先看怎样直接处理一条预订。[2,5,25]表示第2到第5个航班各增加25个座位，所以可以准备一个长度为n、初始全为0的数组，再把这四个位置分别加25。多条预订也逐条这样处理，最后得到的就是答案。

这个方法很直观，重复工作也很明确：如果很多预订都覆盖了同一大段航班，那一段就会被来回遍历。最坏情况下m条预订都覆盖全部n个航班，需要进行mn次逐项加法。题目只要求最终结果，中途不需要每处理一条预订就查询座位数，因此可以考虑先记下每条预订从哪里开始生效、到哪里结束，再统一算出各航班的总数。

要做到这一点，需要换一种保存数组信息的方式。直接保存每个位置的最终值时，一整段增加就要修改一整段；如果保存的是位置之间的变化，连续增加相同数值的一段，就只会改变两处边界。

1.1 差分数组的定义与累加恢复

为了把整段更新改成边界上的操作，先看相邻元素之间的差保存了什么。

差分数组把相邻两个元素的差保存下来，用边界变化表示整段更新。对于原数组a，定义：

d[0]=a[0],d[i]=a[i]−a[i−1](i≥1)d[0]=a[0],\qquad d[i]=a[i]-a[i-1]\quad(i\ge1)

例如a=[2,2,5,5,1]，对应d=[2,0,3,0,-4]。第一个2表示初始值，3表示从2升到5，−4表示从5降到1；连续不变的位置差值为0。

从左到右累加这些变化，就能恢复原值：

a[i]=∑j=0id[j]a[i]=\sum_{j=0}^{i}d[j]

比如走到下标2时，累计值为2+0+3=5；走到下标3时只加0，所以仍为5；最后加上−4，变为1。每个差分项表示“走到这里时，值相对前一个位置改变了多少”。差分为0表示当前位置沿用前一个位置的值，因此上例中的下标3仍然恢复为5。

展开差分数组的构造
python
def make_diff(nums: list[int]) -> list[int]:
    if not nums:
        return []
    return [nums[0]] + [nums[i] - nums[i - 1] for i in range(1, len(nums))]
展开差分数组的恢复
python
def restore(diff: list[int]) -> list[int]:
    total, answer = 0, []
    for delta in diff:
        total += delta
        answer.append(total)
    return answer

1.2 区间更新的起点增加与终点后撤销

对从0开始的闭区间[l,r]整体加v，只需要：

python
# 从l开始增加v
diff[l] += v
# 从r之后取消这次增加
diff[r + 1] -= v

区间内部的相邻两项都加了v，作差时两个v互相抵消，因此内部差分不变。只有进入区间时增加、离开区间时撤销，这两个位置需要修改。

还是用a=[2,2,5,5,1]，现在给下标1到3都加2，结果应为[2,4,7,7,1]。对照修改前后的差分，可以直接看到哪些位置发生了变化：

位置01：进入区间234：离开区间
原数组a22551
修改后的a24771
原差分d2030−4
修改后的d2230−6

下标1只修改了相邻两项中的后一项，所以差分多了2；下标2和3的前后两项都加了2，差分保持不变；下标4的自身没有增加，而前一项加了2，所以差分要再减2。这就对应diff[1]+=2、diff[4]-=2。

还可以从恢复过程理解撤销的位置：累加走到l时，多加进去的v会一直留在累计值中，继续影响后面的每个位置。必须等到r之后再减去v，才能让r本身仍然受到更新，而r+1及后面不再受到这条更新影响。r+1处的减法用来撤销这条更新继续向后传播的增量。恢复到r+1时，累计值中此前多出的v被减掉，该位置就回到了其他更新共同决定的数值。

如果r已经是末尾，可以跳过范围外的撤销；也可以预先多开一个哨兵位置，统一保存r+1的撤销事件，恢复时只输出原数组的n项。哨兵专门保存越过数组末尾的撤销事件，输出时仍只读取原来的n项。

单次更新只记两个边界是O(1)，但获得所有修改后的值，还需要一次O(n)累加恢复。差分适合先批量更新、最后统一取结果；如果更新与查询频繁交错，就不能把两种操作都算作O(1)。

1.3 航班编号转换与多条预订的叠加

每条预订[first,last,seats]表示这一段航班都增加seats个座位，正好是一段相同增量。

航班编号从1开始，数组下标从0开始，闭区间应转换为[first-1,last-1]。因此，增加的位置是first−1，撤销的位置是last：前者是第一个受影响航班的下标，后者是最后一个受影响航班之后的位置。

例如第2到第5个航班对应下标1到4，增加事件放在下标1，撤销事件就应放在下标5。下标5位于五个航班的范围之后，额外准备的哨兵位置用来保存这次撤销。这样无论预订是否覆盖最后一个航班，都可以使用同样的两次修改。

多条预订重叠时，也不需要额外判断它们之间的关系。每条记录都把自己的增加与撤销累加到差分数组里；恢复时，某个位置的累计值自然包含所有仍然生效的预订。也就是说，记录更新时逐条处理边界，读取答案时逐位置叠加影响，重叠区间会在这次累加中自动合并。

把题目中的三条预订逐次写下来，差分数组最初为[0,0,0,0,0,0]。每条预订都要完整执行下面的两次修改，再处理下一条：

预订及对应下标当前操作修改后的完整diff
[1,2,10]，覆盖下标[0,1]diff[0]：0＋10＝10，记录开始[10,0,0,0,0,0]
同一条预订diff[2]：0−10＝−10，从航班3起撤销[10,0,−10,0,0,0]
[2,3,20]，覆盖下标[1,2]diff[1]：0＋20＝20，记录开始[10,20,−10,0,0,0]
同一条预订diff[3]：0−20＝−20，从航班4起撤销[10,20,−10,−20,0,0]
[2,5,25]，覆盖下标[1,4]diff[1]：20＋25＝45，叠加新的开始[10,45,−10,−20,0,0]
同一条预订diff[5]：0−25＝−25，在哨兵处撤销[10,45,−10,−20,0,−25]

注意diff[1]里的45表示“从航班1走到航班2时，累计座位数增加45”，它来自后两条预订同时在航班2开始。这个45表示新增的座位数。航班1已有10个座位，走到航班2再增加45，累计得到的55才是航班2的最终结果。

python
def flight_bookings(bookings: list[list[int]], n: int) -> list[int]:
    # 最后一格为撤销更新的哨兵，不输出。
    diff = [0] * (n + 1)
    for first, last, seats in bookings:
        # 1-based航班first映射到0-based first-1。
        diff[first - 1] += seats
        # last之后的0-based位置正好是last。
        diff[last] -= seats
    answer, running = [], 0
    for i in range(n):
        running += diff[i]
        answer.append(running)
    return answer

正在恢复的航班此前累计值读取的差分本步计算写入结果

最后还剩哨兵diff[5]=−25。若仅为理解而继续累加，会得到25−25=0，表示第三条预订的影响也在全部航班范围之外结束。正式代码只恢复前五项，不会把这个0当成第6个航班输出。演示额外展示哨兵检查，是为了把撤销的含义说明完整。

设m为预订数、n为航班数，记录m次更新花O(m)，恢复n项花O(n)，所以总时间为O(m+n)，额外差分空间为O(n)；结果数组还需要O(n)输出空间。直接逐条修改区间最坏需要O(mn)。这里消除的是重叠预订带来的重复逐项修改，最后输出n项的工作仍然保留。

二、题目二：合并区间

56. 合并区间力扣原题 ↗

题目要求

输入区间数组intervals，每一项[startᵢ,endᵢ]都是包含两端的闭区间。把有交集的区间合并，直到输出中的区间彼此不再重叠。

输出覆盖的范围必须与全部输入区间的并集完全相同。共享端点也算有交集；输入区间不保证有序。

示例1

输入：intervals = [[1,3],[2,6],[8,10],[15,18]]

输出：[[1,6],[8,10],[15,18]]

前两段有重叠，合为[1,6]；其余两段互相分离。

示例2

输入：intervals = [[1,4],[4,5]]

输出：[[1,5]]

两个闭区间都包含4，因此连成一段。

示例3

输入：intervals = [[4,7],[1,4]]

输出：[[1,7]]

输入顺序与坐标顺序相反，但共享端点4，仍需合并。

约束条件

  • 1 ≤ intervals.length ≤ 10⁴
  • 每个intervals[i]恰好包含2个整数。
  • 0 ≤ startᵢ ≤ endᵢ ≤ 10⁴

做完航班预订统计后，再看到合并区间，我首先想到的也是记录开始和结束的位置。排序合并当然也能做，不过当时更想弄清楚的是：如果直接按坐标把这些事件存入数组，能否省去排序，让处理成本更低一些？

因此这里继续保留开始、结束事件的思路，并把坐标跨度也算进复杂度。不过，航班是离散的数组位置，56处理的是数轴上的闭区间。这一区别会影响撤销事件放在哪里。

[1,2]与[2,4]共享端点2，应合成[1,4]；[1,2]与[3,4]之间还有空隙，必须保留为两段。这里还需要保留整数端点之间的覆盖关系，例如2和3之间的2.5是否被某个区间覆盖。

2.1 整数点覆盖计数与区间间隙

闭区间在r+1处撤销，这个规则在航班题里没有问题，那么合并区间是否也能直接照搬？先明确这里的存储方式：每个格子代表一个原整数坐标，只保存该坐标所有增加与减少相加后的净值。按diff[l]+=1、diff[r+1]-=1记录，再累加，就能得到每个整数点被多少个区间覆盖，这个计数本身是正确的。

接着看输入[[1,2],[3,4]]。第一段在1处加1、3处减1；第二段在3处加1、5处减1。每一个事件都符合“从左端开始、到右端之后结束”的规则，合并到一张净差分表后是：

原坐标12345
[1,2]的边界事件+10−100
[3,4]的边界事件00+10−1
相加后的净diff1000−1
累加得到整数点覆盖数11110

整数点1、2、3、4确实都被覆盖，所以恢复出来的计数没有算错。但是，区间2到3之间还有未覆盖的部分，例如2.5不属于任何输入区间。这张表只保存了整数点的覆盖情况，没有保存相邻整数点之间是否连通。如果把连续为正的格子直接当成一整段，就会输出[1,4]，把原先没有覆盖的(2,3)也包含进去。

还可以用另一份输入[[1,4]]验证信息是否足够。它同样在1处加1、5处减1，得到的净diff与上面完全相同，但它真正的答案就是[[1,4]]。两份需要不同答案的输入，已经变成同一份净差分记录，仅凭这份记录就无法再判断中间有没有空隙。因此，r+1对于离散闭区间计数成立；直接用原坐标净差分恢复56的合并区间，还需要额外保留边界或间隙信息。

这也是下面继续采用分开保存开始与结束事件的原因。原来的边界思路可以保留，只要让存储内容足以区分共享端点与中间有间隙这两种情况。

2.2 开始结束事件的独立记录与扫描顺序

用starts[x]记录在x开始的区间数量，用ends[x]记录在x结束的区间数量。扫描线就是按坐标顺序处理这些事件，同时维护当前仍覆盖着的区间数量count。

这里的ends[r]表示“区间在坐标r结束”，扫描到r时仍要包含这个端点，因此要先处理该坐标所有开始事件，再处理结束事件。航班差分里的diff[r+1]-=v则表示“从下一个离散位置起取消增量”。一个保存实际端点事件，一个保存下一格的净变化；它们需要配合各自的扫描顺序使用。因此，判断写法是否成立时，需要把事件位置、保存的信息和扫描顺序一起对应起来。

处理坐标x时，先加入开始事件，再移除结束事件：

  1. 原先count为0且这里有开始事件，记录一段新的起点。
  2. 加入starts[x]，再减去ends[x]。
  3. 结束处理后count回到0，就在x关闭这一段。

对[1,2]与[2,4]，到2之前count为1，在2先加1再减1，仍为1，覆盖继续。对单点[2,2]，同一坐标也先打开、再关闭，能正确保留这个点。

把共享端点的例子展开一次，就能看清事件顺序为什么会影响合并：

当前坐标开始数结束数处理前count先开始、后结束是否输出区间
11000→1→1，记录起点1否
21111→2→1，覆盖仍连续否
40111→1→0，当前段结束输出[1,4]

如果在坐标2先结束旧区间并立刻输出，之后才处理新开始的区间，就会把本来共享端点的两段拆开。相反，先处理开始事件，相当于先确认这个坐标上还有哪些区间加入覆盖，再判断全部结束事件处理完后是否已经没有覆盖。这个顺序正好符合闭区间包含端点的含义。

python
def merge_dense_events(intervals: list[list[int]]) -> list[list[int]]:
    if not intervals:
        return []
    low = min(left for left, _ in intervals)
    high = max(right for _, right in intervals)
    starts, ends = [0] * (high - low + 1), [0] * (high - low + 1)
    for left, right in intervals:
        starts[left - low] += 1
        # 保留两种事件，不能提前净额抵消。
        ends[right - low] += 1
    count, begin, result = 0, None, []
    for offset in range(len(starts)):
        x = low + offset
        if count == 0 and starts[offset] > 0:
            begin = x
        # 闭区间：同坐标先处理开始。
        count += starts[offset]
        # 再处理结束，接触点会保持连通。
        count -= ends[offset]
        if count == 0 and ends[offset] > 0:
            # [x,x]单点也能正确开启并关闭。
            result.append([begin, x])
    return result

开始与结束分开保存还有一个作用：即使两者发生在同一坐标，也可以保留“先开始、后结束”的过程。例如单点区间[2,2]，starts[2]与ends[2]各为1，扫描时count先从0变为1，再从1变回0，便能输出这个点。如果为了省一张表，直接把实际端点事件写成diff[2]+=1、diff[2]-=1并预先相加，结果为0，单点就从记录里消失了。

这是把实际端点事件提前合成净值造成的信息损失，与上一小节“在原坐标r+1撤销后缺少间隙信息”是两个不同问题。本文采用的starts、ends方案同时保留了事件位置和处理顺序，不存在这两个问题；它属于边界增量思想的应用，但存储含义与相邻差分数组需要分别说明。

2.3 密集事件、稀疏事件与排序合并的成本

设区间数为n，实际扫描的坐标跨度为U=max(end)-min(start)+1。按下标放事件不需要排序，记录事件O(n)，扫描坐标O(U)，所以密集事件数组为O(n+U)时间、O(U)辅助空间，另计至多O(n)的输出。

本题坐标限制在0到10⁴之间，确实可以尝试密集数组。当推广到跨度很大、实际端点很少的数据时，可以改为只记录2n个事件，再排序扫描。

我当时关心的“能否省去排序”，在这份密集数组方案里是可以做到的：数组下标本身就给出了坐标顺序。不过，这个顺序并非没有成本，程序需要为跨度内的坐标分配空间，并逐个扫描，即使很多位置没有事件，也仍然会经过它们。所以这里必须同时保留n和U两个量，才能说明省下排序后又花了什么。

例如泛化到只有两三个区间、端点却相距10⁹的情况，逐坐标扫描会做大量无用工作；只保存出现过的端点再排序，就更合适。密集数组适合跨度较小的整数坐标，稀疏事件排序适合端点少而跨度大的数据。本题U最多10001，密集数组的时间和空间都可以根据这个上限直接估算。

def merge_sparse_events(intervals: list[list[int]]) -> list[list[int]]:
    events = [(left, 1) for left, _ in intervals]
    events += [(right, -1) for _, right in intervals]
    # 同坐标+在-之前。
    events.sort(key=lambda event: (event[0], -event[1]))
    count, begin, result = 0, None, []
    for x, delta in events:
        if delta == 1:
            if count == 0:
                begin = x
            count += 1
        else:
            count -= 1
            if count == 0:
                result.append([begin, x])
    return result

同坐标的开始事件排在结束事件前，继续保留闭区间语义。这种写法节约了跨度U对应的空间，但排序需要O(n log n)时间。Python字典虽然保留插入顺序，并不会按坐标大小自动排序。

def merge_sorted(intervals: list[list[int]]) -> list[list[int]]:
    result = []
    for left, right in sorted(intervals):
        if not result or left > result[-1][1]:
            result.append([left, right])
        else:
            # 相等端点也重叠，不能用>=判为分离。
            result[-1][1] = max(result[-1][1], right)
    return result

排序合并也可以用相同的“维护当前覆盖段”来理解。把区间按左端排好后，如果下一段的起点没有超过当前终点，两段就有交集，只需把终点更新为两者较大值；如果起点已经超过当前终点，当前段才可以输出，再开启下一段。这里取较大值是为了保留包含关系，例如当前为[1,10]，读到[2,3]后仍应保持[1,10]，不能把终点缩成3。

因此，密集事件法主要利用整数坐标范围较小这一条件，排序合并则只依赖端点能比较大小，推广到跨度很大或非整数端点时也方便使用。选择时可以同时比较输入值域、需要保存的状态，以及排序或扫描各自承担的工作。

已经按左端排序的输入可以直接O(n)合并；上表讨论的是需要排序的输入。选择方法时，把区间数n、坐标跨度U以及输入是否已有序一起考虑，就能看清记录事件、扫描坐标和排序分别需要多少工作。

补充：如果仍想用单张净差分表，怎样保留间隙

可以用偶数位置表示原坐标、奇数位置表示相邻整数之间的空隙，把闭区间[l,r]覆盖到[2l,2r]，在2r+1撤销。这样[1,2]和[3,4]之间留有未覆盖的间隙，而共享端点仍会连在一起。关键是同时定义坐标、间隙和撤销位置，仅把两个端点乘2还不够。

python
def merge_scaled_diff(intervals: list[list[int]]) -> list[list[int]]:
    if not intervals:
        return []
    low = min(left for left, _ in intervals)
    high = max(right for _, right in intervals)
    diff = [0] * (2 * (high - low) + 2)
    for left, right in intervals:
        diff[2 * (left - low)] += 1
        # 必须有+1，只将两端乘2无效。
        diff[2 * (right - low) + 1] -= 1
    running, begin, result = 0, None, []
    for i, delta in enumerate(diff):
        old = running
        running += delta
        if old == 0 and running > 0:
            begin = low + i // 2
        if old > 0 and running == 0:
            result.append([begin, low + (i - 1) // 2])
    return result
