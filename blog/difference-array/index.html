差分存的是相邻变化，累加后恢复原数组

如果要把数组中一整段元素都加上v，直接写法需要遍历这一段。多次更新的区间互相重叠时，同一个位置就可能被修改很多次。

差分数组把相邻两个元素的差保存下来，用边界变化表示整段更新。对于原数组a，定义：

d[0]=a[0],d[i]=a[i]−a[i−1](i≥1)d[0]=a[0],\qquad d[i]=a[i]-a[i-1]\quad(i\ge1)

例如a=[2,2,5,5,1]，对应d=[2,0,3,0,-4]。第一个2表示初始值，3表示从2升到5，−4表示从5降到1；连续不变的位置差值为0。

从左到右累加这些变化，就能恢复原值：

a[i]=∑j=0id[j]a[i]=\sum_{j=0}^{i}d[j]

展开差分数组的构造
python
def make_diff(nums: list[int]) -> list[int]:
    if not nums:
        return []
    return [nums[0]] + [nums[i] - nums[i - 1] for i in range(1, len(nums))]
展开差分数组的恢复
python
def restore(diff: list[int]) -> list[int]:
    total, answer = 0, []
    for delta in diff:
        total += delta
        answer.append(total)
    return answer

区间加法的两个边界：l处增加、r＋1处撤销

对从0开始的闭区间[l,r]整体加v，只需要：

python
diff[l] += v       # 从l开始增加v
diff[r + 1] -= v   # 从r之后取消这次增加

区间内部的相邻两项都加了v，作差时两个v互相抵消，因此内部差分不变。只有进入区间时增加、离开区间时撤销，这两个位置需要修改。

如果r已经是末尾，可以跳过范围外的撤销；也可以预先多开一个哨兵位置，统一保存r+1的撤销事件，恢复时只输出原数组的n项。哨兵是额外存储位置，不是新增的数据元素。

单次更新只记两个边界是O(1)，但获得所有修改后的值，还需要一次O(n)累加恢复。差分适合先批量更新、最后统一取结果；如果更新与查询频繁交错，就不能把两种操作都算作O(1)。

1109航班预订统计：从编号转换到差分下标

1109. 航班预订统计完整力扣题面 ↗

题面原文节选

这里有 n 个航班，它们分别从 1 到 n 进行编号。
示例输入与输出bookings=[[1,2,10],[2,3,20],[2,5,25]], n=5 → [10,55,45,25,25]

任务与约束：每条[first,last,seats]为包含两端的航班范围增加seats个座位，求所有航班最终预订座位数。n与预订数为1～2×10⁴，1≤first≤last≤n，seats为1～10⁴。

每条预订[first,last,seats]表示这一段航班都增加seats个座位，正好是一段相同增量。

航班编号从1开始，数组下标从0开始，闭区间应转换为[first-1,last-1]。因此增加的位置是first−1，撤销的位置是last，不是在两个位置上都减1。

python
def flight_bookings(bookings: list[list[int]], n: int) -> list[int]:
    diff = [0] * (n + 1)  # 最后一格为撤销更新的哨兵，不输出。
    for first, last, seats in bookings:
        diff[first - 1] += seats  # 1-based航班first映射到0-based first-1。
        diff[last] -= seats       # last之后的0-based位置正好是last。
    answer, running = [], 0
    for i in range(n):
        running += diff[i]
        answer.append(running)
    return answer

交互演示：航班预订统计

展开逐步演示

三条预订叠加后，差分为[10,45,-10,-20,0,-25]。累加前五项得到[10,55,45,25,25]。最后一格−25使累计量归零，表示更新全部结束，不对应第6个航班。

设m为预订数、n为航班数，记录m次更新花O(m)，恢复n项花O(n)，所以总时间为O(m+n)，额外差分空间为O(n)；结果数组还需要O(n)输出空间。直接逐条修改区间最坏需要O(mn)。这里消除的是重叠预订带来的重复逐项修改，最后输出n项的工作仍然保留。

56合并区间：边界思想可以复用，区间含义需要区分

56. 合并区间完整力扣题面 ↗

题面原文节选

请你合并所有重叠的区间，并返回 一个不重叠的区间数组，该数组需恰好覆盖输入中的所有区间 。
示例输入与输出[[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]；[[1,4],[4,5]] → [[1,5]]

任务与约束：合并重叠区间，输出覆盖相同范围且互不重叠的区间集合。区间数为1～10⁴，0≤start≤end≤10⁴；区间包含端点。

做完航班预订统计后，再看到合并区间，我首先想到的也是记录开始和结束的位置。排序合并当然也能做，不过当时更想弄清楚的是：如果直接按坐标把这些事件存入数组，能否省去排序，让处理成本更低一些？

因此这里继续保留开始、结束事件的思路，并把坐标跨度也算进复杂度。不过，航班是离散的数组位置，56处理的是数轴上的闭区间。这一区别会影响撤销事件放在哪里。

[1,2]与[2,4]共享端点2，应合成[1,4]；[1,2]与[3,4]之间还有空隙，必须保留为两段。没有未覆盖的整数点，并不等于数轴上没有间隙。

如果直接按整数格使用diff[l]+=1、diff[r+1]-=1，再把连续正值格子输出成一个区间，那么[1,2]在3处撤销，[3,4]也在3处开始，两件事会抵消，错误地得到[1,4]。这是把离散覆盖规则搬到数轴区间时产生的语义问题。

分开保存开始和结束，同一坐标先开始、再结束

用starts[x]记录在x开始的区间数量，用ends[x]记录在x结束的区间数量。扫描线就是按坐标顺序处理这些事件，同时维护当前仍覆盖着的区间数量count。

处理坐标x时，先加入开始事件，再移除结束事件：

  1. 原先count为0且这里有开始事件，记录一段新的起点。
  2. 加入starts[x]，再减去ends[x]。
  3. 结束处理后count回到0，就在x关闭这一段。

对[1,2]与[2,4]，到2之前count为1，在2先加1再减1，仍为1，覆盖继续。对单点[2,2]，同一坐标也先打开、再关闭，能正确保留这个点。

python
def merge_dense_events(intervals: list[list[int]]) -> list[list[int]]:
    if not intervals:
        return []
    low = min(left for left, _ in intervals)
    high = max(right for _, right in intervals)
    starts, ends = [0] * (high - low + 1), [0] * (high - low + 1)
    for left, right in intervals:
        starts[left - low] += 1
        ends[right - low] += 1  # 保留两种事件，不能提前净额抵消。
    count, begin, result = 0, None, []
    for offset in range(len(starts)):
        x = low + offset
        if count == 0 and starts[offset] > 0:
            begin = x
        count += starts[offset]  # 闭区间：同坐标先处理开始。
        count -= ends[offset]    # 再处理结束，接触点会保持连通。
        if count == 0 and ends[offset] > 0:
            result.append([begin, x])  # [x,x]单点也能正确开启并关闭。
    return result

如果只存一张净变化表diff[l]+=1、diff[r]-=1，单点区间的两个事件会直接抵消，无法再看出这个点曾被覆盖。分开保存starts和ends，是为了保留同一坐标内的事件顺序。这属于边界增量思想的应用，但不等于前面的相邻差分定义。

密集数组的成本取决于区间数和坐标跨度

设区间数为n，实际扫描的坐标跨度为U=max(end)-min(start)+1。按下标放事件不需要排序，记录事件O(n)，扫描坐标O(U)，所以密集事件数组为O(n+U)时间、O(U)辅助空间，另计至多O(n)的输出。

本题坐标限制在0到10⁴之间，确实可以尝试密集数组。当推广到跨度很大、实际端点很少的数据时，可以改为只记录2n个事件，再排序扫描。

展开稀疏事件排序扫描
python
def merge_sparse_events(intervals: list[list[int]]) -> list[list[int]]:
    events = [(left, 1) for left, _ in intervals]
    events += [(right, -1) for _, right in intervals]
    events.sort(key=lambda event: (event[0], -event[1]))  # 同坐标+在-之前。
    count, begin, result = 0, None, []
    for x, delta in events:
        if delta == 1:
            if count == 0:
                begin = x
            count += 1
        else:
            count -= 1
            if count == 0:
                result.append([begin, x])
    return result

同坐标的开始事件排在结束事件前，继续保留闭区间语义。这种写法节约了跨度U对应的空间，但排序需要O(n log n)时间。Python字典虽然保留插入顺序，并不会按坐标大小自动排序。

方案时间空间口径适用条件
密集开始/结束数组O(n+U)O(U)辅助，O(n)输出值域较小，能接受扫描所有坐标
稀疏事件排序O(n log n)O(n)只处理端点，不承担大跨度成本
区间按左端排序后合并O(n log n)本文Python实现O(n)不依赖整数小值域，代码更简短
对照：按左端排序合并区间
python
def merge_sorted(intervals: list[list[int]]) -> list[list[int]]:
    result = []
    for left, right in sorted(intervals):
        if not result or left > result[-1][1]:
            result.append([left, right])
        else:
            # 相等端点也重叠，不能用>=判为分离。
            result[-1][1] = max(result[-1][1], right)
    return result

已经按左端排序的输入可以直接O(n)合并；上表讨论的是需要排序的输入。哪种方法更合适，要同时看n与U，不能给密集数组凭空加上排序成本，也不能省略它扫描坐标的成本。

补充：如果仍想用单张净差分表，怎样保留间隙

可以用偶数位置表示原坐标、奇数位置表示相邻整数之间的空隙，把闭区间[l,r]覆盖到[2l,2r]，在2r+1撤销。这样[1,2]和[3,4]之间留有未覆盖的间隙，而共享端点仍会连在一起。关键是同时定义坐标、间隙和撤销位置，仅把两个端点乘2还不够。

python
def merge_scaled_diff(intervals: list[list[int]]) -> list[list[int]]:
    if not intervals:
        return []
    low = min(left for left, _ in intervals)
    high = max(right for _, right in intervals)
    diff = [0] * (2 * (high - low) + 2)
    for left, right in intervals:
        diff[2 * (left - low)] += 1
        diff[2 * (right - low) + 1] -= 1  # 必须有+1，只将两端乘2无效。
    running, begin, result = 0, None, []
    for i, delta in enumerate(diff):
        old = running
        running += delta
        if old == 0 and running > 0:
            begin = low + i // 2
        if old > 0 and running == 0:
            result.append([begin, low + (i - 1) // 2])
    return result

差分与前缀和的更新、查询分工

差分保存变化量，通过两个边界修改表示整段增加；前缀和保存累计量，通过两个累计值相减查询区间和。对差分进行前缀累加可以恢复原数组，但两种操作的用途不同：1109是在批量更新，303是在重复查询。

另外，438中的字符频次也可以比较两张表的差，但那是字符计数之间的差，不是相邻数组元素的差。判断一个变量是否属于本篇的差分数组，要看它保存的含义，不能只看它是否叫diff。
