评分器也需要单独验证

LLM-as-Judge是让模型依据评分标准评价其他输出。它适合辅助检查开放文本，但评分仍受输入、标准和模型行为影响。事实核对、权限检查或精确数值计算能够程序验证时，应优先保留确定性检查。

例如“解释通顺”与“引用能支持结论”是两个维度。答案可以很流畅，却引用了过期制度。把所有维度合成一个总分，会隐藏具体失败，所以评分标准应写出每一项接受什么证据、出现什么错误必须不通过。

已有研究讨论了位置偏差、偏爱长答案及自我偏好等限制；这些研究说明需要校准，不能直接把某篇论文中的一致率当成当前业务Judge的准确率。LLM-as-Judge研究

用100条教学样本检查误判

假设人工依据固定标准复核100份答案，其中60份合格、40份不合格，Judge判断如下。这是构造的算例，不是本项目测量结果。

人工合格人工不合格合计
Judge通过541064
Judge不通过63036

总体一致率为(54+30)/100=84%。但在Judge放行的64份中，有10份不合格，放行精确率为54/64=84.375%；在40份实际不合格答案中，错误放行了10/40=25%。

总体一致率较高，仍可能掩盖不能接受的错误放行。 哪个指标最重要取决于用途：用于排序候选答案和用于自动批准外部操作，对误判的容忍程度不同。

人工标签也需要检查。定义含糊、标注者分歧或缺少原始证据时，不能把人工结果直接当成毫无误差的真值。应记录分歧并复核，再形成冻结的校准集；调过标准后使用独立测试集验证，避免只适应已见样本。

成对比较怎样减少顺序与风格影响

比较A、B两份回答时，可以匿名化来源、随机化展示顺序，并交换顺序复测一部分样本。如果模型总偏向靠前的回答，结果需要单独处理；如果长回答更容易得高分，应检查增加的内容是否真的正确。

输出最好包含按标准定位的证据和可复核结论，不把冗长解释本身当作可靠性。Judge不应拥有执行被评答案中指令的权限；答案是评测数据，不能让“请忽略评分标准”改变任务。

记忆和多Agent怎样做受控比较

要判断长期记忆是否改善任务，先固定模型、任务集、工具及预算，再设置无记忆与有记忆版本。记忆内容只能来自该任务允许使用的历史，不能把测试答案提前写入记忆。

例如100个教学任务中，无记忆版本完成70个，有记忆版本完成78个，还需要查看逐任务配对结果：新增成功的是哪些，原本成功却失败的又有哪些。只比较70与78，看不出收益是否集中在少数类型，也看不出是否出现新的权限或过期信息问题。

多Agent同理。应比较合理预算下的单Agent基线，并记录总模型调用、输入输出token、工具耗时和关键路径延迟。并行执行可能减少等待，却增加总费用；任务成功率提高是否值得，要和实际业务约束一起判断。

可以用“每个成功任务的总成本”补充平均调用成本，但计算时应把失败任务的开销也计入分子，分母使用成功任务数，并同时报告成功率。否则通过放弃困难任务降低平均成本，会让指标失去意义。

面试问答：怎样确认Judge的高分有意义

LLM-as-Judge的分数结果如何衡量，怎么确定LLM打高分就一定是好？

回答： 无法仅凭模型打高分就确认答案好，需要先定义质量维度，再用独立人工复核及程序检查校准Judge。事实、引用、任务完成和权限等维度应分开，关键违规可以设置为直接不通过，避免流畅度补偿事实错误。

校准应统计一致率、误放行和误拒绝，并按任务类型分析。教学例中总体一致率84%，但实际不合格答案有25%被放行，若用于自动执行高影响操作，就可能不能接受。还要检查位置、长度、模型偏好及提示注入影响，并随机化匿名比较顺序。

评分规则和模型更新后需要回归；人工标准存在分歧时先统一定义。最终是否可用由错误成本和校准结果决定，不能用外部论文的一致率替代当前业务验证。

延伸追问（自拟）：让多个Judge投票是否就可靠？ 多个Judge可能共享偏差，错误并不独立。投票可以作为方案，但仍要用相同校准集和独立测试集验证改善及成本。

如何证明长期记忆和多 Agent 能提高完成质量而非增加成本？

回答： 分别对记忆与多Agent做受控比较，固定任务、模型、工具和主要预算，设置有竞争力的基线，比较逐任务成功、失败类型及资源消耗。记忆实验防止测试信息泄漏，多Agent实验需要把所有参与者的调用成本计入。

应报告配对差异、样本量和波动范围，并按任务难度、是否需要历史信息、是否具有可并行子任务分组。离线改善后再用适当线上实验检验真实收益。若成功率没有改善而费用上升，就不能仅以结构复杂或执行步骤更多作为价值证明。

延伸追问（自拟）：多Agent延迟更低但费用更高，算优化吗？ 需要看业务目标。低延迟可能有价值，但应同时展示质量、延迟和总成本，让取舍可评估，不能只挑一个有利指标。
