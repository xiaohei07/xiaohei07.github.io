自回归生成每一步仍然要用到历史

前面的注意力算例说明，新位置会关注历史位置的Key与Value。自回归生成按已有前缀预测下一个Token，再把新Token接回输入，继续预测。

在固定权重、推理模式及兼容位置设置下，因果模型的历史位置表示不依赖后来生成的Token，因此可以缓存各层已经算出的K与V。KV Cache保存的是中间表示，不是最终答案文本，也不是知识库。Transformers缓存机制

三Token提示怎样接到后续生成

假设提示为[a,b,c]，模型接下来生成d、e：

阶段本次处理的Token缓存变化本次得到什么
Prefilla、b、c建立各层3个位置的K/V用最后位置的logits选择d
第一次Decoded追加d的K/V，长度变4让d关注历史，预测e
第二次Decodee追加e的K/V，长度变5继续预测下一个Token

Prefill处理已有提示，Decode逐步处理新生成Token。 选择出d的瞬间，d还没有在这条序列的下一次前向计算中产生各层K/V；它在第一次Decode被输入后才加入缓存。把“生成出的Token数”和“已经处理并缓存的Token数”混在一起，会使显存和时序推演差一位。

历史Q通常不需要作为同样用途的长期缓存，因为下一步主要需要新位置的Q，与历史K计算匹配，再组合历史V。缓存省去了历史K/V等重复前向计算，但新Token仍要经过模型，并读取与使用历史缓存。

KV净荷为什么与长度和KV头数有关

假设每层具有相同的KV结构，各请求缓存长度相同，KV净荷可估算为：

MKV=2LBTHkvDhsM_{\mathrm{KV}}=2LBT H_{\mathrm{kv}}D_hs

L为层数，B为batch大小，T为每条序列缓存长度，H_kv为KV头数，D_h为每头维度，s为每个元素的字节数。系数2来自K与V。

取教学配置L=6、B=2、T=1024、H_kv=4、D_h=64、s=2：

2×6×2×1024×4×64×2=12 582 912字节=12MiB2\times6\times2\times1024\times4\times64\times2 =12\,582\,912\text{字节}=12\text{MiB}

把长度翻倍，净荷变为24MiB；保持其他条件而把KV头数从4改为8，也变为24MiB。MiB以2²⁰字节计算，不能与十进制MB混用。

GQA（分组查询注意力）允许多个查询头共享一组KV头；MQA使用单个KV头供查询头共享。估算应代入实际KV头数，而非机械使用查询头数。不同层有不同窗口或头结构时，需要按层求和。GQA论文对头数关系的说明

这只是缓存数值的净荷，未包含模型权重、分配碎片、页管理信息、临时缓冲及其他运行时开销。量化缓存还可能有缩放参数等附加信息，不能只把s除以2就当成实测显存。

长上下文为什么仍然影响速度

单个新查询与更长历史K/V交互，需要处理更多历史信息。标准稠密注意力的Prefill具有二次规模的注意力计算关系；使用优化内核可以减少中间矩阵显存或访存，并不自动把所有计算复杂度变成线性。

Decode在小batch时常受到权重和缓存访存等因素限制，但实际瓶颈取决于硬件、模型及调度。应分别测首Token延迟、后续Token间隔和整体吞吐，不能用一个“每秒Token数”说明所有体验。

连续批处理可以在请求完成后接入新请求，提高资源利用；分页缓存有助于管理不同长度序列。具体实现仍需处理容量、淘汰、取消及长请求公平性，本文不把这些调度能力推定为任意服务框架都已经配置。

缓存复用需要相同的计算前提

跨请求复用前缀缓存，需要确认模型权重、Token前缀、位置与影响计算的配置兼容。视觉输入或其他隐藏条件不同，也可能让相同文本不再对应相同缓存。

历史上下文被修改后，不能只在尾部继续接缓存。位置变换、截断和滑动窗口也要按实现处理。训练时为了反向传播保存的激活，又与这里的推理KV Cache不同，不能直接用推理缓存方案替代训练计算图。

面试问答：KV Cache的作用

是否了解 KV Cache？它在大模型推理过程中起到什么作用？

回答： 在自回归因果模型推理中，历史Token在各层的K、V可以缓存，后续只计算新Token相关表示，并让新查询与缓存交互，减少历史前缀的重复计算。它提升逐步生成效率，但仍消耗与层数、并发、长度和KV头数相关的内存。

Prefill先处理提示并建立缓存，利用最后位置预测首个新Token；随后Decode将该Token输入，追加其K/V，再预测下一个。标准简化净荷为2LBT H_kv D_hs，GQA应使用实际KV头数。本文配置计算为12MiB，这不包含权重和运行时开销。

长上下文仍增加缓存读取及注意力计算，不能承诺每一步耗时恒定。复用还要求模型、前缀、位置及计算配置兼容；上下文修改或权重更新后，旧缓存不能任意继续使用。

延伸追问（自拟）：KV Cache是不是越大越好？ 它使系统能保留更长历史或更多并发，也增加内存和访存压力。应结合任务需要、截断策略和调度限制选择容量，并分别衡量质量与吞吐。
