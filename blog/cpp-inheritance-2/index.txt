1d:T4b1c,<span id="一基类和派生类的默认成员函数" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-一基类和派生类的默认成员函数">（一）基类和派生类的默认成员函数：</h3>
<p>从 C++11 起，通常讨论的特殊成员函数有六类：</p>
<ul>
<li>默认构造函数</li>
<li>析构函数</li>
<li>拷贝构造函数</li>
<li>移动构造函数</li>
<li>拷贝赋值运算符</li>
<li>移动赋值运算符</li>
</ul>
<p>编译器是否隐式声明这些函数、何时定义它们，各有条件。例如，声明了其他构造函数后，编译器不会再自动提供无参默认构造函数；用户声明复制操作或析构函数，也会影响移动操作的生成。基类或成员不支持所需操作时，默认化的特殊成员还可能被定义为删除的函数，不能调用。取地址运算符不属于这六类特殊成员。</p>
<p>分类与条件见 <a href="https://eel.is/c++draft/special" rel="noopener noreferrer">特殊成员函数</a>、<a href="https://eel.is/c++draft/class.default.ctor#1" rel="noopener noreferrer">默认构造函数</a>和<a href="https://eel.is/c++draft/class.copy.ctor" rel="noopener noreferrer">复制/移动构造函数</a>。下面仍围绕原来的构造、析构、拷贝和赋值示例展开，移动操作暂不展开。</p>
<span id="1-构造函数" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-1-构造函数">1. 构造函数：</h4>
<p>建立一个类层次后，通常创建某个派生类的对象，该对象也包括使用基类的数据和函数。</p>
<p>c++提供一种机制，在创建派生类对象时用指定参数调用基类的构造函数来初始化派生类继承基类的数据。</p>
<p>此时，派生类的构造函数声明为：</p>
<p><em><strong>派生类构造函数(变元表)：基类(变元表),对象成员1(变元表), ……. , 对象成员n(变元表) { 函数体}</strong></em></p>
<p>派生类的构造函数必须调用基类的构造函数初始化基类的那一部分成员，如果基类没有默认的构造函数，则必须在派生类构造函数的初始化列表阶段显式调用。</p>
<p>构造函数的执行顺序为基类->派生类。</p>
<span id="2-析构函数" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-2-析构函数">2. 析构函数：</h4>
<p>因为在派生类的构造函数调用了基类的构造函数，因此其析构函数也需要对派生类对象和基类对象都进行清理。该任务的完成由各自的析构函数完成。</p>
<p>析构函数的执行顺序为派生类->基类。</p>
<p>注意：不要在派生类中主动调用基类的析构函数，因为派生类的析构函数在被调用完成后会自动调用基类的析构函数清理基类成员。以此来保证派生类对象先清理派生类成员再清理基类成员。</p>
<span id="3-拷贝构造函数" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-3-拷贝构造函数">3. 拷贝构造函数：</h4>
<p>自定义派生类拷贝构造函数时，如果要复制基类部分，应在初始化列表中写 <code>Base(other)</code>。下面的 <code>Son(const Son&#x26; s):Father(s)</code> 就是这种写法，<code>Father</code> 的引用参数会绑定到 <code>s</code> 中的基类子对象。若省略该初始化项，基类部分会尝试默认初始化，而不会自动复制。</p>
<p>编译器隐式定义的拷贝构造函数则会依次复制基类子对象和非静态数据成员。<a href="https://eel.is/c++draft/class.copy.ctor#15" rel="noopener noreferrer">规则依据</a></p>
<span id="4-赋值操作符重载" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-4-赋值操作符重载">4. 赋值操作符重载：</h4>
<p>自定义派生类的 <code>operator=</code> 时，通常显式调用 <code>Base::operator=(other)</code> 来复制基类部分，再处理派生类自己的成员。编译器隐式定义的赋值运算符会自动处理这些基类和成员。</p>
<p>基类与派生类的赋值运算符同名会产生隐藏，但一次普通赋值不会因此自动无限递归。只有在自己的函数体中又调用了自己，才会递归；下面用 <code>Father::operator=(s)</code> 明确调用基类版本。<a href="https://eel.is/c++draft/class.copy.assign#12" rel="noopener noreferrer">规则依据</a></p>

<span id="二基类和派生类的赋值转换" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-二基类和派生类的赋值转换">（二）基类和派生类的赋值转换：</h3>
<p>以下讨论基类可访问且没有二义性的情况，例如下面的公有单继承。派生类对象可以用来初始化或赋值给基类对象，也可以通过基类指针、引用访问：</p>
<ul>
<li>
<p>基类的对象：</p>
<p>因为派生类中包括基类的所有数据成员，赋值时将这部分赋值给基类即可完成赋值转换。</p>
</li>
<li>
<p>基类的指针：</p>
<p>将派生类对象的地址转换为基类指针，得到的是该对象中基类子对象的地址；转换时可能调整地址，不能假定它总在整个对象的开头。通过基类指针使用的是基类接口。</p>
</li>
<li>
<p>基类的引用：</p>
<p>基类引用绑定到派生类对象中的基类子对象，通过基类接口操作原对象，不会另建一个基类对象。</p>
</li>
</ul>
<p>把派生类对象按值复制到基类对象，会只保留基类部分，通常称为对象切片。上面的指针转换和引用绑定仍指向原来的对象，不发生这种按值切片。<a href="https://eel.is/c++draft/conv.ptr#3" rel="noopener noreferrer">指针转换规则</a>与<a href="https://eel.is/c++draft/class.derived.general" rel="noopener noreferrer">引用绑定说明</a>可供对照。</p>
<p>基类对象不会仅凭继承关系自动变成派生类对象。下面把 <code>pa1</code> 转回 <code>B*</code>，前提是 <code>pa1</code> 确实指向 <code>b1</code> 的基类子对象；不能把任意 <code>A*</code> 都这样使用。类型前提不满足的向下转换可能产生未定义行为，详见 <a href="https://eel.is/c++draft/expr.static.cast#10" rel="noopener noreferrer">基类指针向下转换规则</a>。</p>

<span id="三单继承和多继承" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-三单继承和多继承">（三）单继承和多继承：</h3>
<span id="1-基本内容" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-1-基本内容">1. 基本内容</h4>
<p>单继承是指派生类只有一个直接基类，多继承是指一个派生类拥有两个或多个直接基类。</p>
<p>继承的格式详见一。</p>
<p>多继承完成了更多的代码复用，并使得复用的程度更深。</p>
<p>多继承时，派生类构造函数调用多个基类的构造函数，析构函数同理，构造顺序按照声明继承的顺序进行，析构则相反顺序。</p>
<p>若不同继承基类有同名成员，直接访问会造成命名冲突，此时需要在名字前加上类名和域解析符::，显式指定使用哪个类的成员，消除二义性。</p>

<span id="2-菱形继承" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-2-菱形继承">2. 菱形继承</h4>
<p>多继承内存在着许多问题，例如二义性和代码冗余，下面通过菱形继承说明。</p>
<p>菱形继承是多继承的一种特殊情况。</p>
<p><img src="https://s1.ax1x.com/2023/04/04/pp4VDQs.png" alt="20_C++菱形继承" width="800" height="204" loading="lazy" decoding="async" referrerpolicy="no-referrer"></p>
<p>如图，在非虚继承下，类 B 和类 C 分别继承类 A，类 D 再继承 B、C，一个 D 对象中会有两个不同的 A 子对象。它们分别构造和析构，各自保存一份 A 的数据。如果设计只需要共享一份 A，这种结构就会保存重复数据。<a href="https://eel.is/c++draft/class.mi#4" rel="noopener noreferrer">规则依据</a></p>
<p>同时，因为BC都继承了A的成员，D在继承BC时会存在同名的数据成员，无法直接通过变量名读取相应的值，产生了二义性，此时需要通过域解析符::进行区分，非常麻烦。</p>
<p>一般情况下，不建议设计多继承和菱形继承，因为情况比较复杂。</p>

<span id="3-菱形继承的解决虚继承" class="legacy-anchor" aria-hidden="true"></span><h4 id="section-3-菱形继承的解决虚继承">3. 菱形继承的解决：虚继承</h4>
<p>为了避免以上的情况出现，我们需要通过虚继承的方式解决问题——需要虚基类。</p>
<p>虚基类不是在声明基类时声明的，而是声明派生类时指定继承方式声明的。</p>
<p>虚继承是指在继承的基类前添加关键字virtual，格式为：</p>
<p><em><strong>class 派生类名: virtual 继承方式 基类名</strong></em></p>
<p>此时的基类被称为虚基类，也就是被虚继承的基类（不是抽象类！！）</p>
<p>在菱形继承中，当BC对A都进行虚继承后，D对BC进行多继承时，重复的变量将只会保留一份。这是因为，D不仅对直接基类进行初始化，也会对虚基类初始化，且只有一次——c++编译器只调用最后的派生类对基类的构造函数调用，忽略其他派生类对虚基类的构造函数调用，避免了对基类数据成员的重复初始化。</p>
<p>在这里，B 和 C 共享同一个 A 虚基类子对象，因此从 A 继承的那个成员不再因两份 A 而产生二义性。B、C 自己声明的其他同名成员仍可能需要用类名限定。</p>
<p>此处暂不介绍虚继承的内存模型，以后有需要单开一篇进行介绍。</p>
