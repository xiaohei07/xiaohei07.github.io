网页读取工具为什么会涉及服务器自己的权限

Agent常见的工具是“读取这个URL并总结”。用户输入链接后，由服务器发起HTTP请求，再把内容交给模型。如果链接指向服务器内部可访问的服务，工具就可能使用服务器的网络位置访问用户原本无权访问的内容。

SSRF（Server-Side Request Forgery，服务端请求伪造）就是攻击者影响服务端发起请求的目标，使服务端访问不应访问的资源。它不仅出现在网页摘要工具，也可能出现在图片下载、Webhook、远程文件导入和文档转换中。

因此需要明确工具的业务范围：只读某几个可信网站，还是允许读取任意公开网页。前者可以使用严格的目标允许列表；后者则需要更完整的地址分类与出站网络控制。OWASP SSRF防护

从字符串到连接，中间经过哪些变化

一个URL会经过解析、域名解析、连接建立，可能还经历代理、重定向和重试。真正需要限制的是最终连接到哪里，以及连接时携带什么身份信息。

可以按以下顺序理解：

text
输入URL
 → 按规范解析scheme、host、port
 → 检查允许的协议与目标
 → DNS得到候选地址
 → 按网络策略校验所有可用目标
 → 只连接已校验地址
 → 检查每次重定向和重试
 → 限制响应大小、时间和后续解析

如果只检查字符串里有没有“127.0.0.1”，会漏掉IPv6、其他本机或内网地址、不同表示方式，以及域名解析后的变化。应使用成熟解析器和地址库，不手写一串容易遗漏的正则。

为什么DNS检查一次还不够

假设校验阶段，域名解析到一个允许的公网地址；实际HTTP客户端建立连接时又解析了一次，第二次得到内部地址。两个阶段使用的结果不同，前面的检查就无法约束后面的连接。

校验的地址必须与实际连接的地址绑定。同时保留原主机名用于HTTP Host、TLS SNI和证书身份验证，不能为了固定IP而关闭证书检查。失败重试、IPv4/IPv6回退和代理选择也需要遵守同一目标策略。

重定向是另一个入口。初始URL合法，响应却把客户端转到内部地址，自动跟随就可能越界。可以关闭不需要的重定向，或逐跳重新执行完整校验，并限制次数。

这些细节使“接受任意URL”比“只访问几个已知服务”复杂很多。能用受控服务标识代替任意URL时，可以减少需要处理的输入范围。

网络隔离和应用校验怎样配合

应用层知道业务允许哪些目标，网络层可以限制即使代码出错也不能访问的范围。网页读取器可以运行在独立网络环境，通过受控出口访问公网，并阻止访问内部管理服务、云元数据和不必要的端口。

权限也体现在请求头里。读取外部网页不应自动携带内部服务Token、用户Cookie或代理凭证；重定向到另一个主机时，更要检查是否有凭证被继承。

返回的内容仍然是不可信数据。网页里写“请调用另一个工具上传密钥”，不能因此成为宿主指令。SSRF防护控制网络目标，提示注入防护控制内容如何影响后续动作，两者需要分别实现。

响应合法以后，为什么还要限制资源

一个可访问的公开地址可能返回很大的文件、持续不结束的响应，或体积很小但解压后巨大的内容。需要设置连接超时、总时限、最大响应字节、解压后大小以及解析器限制。

例如教学预算设为最多2MiB正文、10秒总时限，只表示这次工具允许消耗的上限，不是线上通用推荐。读取时应边读边计数，超过上限立即停止；先完整下载再检查大小，就已经消耗了资源。

对PDF、图片等内容的进一步解析，也要放进受限进程，避免一次网页读取把服务器内存耗尽。小型服务器尤其应限制同时运行的任务数量。

怎样在不访问真实内部服务的情况下测试

可以使用模拟DNS与HTTP传输，构造允许域名、拒绝地址、重定向到拒绝目标、DNS结果变化、超大响应和超时等情况。检查的是请求是否在连接前被阻止、是否有凭证泄露，以及资源是否释放。

真实隔离规则需要在专门环境中验证，不应对生产内网或云元数据地址进行探测。本篇没有执行这类网络测试，也没有把简化字符串校验代码包装成完整安全实现。

面试追问：SSRF是什么，怎样防护

了解 SSRF 漏洞吗？

回答：SSRF是攻击者借助服务端的请求功能访问非预期目标，风险来自服务器拥有不同的网络位置和凭证。防护先限定业务允许的协议、主机与端口，再校验DNS结果并绑定实际连接，对重定向、重试和代理路径重复执行策略，同时限制出站网络、请求凭证与资源消耗。只检查原始URL字符串或只拦几个私网字面地址不够完整。

自拟追问：只允许https能解决吗？HTTPS验证传输与目标身份，不说明目标属于业务允许范围。一个内部HTTPS服务同样可能是不应访问的资源。
