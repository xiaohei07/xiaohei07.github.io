29:T2168,<p>在浏览器里打开一篇文章，看起来只做了一件事：输入网址，然后等页面出来。不过网页里的HTML、样式、脚本和图片通常要分别获取。后面点击“发送反馈”，浏览器又会发出新的请求，这次服务器返回的是JSON数据。</p>
<p>先把这两个过程分清，后面再看Next.js和FastAPI的分工就会容易一些。下面用本站的文章与反馈举例，请求中的内容是教学数据。</p>
<span id="section-一url怎样确定要访问的资源" class="legacy-anchor" aria-hidden="true"></span><span id="section-url怎样确定要访问的资源" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-一url组成dns解析与连接建立">一、URL组成、DNS解析与连接建立</h2>
<p>例如<code>https://blog.07xiaohei.com/blog/python-slices/</code>，<code>https</code>指定协议，<code>blog.07xiaohei.com</code>是主机名，<code>/blog/python-slices/</code>是路径。HTTPS默认使用443端口，所以网址里通常不用再写<code>:443</code>。查询参数放在<code>?</code>后面；<code>#</code>后面的片段用于定位页面内部位置，一般不会随HTTP请求发给服务器。</p>
<p>浏览器需要先确定域名对应的地址。<strong>DNS负责把域名解析为可访问的地址信息</strong>；浏览器随后建立连接，再按协议交换数据。HTTPS还要建立经过身份验证的加密连接，浏览器会检查证书是否适用于访问的域名。DNS、连接、TLS、HTTP属于不同层次，排错时也应分别确认。</p>
<p>连接不一定每次重新建立，DNS结果也可能被缓存。实际访问时，浏览器可以复用已有连接和DNS缓存，从对应阶段继续处理。HTTP/1.1和HTTP/2通常使用TCP；HTTP/3使用基于UDP的QUIC。本文用HTTP/1.1的文本形式展示报文，便于阅读，不代表实际线上协议一定是这个版本。</p>
<span id="section-二请求和响应各自包含什么" class="legacy-anchor" aria-hidden="true"></span><span id="section-请求和响应各自包含什么" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-二http请求与响应的组成">二、HTTP请求与响应的组成</h2>
<p>读取文章的简化请求如下：</p>
<div class="code-block"><div class="code-toolbar"><span>http</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-http">GET /blog/python-slices/ HTTP/1.1
Host: blog.07xiaohei.com
Accept: text/html
</code></pre></div>
<p><code>GET</code>是方法，说明当前要取得资源；路径指定资源；<code>Host</code>让服务器知道要处理哪个站点。响应可以写成：</p>
<div class="code-block"><div class="code-toolbar"><span>http</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-http">HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Cache-Control: no-cache

&#x3C;!doctype html>
&#x3C;html>...&#x3C;/html>
</code></pre></div>
<p><strong>状态码描述请求结果，响应头补充内容类型与缓存规则，空行之后的响应体承载实际内容</strong>。<code>Content-Type</code>帮助浏览器解释这些字节；同一个服务器可以返回HTML、JSON、图片或其他格式。<a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview" rel="noopener noreferrer">MDN的HTTP说明</a>介绍了这套请求与响应模型。</p>
<p>读取HTML后，浏览器构建DOM，解析CSS并计算布局，再进行绘制；脚本还可能修改页面或继续获取数据。这些工作会交错进行，图片和脚本也可能并行下载。把所有资源下载时间相加，并不能直接得到页面总加载时间。</p>
<span id="section-三从读文章到提交反馈数据在哪里变了" class="legacy-anchor" aria-hidden="true"></span><span id="section-从读文章到提交反馈数据在哪里变了" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-三反馈提交中的json数据库记录与回执">三、反馈提交中的JSON、数据库记录与回执</h2>
<p>假设给文章提交一条“切片例子建议补充边界说明”的反馈，浏览器把输入组织成JSON：</p>
<div class="code-block"><div class="code-toolbar"><span>http</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-http">POST /api/v1/feedback HTTP/1.1
Content-Type: application/json
Origin: https://blog.07xiaohei.com

{"content_id":"python-slices","kind":"question","message":"切片例子建议补充边界说明"}
</code></pre></div>
<p>JSON只是数据的文本表示，后端还需要检查其中的字段。例如，<strong>content_id需要经过格式校验和内容登记查询，才能确认它指向已发布文章</strong>；Origin说明请求声称来自哪个源，用户身份则要通过单独的认证机制判断。</p>
<p>本站中，Nginx把<code>/api/</code>请求转给FastAPI。通过校验并成功提交数据库事务后，API返回201，以及新反馈的ID和<code>pending</code>状态。前端读取回执，再把页面上的提示改成发送成功。正文页面早已存在，这次更新不需要重新构建文章HTML。</p>
