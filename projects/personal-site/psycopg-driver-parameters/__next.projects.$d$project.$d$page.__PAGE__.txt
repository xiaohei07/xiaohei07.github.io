2f:T2075,<p>SQLAlchemy已经能写查询，为什么依赖里还有psycopg？因为Python中描述数据库操作，与真正连接PostgreSQL、传送参数、读取响应之间，还需要驱动。本站使用psycopg3完成这一层工作。</p>
<span id="section-一一次查询经过哪些对象" class="legacy-anchor" aria-hidden="true"></span><span id="section-一次查询经过哪些对象" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-一sqlalchemypsycopg与postgresql的调用关系">一、SQLAlchemy、psycopg与PostgreSQL的调用关系</h2>
<p><a href="/images/website-series/driver.svg" target="_blank" rel="noopener noreferrer" class="article-image-link" aria-label="查看图片原图：业务对象、SQLAlchemy、psycopg和PostgreSQL之间的职责划分"><img src="/images/website-series/driver.svg" alt="业务对象、SQLAlchemy、psycopg和PostgreSQL之间的职责划分" width="1100" height="425" loading="lazy" decoding="async" referrerpolicy="no-referrer"></a></p>

<div class="code-block"><div class="code-toolbar"><span>text</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-text">业务代码中的Session/查询表达式

<p><strong>Pydantic解析与校验输入，SQLAlchemy组织查询和事务，psycopg完成连接、参数适配与数据库通信</strong>。这三个库分别处于输入处理、数据访问组织和驱动通信的位置。<code>postgresql+psycopg://...</code>中的前半部分指定数据库与驱动组合，连接信息来自私有配置，不能写进浏览器代码。</p>
<p>本站没有额外使用<code>psycopg_pool</code>，连接池由SQLAlchemy管理。因此，连接池参数主要从SQLAlchemy的Engine配置中查看。</p>
<span id="section-二直接使用驱动时如何传参数" class="legacy-anchor" aria-hidden="true"></span><span id="section-直接使用驱动时如何传参数" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-二直接使用psycopg传递sql与值参数">二、直接使用psycopg传递SQL与值参数</h2>
<p>下面的独立教学片段从环境变量取得练习库连接信息，查询指定内容ID的待审核反馈。不要连接生产库做练习：</p>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">import</span> os
<span class="hljs-keyword">import</span> psycopg

    <span class="hljs-keyword">with</span> conn.cursor() <span class="hljs-keyword">as</span> cur:
        cur.execute(
            <span class="hljs-string">"SELECT id, message FROM feedback WHERE content_id = %s AND status = %s"</span>,
            (<span class="hljs-string">"python-slices"</span>, <span class="hljs-string">"pending"</span>),
        )
        rows = cur.fetchall()
</code></pre></div>
<p><strong>SQL文本和参数分别传递</strong>，<code>%s</code>由驱动按参数规则处理，不是让Python先做字符串格式化。占位符外面也不手工加引号；数值同样通过参数传入。只有一个参数时，元组写成<code>(value,)</code>，逗号不能省略。<a href="https://www.psycopg.org/psycopg3/docs/basic/params.html" rel="noopener noreferrer">psycopg参数文档</a>说明了这些约定。</p>
<p>如果用f-string把用户消息拼入SQL，单引号等内容可能改变SQL结构。参数绑定将值作为数据传递，避免这种混入语句结构的情况。<strong>参数绑定保障的是SQL语句结构与数据值的分离</strong>。消息之后如果要作为HTML展示，还需要安全呈现；请求者是否有权执行查询，也由应用另行判断。</p>
<span id="section-三表名和排序字段不能当普通值绑定" class="legacy-anchor" aria-hidden="true"></span><span id="section-表名和排序字段不能当普通值绑定" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-三sql标识符与排序选项的受控组合">三、SQL标识符与排序选项的受控组合</h2>
<p>参数通常用于值，不能用<code>SELECT * FROM %s</code>把任意表名当参数传入。如果业务确实允许选择不同表或排序列，应先做允许值映射，再使用<code>psycopg.sql.Identifier</code>等组合接口处理标识符。</p>
<p>一种清楚的排序设计是让前端提交<strong>有限枚举</strong>，例如newest，再由后端映射到固定的排序表达式。不要直接接受用户提供的一段<code>ORDER BY</code>文本。ORM同样不能保护程序自行拼接的危险SQL字符串。</p>
<span id="section-四python值怎样变成数据库值" class="legacy-anchor" aria-hidden="true"></span><span id="section-python值怎样变成数据库值" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-四python类型与postgresql类型之间的适配">四、Python类型与PostgreSQL类型之间的适配</h2>
<p>字符串、整数、UUID和日期时间需要在Python表示与PostgreSQL类型之间转换，psycopg的适配器负责这一步。结果返回时再转换为相应Python对象；ORM可以继续把结果组织成映射实例。<a href="https://www.psycopg.org/psycopg3/docs/advanced/adapt.html" rel="noopener noreferrer">数据适配说明</a>介绍了这套转换机制。</p>
<p>驱动转换与业务验证也不同。消息是否至少5个字符属于接口约束，PostgreSQL文本不接受NUL又是存储边界。本站在Pydantic模型里提前拒绝NUL，避免把一个可预期的输入问题拖到数据库阶段才变成错误。</p>

<p>psycopg默认事务模式下，执行查询通常也会启动事务。长期保持连接却不结束事务，可能形成idle in transaction，带来资源和维护问题。使用<code>with psycopg.connect(...) as conn</code>时，<strong>代码块正常退出会提交，异常退出会回滚，两种情况都会关闭连接</strong>；也可以通过显式事务块安排更具体的事务范围。<a href="https://www.psycopg.org/psycopg3/docs/basic/transactions.html" rel="noopener noreferrer">事务管理文档</a>说明了默认与autocommit行为。</p>
<p>上一篇的普通<code>with Session(...)</code>主要负责关闭Session，而这里的psycopg连接上下文还处理提交或回滚。<strong>with负责调用上下文管理器，具体退出动作由对象实现决定</strong>，所以需要按所使用的对象理解行为。本站通过SQLAlchemy Session管理事务时，应遵循Session边界，不在中间随意对底层连接另起一套提交逻辑。</p>
