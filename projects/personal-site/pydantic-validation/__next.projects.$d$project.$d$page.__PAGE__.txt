<span id="section-从普通python类到输入模型" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-一从普通python类到输入模型">一、从普通Python类到输入模型</h2>
<p>下面是根据本站反馈模型缩小后的教学示例：</p>
<div class="code-block"><div class="code-toolbar"><span>python</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-python"><span class="hljs-keyword">from</span> typing <span class="hljs-keyword">import</span> <span class="hljs-type">Literal</span>
<span class="hljs-keyword">from</span> pydantic <span class="hljs-keyword">import</span> BaseModel, ConfigDict, Field

<span class="hljs-keyword">class</span> <span class="hljs-title class_">FeedbackInput</span>(<span class="hljs-title class_ inherited__">BaseModel</span>):
    model_config = ConfigDict(extra=<span class="hljs-string">"forbid"</span>, str_strip_whitespace=<span class="hljs-literal">True</span>)
    content_id: <span class="hljs-built_in">str</span> = Field(min_length=<span class="hljs-number">1</span>, max_length=<span class="hljs-number">80</span>)
    kind: <span class="hljs-type">Literal</span>[<span class="hljs-string">"correction"</span>, <span class="hljs-string">"question"</span>, <span class="hljs-string">"other"</span>]
    message: <span class="hljs-built_in">str</span> = Field(min_length=<span class="hljs-number">5</span>, max_length=<span class="hljs-number">4000</span>)

<p>继承BaseModel后，<strong>类型标注说明字段类型，Field补充长度等约束</strong>。配置中的<code>extra="forbid"</code>拒绝多余字段，<code>str_strip_whitespace=True</code>先去除字符串首尾空白，再按相应规则检查；Literal则把反馈类型限制在列出的三个值中。本站完整模型还限制内容ID格式，并拒绝NUL字符。</p>
<p>这些规则可以通过<code>FeedbackInput.model_validate(data)</code>用于普通Python代码，也可以由FastAPI在读取请求体时使用。模型并不局限于Web接口。<a href="https://docs.pydantic.dev/latest/concepts/models/" rel="noopener noreferrer">模型说明</a>介绍了验证、序列化和配置。</p>
<span id="section-二固定一份输入逐项改变条件" class="legacy-anchor" aria-hidden="true"></span><span id="section-固定一份输入逐项改变条件" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-二字段校验的输入示例与失败原因">二、字段校验的输入示例与失败原因</h2>
<p>以<code>content_id="python-slices"</code>、<code>kind="question"</code>、<code>message="这个例子如何处理空列表"</code>作为正常输入。分别改变一处，就能看见每条规则在做什么：</p>








































<table><thead><tr><th>改动</th><th>预期结果</th><th>原因</th></tr></thead><tbody><tr><td>去掉message</td><td>拒绝</td><td>必填字段缺失</td></tr><tr><td>kind改成reply</td><td>拒绝</td><td>不在允许值中</td></tr><tr><td>message改成两个字符</td><td>拒绝</td><td>不到最小长度</td></tr><tr><td>添加status=resolved</td><td>拒绝</td><td>客户端不允许指定审核状态</td></tr><tr><td>消息首尾有空格</td><td>按去空白后的内容检查</td><td>当前反馈模型允许整理首尾空白</td></tr><tr><td>消息包含U+0000</td><td>本站模型拒绝</td><td>进入PostgreSQL文本处理前阻止非法字符</td></tr></tbody></table>
<p>这些情况中，字段校验可以在进入写库代码前失败。<strong>字段校验之后还需要业务检查</strong>。例如一个content_id即使格式正确，也要查询内容登记，才能确认它是否对应已发布文章。</p>
<span id="section-三strictinput这个类名不等于严格模式" class="legacy-anchor" aria-hidden="true"></span><span id="section-strictinput这个类名不等于严格模式" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-三严格模式配置与密码字段的独立处理">三、严格模式配置与密码字段的独立处理</h2>
<p>本站父类名叫<code>StrictInput</code>，实际配置是拒绝多余字段和去首尾空白，<strong>没有设置全局<code>strict=True</code></strong>。因此，判断是否允许类型转换时，需要查看<strong>字段规则、模型配置和验证入口</strong>。</p>
<p>Pydantic可以进行一定的数据转换；严格模式收紧部分转换，但不同输入方式仍有具体规则。需要严格检查时，应明确配置并增加相应样例，见<a href="https://docs.pydantic.dev/latest/concepts/strict_mode/" rel="noopener noreferrer">严格模式文档</a>。</p>
<p>另一个需要保留区别的字段是密码。反馈消息可以去首尾空白，密码则不能擅自trim，否则用户输入的凭据会被改变。本站<code>LoginInput</code>没有继承反馈的字符串清理配置，密码使用<strong>SecretStr减少明文被意外打印的风险</strong>，保存与验证密码时则另用密码哈希机制处理。</p>
<span id="section-四自定义validator怎样补规则" class="legacy-anchor" aria-hidden="true"></span><span id="section-自定义validator怎样补规则" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-四通过自定义validator补充字段规则">四、通过自定义validator补充字段规则</h2>
<p>本站用<code>field_validator("*", mode="before")</code>检查字符串中的NUL。<strong>before验证器在通常的字段解析前接收原始值</strong>。输入此时可能是字符串，也可能是其他类型，因此需要先判断类型，再执行字符串检查。</p>
<p>普通长度和枚举限制优先用现成字段规则，自定义validator用于确有需要的逻辑。若检查涉及数据库或外部服务，要仔细考虑它是否适合放在模型层，避免一个看似简单的解析动作暗中发起网络访问。<a href="https://docs.pydantic.dev/latest/concepts/validators/" rel="noopener noreferrer">validator文档</a>说明了不同执行阶段。</p>
