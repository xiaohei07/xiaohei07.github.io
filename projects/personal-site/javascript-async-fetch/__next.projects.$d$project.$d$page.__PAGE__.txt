2e:T293b,<p>写过简单JS后，应该已经接触过函数、对象和事件。做前后端交互时，还需要补上Promise、<code>async/await</code>、模块和错误处理。这几个内容可以用一个完整过程串起来：点击按钮，等待接口返回，然后更新页面。</p>
<span id="section-模块怎样把代码组织起来" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-一模块怎样把代码组织起来">一、模块怎样把代码组织起来</h2>
<p>本站把HTTP请求放在<code>src/lib/api.ts</code>，表单组件再导入其中的函数。简化成JS，结构如下：</p>
<div class="code-block"><div class="code-toolbar"><span>js</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-js"><span class="hljs-comment">// api.js</span>
<span class="hljs-keyword">export</span> <span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">readReceipt</span>(<span class="hljs-params">url</span>) {
  <span class="hljs-keyword">const</span> response = <span class="hljs-keyword">await</span> <span class="hljs-title function_">fetch</span>(url);
  <span class="hljs-keyword">if</span> (!response.<span class="hljs-property">ok</span>) <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">Error</span>(<span class="hljs-string">`HTTP <span class="hljs-subst">${response.status}</span>`</span>);
  <span class="hljs-keyword">return</span> response.<span class="hljs-title function_">json</span>();
}

<span class="hljs-comment">// 页面模块</span>
<span class="hljs-keyword">import</span> { readReceipt } <span class="hljs-keyword">from</span> <span class="hljs-string">"./api.js"</span>;
</code></pre></div>
<p><code>export</code>声明供其他模块使用的内容，<code>import</code>按名称取得它。相对路径需要相对于当前模块理解；本站的<code>@/lib/api</code>则使用了工程配置的路径别名，浏览器并不会天然认识<code>@</code>。构建工具负责解析这类工程写法。</p>
<p>代码拆分的直接收益是，同一套超时与错误提示可以被多个组件复用。如果每个表单各自拼接口地址，后面修改API前缀就容易漏掉一处。</p>
<span id="section-promise表示尚未确定的异步结果" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-二promise表示尚未确定的异步结果">二、Promise表示尚未确定的异步结果</h2>
<p>调用<code>fetch()</code>时，请求还没有完成，它先返回Promise。<strong>Promise表示尚未确定的异步结果</strong>，后续可能兑现为Response，也可能因为网络错误等原因被拒绝。<code>await</code>允许异步函数等到这个Promise完成，再继续执行后面的代码；等待期间，浏览器仍有机会处理其他任务。</p>
<div class="code-block"><div class="code-toolbar"><span>js</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-js"><span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">loadTitle</span>(<span class="hljs-params"></span>) {
  <span class="hljs-variable language_">console</span>.<span class="hljs-title function_">log</span>(<span class="hljs-string">"开始读取"</span>);
  <span class="hljs-keyword">const</span> response = <span class="hljs-keyword">await</span> <span class="hljs-title function_">fetch</span>(<span class="hljs-string">"/example.json"</span>);
  <span class="hljs-keyword">const</span> data = <span class="hljs-keyword">await</span> response.<span class="hljs-title function_">json</span>();
  <span class="hljs-variable language_">console</span>.<span class="hljs-title function_">log</span>(data.<span class="hljs-property">title</span>);
}
</code></pre></div>
<p>这里有两次等待。第一次等待响应可用，第二次等待响应体读取并按JSON解析。<code>async</code>函数的返回值也会包装成Promise，因此调用者同样需要<code>await</code>或<code>.then()</code>取得结果。上面的路径是教学占位，不能当作本站已有接口。</p>
<p>需要注意，<code>await</code>不会把CPU密集计算自动移到另一个线程。如果等待结束后运行一个很长的同步循环，页面仍可能卡住。并行下载与并行计算也应分别考虑。</p>
<span id="section-将成功http失败和网络失败分开" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-三将成功http失败和网络失败分开">三、将成功、HTTP失败和网络失败分开</h2>
<p>下面是适合阅读的独立函数示例。它只展示请求处理方式，没有在生产接口执行：</p>
<div class="code-block"><div class="code-toolbar"><span>js</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-js"><span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">createFeedback</span>(<span class="hljs-params">payload</span>) {
  <span class="hljs-keyword">const</span> response = <span class="hljs-keyword">await</span> <span class="hljs-title function_">fetch</span>(<span class="hljs-string">"/api/v1/feedback"</span>, {
    <span class="hljs-attr">method</span>: <span class="hljs-string">"POST"</span>,
    <span class="hljs-attr">headers</span>: { <span class="hljs-string">"Content-Type"</span>: <span class="hljs-string">"application/json"</span> },
    <span class="hljs-attr">body</span>: <span class="hljs-title class_">JSON</span>.<span class="hljs-title function_">stringify</span>(payload),
    <span class="hljs-attr">signal</span>: <span class="hljs-title class_">AbortSignal</span>.<span class="hljs-title function_">timeout</span>(<span class="hljs-number">15000</span>),
  });
  <span class="hljs-keyword">if</span> (!response.<span class="hljs-property">ok</span>) {
    <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">Error</span>(<span class="hljs-string">`请求没有成功：<span class="hljs-subst">${response.status}</span>`</span>);
  }
  <span class="hljs-keyword">return</span> response.<span class="hljs-title function_">json</span>();
}
</code></pre></div>
<p>JS对象要先经过<code>JSON.stringify</code>变成JSON文本；请求头说明正文格式。接口返回422时，<code>fetch</code>本身通常没有失败，但<code>response.ok</code>为false，所以需要主动抛出错误。网络不可达、请求被中止等情况则可能直接使<code>fetch</code>拒绝。<a href="https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch" rel="noopener noreferrer">Fetch官方参考</a>对这些行为及请求选项有更完整的说明。</p>
<p>实际项目的<code>apiRequest</code>还统一处理503、401、403、429和422，不把服务端未经筛选的诊断文字直接显示给用户。204没有响应体，因此会单独返回，避免对空响应调用<code>json()</code>。</p>

<span id="section-两个请求怎样安排顺序" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-五两个请求怎样安排顺序">五、两个请求怎样安排顺序</h2>
<p>如果请求B需要请求A返回的ID，就应该先等A，再发B。两个互不依赖的只读请求可以用<code>Promise.all</code>一起等待，但其中一个拒绝后，其他已经发出的请求不会自动取消；需要全部结果时，可以考虑<code>Promise.allSettled</code>。</p>
<p>搜索还有一种常见问题：用户先输入<code>react</code>，很快改成<code>next</code>，前一个请求却更晚返回。如果直接用每次返回的数据覆盖结果，就会显示过时内容。可以中止旧请求，也可以给请求标记序号，只接受当前序号的结果。本站站内搜索先加载静态索引，再在本地匹配，并没有为每次输入访问服务器搜索接口，因此不要把这个教学场景写成本站现有缺陷。</p>
