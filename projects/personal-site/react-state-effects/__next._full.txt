29:T490a,<p>输入框内容、当前标签、请求是否进行中，这些数据变化后都需要更新界面。在React中，可以用<strong>state保存需要参与渲染的数据</strong>，再通过状态更新函数通知React重新渲染。普通变量也能保存值，但只修改普通变量时，React不会因此安排界面更新。</p>
<span id="section-一usestate保存的是哪一轮状态" class="legacy-anchor" aria-hidden="true"></span><span id="section-usestate保存的是哪一轮状态" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-一usestate的状态快照与更新队列">一、useState的状态快照与更新队列</h2>
<div class="code-block"><div class="code-toolbar"><span>tsx</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-tsx"><span class="hljs-string">"use client"</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">Counter</span>(<span class="hljs-params"></span>) {

  <span class="hljs-keyword">return</span> <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">button</span> <span class="hljs-attr">onClick</span>=<span class="hljs-string">{()</span> =></span> setCount(count + 1)}>{count}<span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span></span>;

<p><code>count</code>是本轮渲染读取到的值，<code>setCount</code>安排新的状态。调用它之后，当前函数里的<code>count</code>不会立刻变成新值；React后续渲染时才会把更新后的状态交给组件。<a href="https://react.dev/learn/state-as-a-snapshot" rel="noopener noreferrer">状态快照</a>说明了事件处理函数为何会保留某一轮的值。</p>
<p>例如同一个点击处理里连续执行三次<code>setCount(count + 1)</code>，三次计算使用的是该次渲染中的同一份<code>count</code>。如果目标是基于前一次待处理值累加三次，可以写三次<code>setCount(value => value + 1)</code>。<strong>更新函数接收队列中前一次更新的结果</strong>，因此三次更新可以依次累加。<a href="https://react.dev/learn/queueing-a-series-of-state-updates" rel="noopener noreferrer">状态更新队列</a>有对应过程。</p>
<span id="section-二输入框怎样保持值与界面一致" class="legacy-anchor" aria-hidden="true"></span><span id="section-输入框怎样保持值与界面一致" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-二受控输入与对象状态的更新">二、受控输入与对象状态的更新</h2>
<div class="code-block"><div class="code-toolbar"><span>tsx</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-tsx"><span class="hljs-keyword">const</span> [message, setMessage] = <span class="hljs-title function_">useState</span>(<span class="hljs-string">""</span>);

<span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">textarea</span>
  <span class="hljs-attr">value</span>=<span class="hljs-string">{message}</span>
  <span class="hljs-attr">onChange</span>=<span class="hljs-string">{event</span> =></span> setMessage(event.target.value)}

<p>输入触发<code>onChange</code>，把新的字符串存入state；下一轮渲染再把这个字符串传给<code>value</code>。这种由组件状态管理输入值的方式，称为<strong>受控输入</strong>。</p>
<p>本站反馈表单在等待期间禁用输入与按钮，成功后清空字符串，失败则保留。因此处理成功与失败时需要分别更新对应状态，不能在提交函数末尾无条件清空。</p>
<p>数组和对象也应产生新值，例如<code>setTags(tags => [...tags, "React"])</code>，而不是直接对原数组<code>push</code>后继续复用原引用。这样更容易保持每轮状态清楚，也能避免修改其他地方仍在使用的对象。</p>

<span id="section-四横幅切换为什么要保留上一张图" class="legacy-anchor" aria-hidden="true"></span><span id="section-横幅切换为什么要保留上一张图" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-四横幅切换中的成功失败与旧图保留">四、横幅切换中的成功、失败与旧图保留</h2>
<p>本站横幅维护<code>current</code>、<code>previous</code>和<code>ready</code>。切换时先保存上一张图，再请求下一张；新图成功加载后才进入过渡，过渡结束再释放旧图。</p>

<p>工程曾记录<code>onError</code>与<code>onLoad</code>共用成功处理，导致失败也被当作“可以结束旧图保留”。修正后将失败回调分开。这里的关键是<strong>分别定义成功和失败事件对应的状态转换</strong>，只有新图成功加载，才具备移除旧图的条件。</p>
<p>轮播还需要考虑页面是否可见、横幅是否在视口内、用户是否选择减少动态效果。本站通过这些条件决定是否继续计时，并在依赖变化时清理计时器，避免离开页面后仍积累后台任务。</p>
<span id="section-五阅读目录怎样从标题列表变成可操作的树" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-五阅读目录的树结构与交互状态">五、阅读目录的树结构与交互状态</h2>
<p>目录同时涉及内容结构和交互状态。输入是正文解析得到的标题列表，每项包含<code>id</code>、<code>text</code>、<code>level</code>；输出是可展开的目录分支，以及当前阅读位置的标记。<strong>标题文字与层级属于内容结构，当前节和手动折叠属于交互状态</strong>。分别管理这两部分数据，才能在阅读位置变化时更新目录，又保留原有的标题关系。</p>
<h3 id="section-51-用栈建立标题的父子关系">5.1 用栈建立标题的父子关系</h3>
<p><strong>栈</strong>可以先理解为只从末尾放入、取出数据的列表。这里保存当前标题的祖先链。读到新标题时，末尾如果不比它层级更浅，就移走，直到找到可作为父级的标题。</p>
<p>用教学输入<code>h2:A、h3:B、h4:C、h3:D、h2:E</code>逐步推演：</p>



































<table><thead><tr><th>当前标题</th><th>处理后找到的父级</th><th>加入后的祖先栈</th></tr></thead><tbody><tr><td>A，二级</td><td>无，作为根节点</td><td>A</td></tr><tr><td>B，三级</td><td>A</td><td>A、B</td></tr><tr><td>C，四级</td><td>B</td><td>A、B、C</td></tr><tr><td>D，三级</td><td>弹出C与B，剩下A</td><td>A、D</td></tr><tr><td>E，二级</td><td>弹出D与A，作为新根</td><td>E</td></tr></tbody></table>
<p>最终A下面有B和D，B下面有C；E与A并列。本站<code>headingTree</code>使用的就是这个关系：弹出所有<code>level >= 新标题level</code>的末尾节点，再挂到最近较浅标题下。跳级的h2→h4仍能挂到h2下面，不会凭空造一个h3。</p>
<p>每个标题入栈一次，出栈至多一次，因此<strong>建树时间是O(n)</strong>，n为标题数。这里分析的是建树步骤，不是整套目录交互都恒定耗时；寻找路径、读取DOM位置和渲染还有各自工作。</p>
<span id="section-52-当前节与手动折叠各自保存什么" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-52-当前阅读位置与手动折叠状态的配合">5.2 当前阅读位置与手动折叠状态的配合</h3>
<p><code>activeId</code>记录当前阅读标题，<code>headingPath</code>取得从根到该标题的路径。默认只展示根级目录，进入某节后展开它的祖先链，让读者能看到当前位置。</p>
<p>假设读者停在C，手动折叠A。若每次滚动都强制展开A，刚才的操作会立刻失效。本站把手动展开集合与当时的activeId一起保存：仍在C时使用手动选择；进入D后旧选择失效，重新按D的祖先路径展开。这样既能跟随阅读，又能让同一节里的手动折叠保持有效。</p>
<p>当前节由IntersectionObserver、滚动监听和hashchange共同更新。观察器感知可见关系，滚动与锚点事件补充快速跳转等情况；<code>requestAnimationFrame</code>把同一轮滚动工作合并到适当的绘制时机。当前项超出目录视口时，只调整目录容器的scrollTop，避免为了显示一条目录而拖动正文。</p>
<span id="section-53-窄屏为什么使用portal和dialog" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-53-窄屏目录的portal定位与dialog模态交互">5.3 窄屏目录的Portal定位与dialog模态交互</h3>
<p>当视口不大于1350px，本站使用窄屏目录布局。文首目录滚出后才出现悬浮按钮；这个条件按视口宽度判断，所以较窄的桌面窗口也会使用同一布局。打开按钮后，读者需要在弹层里看到当前章节，选中目标后回到正文。</p>
<p><strong>Portal改变DOM放置位置，同时保留React树中的关系。</strong> 本站把悬浮控件和dialog放到document.body，避开祖先动画容器对fixed定位的影响。上下文和React事件传播仍遵循原组件树，这一点与单纯把DOM搬到另一个父元素的直觉不同。<a href="https://react.dev/reference/react-dom/createPortal" rel="noopener noreferrer">React的Portal说明</a>解释了两种关系。</p>
<p>原生<code>dialog.showModal()</code>提供模态交互基础；代码在打开后把焦点移到当前目录项。点击目录时先关闭弹层，再按链接锚点跳转；Esc或关闭按钮只是收起，不应额外跳动正文。弹层打开期间锁住背景滚动，位置更新也暂停，避免弹层布局变化误判当前章节。原生行为可对照<a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog" rel="noopener noreferrer">dialog参考</a>。</p>
<p>离开适用断点或组件卸载时，需要移除监听、断开观察器并取消待执行的rAF。Portal和dialog减少了部分定位与模态处理工作，但焦点恢复、关闭清理、减少动态效果及真实设备仍要检查；已有Chrome视口结果不能代替实机Safari和完整无障碍验收。</p>

<span id="section-61-先确定保存哪一份状态" class="legacy-anchor" aria-hidden="true"></span><h3 id="section-61-明暗主题栏目色与全站统一色的状态">6.1 明暗主题、栏目色与全站统一色的状态</h3>
<p>亮色、暗色、跟随系统决定明暗主题；栏目色与全站统一色决定配色作用范围，两者是不同维度。<strong>state驱动当前画面，localStorage用于刷新后恢复，DOM呈现最终结果</strong>，因此，修改偏好时需要同时安排状态更新、存储写入和页面应用。</p>
<p>本站<code>section</code>模式分别保存各栏目颜色，<code>custom</code>模式统一全站。状态还要区分自定义种子色与原始整套色板：一个hex可以生成配色变量，却不一定还原原栏目里文字、背景、边框等变量的原始组合。</p>

<h3 id="section-62-从复制研究配色到恢复项目原色">6.2 从复制研究配色到恢复项目原色</h3>
<p>假设各栏目先用原色，读者在项目页点击“研究”色卡。目标仍是projects，来源是research；如果来源没有自定义hex，就保存采用研究原色板的选择。导航仍属于项目，颜色来源变化不会把URL或内容分类也改成研究。</p>
<p>若之后研究栏目改成自定义hex，项目保留的是复制当时解析出的选择，不会自动订阅研究的新设置。<strong>复制保存的是操作当时的配色结果</strong>，后续修改来源栏目时，目标栏目会继续使用原先保存的选择。</p>
<p>接着在项目页点击自身“项目”。旧实现再次读取项目已经保存的研究配色，所以看起来没有恢复。当前<code>copySectionPalette</code>先判断<code>source === target</code>，在这一分支读取项目的<strong>原始色板</strong>，清除项目覆盖。修正落在动作含义和状态转换上，单改CSS颜色不能解决“再次复制错误来源”的问题。</p>
<p>统一模式下点击自身，会把当前栏目的原色板应用全站；之前各栏目的设置仍保留，以便切回栏目模式。颜色恢复也只重置颜色相关状态，不应顺带清除布局、动态效果等其他偏好。</p>

<p>localStorage可能留有旧格式或损坏数据。当前解析只接受白名单栏目、合法枚举、六位hex和有界数值，不把读出来的对象原样应用。首屏入口脚本和运行期使用同一个<code>resolveColorPreferences</code>，让刷新与客户端切页对“当前应使用哪套色板”得到相同判断。</p>
