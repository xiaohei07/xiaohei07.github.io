程序中的变量随着进程退出就可能消失，反馈记录却需要在重启后保留。PostgreSQL负责持久保存这些数据，并提供查询、约束和事务能力。先从表、行和SQL看起，再讨论ORM会比较容易。

一、一条反馈怎样放进表里

表规定一类数据的字段，每行是一条记录，每列有自己的类型。例如消息用文本，状态用限定字符串，创建时间用带时区的时间类型。下面是只用于理解关系的简化表：

sql
CREATE TABLE lesson_feedback (
  id integer PRIMARY KEY,
  content_id text NOT NULL,
  message text NOT NULL,
  status text NOT NULL DEFAULT 'pending',
  CHECK (status IN ('pending', 'resolved', 'rejected'))
);

本站真实反馈ID使用UUID，并且有外键、时间、审核人和消息长度限制；不能拿这个教学表直接替换实际Schema。表定义与数据类型的基本写法见PostgreSQL建表教程。

PRIMARY KEY标识每行并保证唯一且非空；NOT NULL拒绝缺值；DEFAULT在没有提供对应值时填入默认值；CHECK限制允许的数据。默认值不是对任意输入的强制覆盖，客户端显式传来其他合法值时，还要看接口和权限是否允许。

二、查询怎样从条件走到结果

sql
SELECT id, content_id, message
FROM lesson_feedback
WHERE status = 'pending'
ORDER BY id DESC
LIMIT 20;

FROM指定表，WHERE筛选行，SELECT决定返回哪些列，ORDER BY排序，LIMIT限制数量。SQL的书写顺序与数据库内部实际执行计划不必一致；这段解释是帮助理解结果，不是宣称数据库按这些行逐行执行。查询教程包含筛选和排序规则。

本站管理列表按created_at DESC, id DESC排序，每页20条。相同时间可能有多条反馈，第二个排序字段使顺序更稳定。当前实现用offset分页，页码很大时可能付出较多跳过记录的成本；未来可以评估按最后一条时间与ID做游标分页，但不是当前已实现能力。

三、本站表之间怎样关联

content_entries登记内容ID、slug和标题，不保存完整文章正文；它预留了content_hash字段，但当前登记与种子同步不写入正文摘要。按现有模型，新条目该列留空，已有条目更新时保留该列原值；这不等于每次清空，也不能据此断言真实库所有行均为空。feedback.content_id通过外键关联内容；admin_users保存作者账号；admin_sessions保存会话摘要和过期时间；audit_events保存登录、退出和审核等操作记录。迁移工具还维护自己的版本表，因此统计表数量时需说明是否把迁移元数据算进去。

例如教学条目note-a原本有摘要H，登记同步只更新题名与公开状态后，H仍保留；若新建note-b，输入不包含摘要且该列没有默认值，就按可空字段保存。文件清单中的SHA256、公开批准的manifestHash和数据库这一列处在不同位置，没有自动互相同步。这里依据代码与模型推演，没有查询生产库的实际列值。

外键保证引用关系。本站内容被反馈引用时，删除策略是RESTRICT，避免删除内容登记后留下无对应对象的反馈；审核人字段则允许在账号删除后置空，保留反馈历史。外键的删除动作应该按业务语义选择，不能所有关系都套CASCADE。约束文档解释了主键、唯一性、检查与外键的区别。

数据库约束可以拦住不符合规则的写入，但不替代权限检查。 例如“某个用户是否能审核”仍应由应用判断；表允许resolved，不表示任何匿名请求都能写这个状态。

四、索引为什么要根据查询建

索引提供额外的数据访问结构，让数据库在适合的条件下减少扫描。本站给反馈的status, created_at建立组合索引，与按状态筛选、按时间取最近记录的查询有关。

索引也占空间，每次相关写入都要维护。它并不保证所有查询更快，小表可能顺序扫描更合适；组合索引能否覆盖筛选和排序，还与列顺序、条件和执行计划有关。当前索引没有包含排序的全部id条件，不应宣称已经覆盖整个查询。多列索引给出相应规则。

真正想验证性能，应在接近实际的数据规模下看EXPLAIN，需要实际执行统计时使用EXPLAIN ANALYZE并注意它会执行语句。不能把生产写语句随便加上ANALYZE运行。本站尚未给出大规模反馈表的容量结论。

五、NULL、时间与文本需要注意什么

NULL表达未知或没有值，比较时通常使用IS NULL，不能把它当普通字符串"null"。本站未审核记录的审核时间为NULL。

PostgreSQL的timestamptz表示时间点，展示时受会话时区影响，并不保留用户最初输入的时区名称。API与数据库应统一处理时间，再由显示层决定格式，避免拿本地无时区字符串互相比较。

参数化查询用于安全传递消息值，后面psycopg驱动会解释。数据能安全传入并不意味着所有业务关系都成立；一次审核涉及多个写入时，还需要事务与并发控制。
