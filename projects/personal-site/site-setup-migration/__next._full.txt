<span id="section-二环境恢复先看锁文件" class="legacy-anchor" aria-hidden="true"></span><span id="section-环境恢复先看锁文件" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-二根据锁文件恢复开发环境">二、根据锁文件恢复开发环境</h2>
<p>恢复已有工程时，需要同时查看<strong>运行环境版本</strong>和<strong>依赖锁文件</strong>。工程环境记录使用Node24.18.0、npm12.0.2和Python3.11.2；2026年10月25日读取的前端声明与锁文件包括Next16.4.2、React19.3.1和TypeScript5.9.3，后端锁文件包括FastAPI0.143.3、Pydantic2.14.1、SQLAlchemy2.0.55和psycopg3.3.6。</p>
<p>这些版本用来说明当时的环境和安装依据。自己复现时，应在项目环境中按锁文件恢复依赖；生产容器实际使用的版本还需要在对应容器内查看。</p>
<p>已有工程通过<strong><code>npm ci</code>按锁文件恢复JS依赖</strong>，Python则使用项目解释器安装锁定的依赖。执行Python安装命令时，可以采用<code>项目解释器 -m pip</code>的形式，明确依赖会进入哪个环境。脚手架主要用于创建新工程，恢复已有工程时直接使用现有配置。</p>
<p>本机有三类入口：3001是编辑开发预览，3000是构建后的静态预览，8000是本地API。数据库使用独立本地端口。端口不是功能身份，实际要看进程与启动方式，尤其不能因为某端口被占用就直接结束未知进程。</p>
<span id="section-从保存原稿到看到本地页面" class="legacy-anchor" aria-hidden="true"></span><h2 id="section-三从保存原稿到看到本地页面">三、从保存原稿到看到本地页面</h2>
<p>新稿先进入内容目录，完成字段与来源检查后，由导入器复制到前端允许的快照范围。随后开发服务读取快照，或进行静态构建再用3000查看。</p>
<p>以本系列为例，<strong>manuscript是正文修改入口</strong>，构包脚本根据它生成带元数据的articles和清单；工程导入器再读取清单，核对字节后写入冻结快照。直接修改articles，下次构包会覆盖；直接修改快照，会破坏输入摘要；只修改原稿但没重新生成与导入，网站仍读取旧版本。先确定卡在哪一层，再决定执行哪一步。</p>
<div class="code-block"><div class="code-toolbar"><span>powershell</span><button type="button" data-copy-code="true" aria-label="复制代码">复制代码</button></div><pre><code class="hljs language-powershell"># 在site-next目录，检查与生成本地静态产物
npm run typecheck
npm run build
npm run check:export
npm run preview
</code></pre></div>
<p>这些是现有项目命令。<code>preview</code>在服务未运行时启动静态预览；已启动就刷新即可。新系列使用独立导入命令，按明确manifest接入，公开构建仍排除未授权的本地稿件。</p>
<p>如果3001能够看到修改，而3000仍显示旧内容，可以先检查是否重新执行了静态构建；如果内容快照本身还是旧版本，则应先重新生成并导入。<strong>按原稿、快照、构建产物和浏览器的顺序检查</strong>，能够确定需要更新的是哪一层。</p>

<p>正文里的链接还包含片段锚点。只让旧URL跳到新页面，但没保留相应段落入口，读者仍可能失去原来的定位。本站对核验过的旧路径建立301映射，并处理部分旧标题和手写锚点；未逐一验证的历史外部书签不能笼统称为全部兼容。</p>
