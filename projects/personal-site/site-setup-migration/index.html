确定技术栈之后，需要先把旧博客和新工程隔开。否则改新页面时，很容易顺手碰到旧主题、旧依赖或发布脚本，也不容易确认迁移过程中哪些文件发生了变化。

本站新工程位于site-next，旧Hexo相关文件后来集中到oldblog_backup。这个目录调整是在原文件保留与哈希核对的基础上进行的，不能把备份目录当作新站发布源。

一、工程目录怎样按运行职责拆分

text
site-next/
  apps/web/       Next.js前端与受控内容快照
  apps/api/       FastAPI应用、模型与迁移
  scripts/        导入、预览和验证工具
  infra/          Nginx、容器与部署配置
  requirements.lock.txt
docs/content/    原稿、内容交付与核验记录
oldblog_backup/  旧博客与历史备份

这是与本系列相关的结构摘要，没有列出运行凭据和所有生成文件。前端产物、后端源码、数据库数据和原稿分开放置，可以减少把整个工作区上传到公开目录的风险，也便于分别更新。

二、环境恢复先看锁文件

工程环境记录使用Node24.18.0、npm12.0.2、Python3.11.2；10月25日读取的前端声明与锁文件包括Next16.4.2、React19.3.1、TypeScript5.9.3。后端锁文件记录FastAPI0.143.3、Pydantic2.14.1、SQLAlchemy2.0.55和psycopg3.3.6。这里区分环境记录和依赖声明，没有重新进入生产容器逐项读取运行版本；这些数字也不要求读者重装全局环境。

已有工程用npm ci按锁文件恢复JS依赖，Python用项目解释器安装锁定依赖。不要在同一目录重复生成脚手架，也不要用一个不知道指向哪个环境的pip修改全局包。

本机有三类入口：3001是编辑开发预览，3000是构建后的静态预览，8000是本地API。数据库使用独立本地端口。端口不是功能身份，实际要看进程与启动方式，尤其不能因为某端口被占用就直接结束未知进程。

三、从保存原稿到看到本地页面

新稿先进入内容目录，完成字段与来源检查后，由导入器复制到前端允许的快照范围。随后开发服务读取快照，或进行静态构建再用3000查看。

以本系列为例，manuscript是正文修改入口，构包脚本根据它生成带元数据的articles和清单；工程导入器再读取清单，核对字节后写入冻结快照。直接修改articles，下次构包会覆盖；直接修改快照，会破坏输入摘要；只修改原稿但没重新生成与导入，网站仍读取旧版本。先确定卡在哪一层，再决定执行哪一步。

powershell
# 在site-next目录，检查与生成本地静态产物
npm run typecheck
npm run build
npm run check:export
npm run preview

这些是现有项目命令。preview在服务未运行时启动静态预览；已启动就刷新即可。新系列使用独立导入命令，按明确manifest接入，公开构建仍排除未授权的本地稿件。

如果3001能看到修改、3000看不到，先确认有没有重新构建。若连内容快照都没有更新，则需要先重新导入。反复刷新浏览器不能弥补前面没有发生的数据更新。

四、旧文迁移要保留哪些身份

旧文章的标题、文件名、日期路径与新ID不必一一相同。迁移清单记录原路径、源哈希、新ID与规范路由，标题可以修得更准确，ID和旧址映射则尽量稳定。

正文里的链接还包含片段锚点。只让旧URL跳到新页面，但没保留相应段落入口，读者仍可能失去原来的定位。本站对核验过的旧路径建立301映射，并处理部分旧标题和手写锚点；未逐一验证的历史外部书签不能笼统称为全部兼容。

工程记录中的51篇迁移文章与373个source文件校验，统计对象不同：前者是文章条目，后者还包括资源与其他文件。不能把两者相减判断漏迁了多少篇文章。

五、迁移中实际遇到的几类问题

旧文里的中文强调标记需要与新Markdown解析规则适配；本机图片路径不能当公网资源；上下标语法应只处理文本节点，不能误改代码。代码块有语言标记后，呈现层才能更准确高亮，但高亮成功不等于代码运行通过。

目录也要检查最终生成的DOM。旧tocbot踩坑记录中，标题ID与内部span的变化会影响目录扫描，新版把目录与正文标题ID从同一条渲染管线收集，仍要检查链接实际能定位。

历史技术内容需要单独审校。迁移哈希证明原文件是否保留，不能证明原文中的算法结论正确；页面构建证明结构能生成，也不能证明所有示例在当前版本可运行。

六、为什么不直接扫描所有Markdown

工作区还包含私密研究材料、草稿、反馈记录和归档教程。文件扩展名相同，不代表公开条件相同。本站通过显式清单和状态校验接入稿件，并对搜索、页面、资产等一起限制。

本系列的源包仍使用review/private及publishAllowed:false，这是导入协议的含义。它在10月21日已获公开批准；公开构建通过另一份记录核对集合、snapshot与manifestHash，才决定是否发布对应版本。因此文件中的预览标记与当前已批准版本的公开状态需要分别看。修改后必须导入新快照并取得与新摘要对应的公开记录，不能让旧批准默认覆盖所有未来变动。具体机制见内容和搜索的数据流。
