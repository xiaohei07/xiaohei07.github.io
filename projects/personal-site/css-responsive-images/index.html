个人主页同时有文章、侧栏、横幅和代码块。桌面宽屏能放下三列，手机却可能只有一列；图片需要铺满横幅，正文图片又应尽量完整显示。只给所有元素加上width: 100%，还不足以解决这些差别。

一、先确定容器能分到多少宽度

可以用Grid描述文章与目录的两列关系：

css
.reading-layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 15rem;
  gap: 1.5rem;
}
.article { min-width: 0; }
.article pre { overflow-x: auto; }
@media (max-width: 60rem) {
  .reading-layout { grid-template-columns: minmax(0, 1fr); }
}

这是布局教学示例，不是本站完整样式。1fr分配剩余空间，minmax(0, 1fr)允许正文列继续收缩；代码块在自身容器内横向滚动，避免长代码把整个页面撑宽。Flex/Grid子项的自动最小尺寸可能保留内容宽度，因此遇到溢出时，min-width: 0是值得检查的条件，具体行为见MDN min-width。

断点根据内容放不下的位置确定，比直接背“手机等于某个像素”更可靠。浏览器缩放、长标题、侧栏文字增大都会改变空间需求。

本站当前阅读目录的宽屏区域约280–320px，在不大于1350px时切到窄屏目录，文首入口滚出后再提供悬浮按钮。这与上面60rem的教学例子是两个范围：代码片段解释布局原则，具体数字以项目当前样式为准。检验断点时，应看两侧是否有重复入口、弹层是否清理、长标题是否仍可读，不能只检查一个390px截图。

二、图片文件尺寸与显示尺寸怎样对应

一张2560像素宽的图片，可以在CSS中只显示640px宽。前者决定图片包含多少像素，后者是布局尺寸；高像素密度屏幕还会影响需要的清晰度。

html
<img
  src="/images/banner-1280.webp"
  srcset="/images/banner-640.webp 640w,
          /images/banner-1280.webp 1280w,
          /images/banner-1920.webp 1920w"
  sizes="(max-width: 700px) 100vw, 80vw"
  width="1920" height="800"
  alt="横幅示例"
>

这些文件名是教学示意。srcset提供候选实际宽度，sizes告诉浏览器预计占用的布局宽度，浏览器再结合DPR等条件选资源。390px视口、DPR2并不保证选择640宽图片；本项目历史测量中实际选中了1280候选。响应式图片说明解释了候选选择与不同裁切需求。

width和height还能提供固有比例，让浏览器在图片到达前预留空间。缺少尺寸时，图片加载后可能把正文向下推，增加布局位移。alt应说明有信息意义的图；纯装饰图可以使用空alt，并避免把装饰描述反复读给辅助技术用户。HTML图片参考包含这些基础属性。

三、cover为什么会裁掉一部分图片

object-fit: cover保持比例并填满容器，多出的部分会被裁切；contain保持完整图片，但容器可能留出空白。横幅通常优先铺满，技术图和结果截图更需要完整显示。

裁切位置由object-position影响。人物脸部如果靠近边缘，桌面与手机应分别选取合适位置。本项目曾调整首页横幅的宽度限制和宽窄屏裁切，修的是容器与图片呈现关系，不能仅通过重新压缩文件解决。

不同构图需要不同裁切时，可以用picture按媒体条件提供来源。相同构图只需要不同分辨率时，则可以优先使用srcset。正文中的架构图不能为了铺满卡片把节点裁掉。

四、宽公式和表格应该在哪一层滚动

长代码、表格或公式可能天然宽于正文。把整个页面加大，会连导航、正文和按钮一起横移；更合适的做法通常是让必要的内容容器局部滚动，正文列仍能收缩。本站10月25日的公式修正就针对长MathML在窄屏的溢出，不能由“代码块已经有overflow”推断公式节点也得到相同约束。

检查时先比较文档的scrollWidth与可见宽度，再定位哪个元素越界；允许公式内部scrollWidth较大，与整页横向溢出是两种现象。布局修复还要保留公式可读性，不应靠缩小到无法辨认或裁掉末尾解决。

五、动画为什么需要看布局、绘制与合成

浏览器更新样式后，可能重新计算布局、绘制内容，再完成合成。修改宽高和位置可能影响布局；transform与opacity在适合的条件下更容易由合成阶段处理，但是否独立成层仍由浏览器决定，不能保证任何transform动画都没有开销。

大量透明层、模糊、阴影和大图也可能增加绘制或内存成本。优化时应查看实际轨迹，先确认慢在下载、解码、布局还是脚本，再决定减少哪部分工作。

用户选择减少动态效果时，应降低或关闭不必要动画，同时保留功能状态变化：

css
@media (prefers-reduced-motion: reduce) {
  .banner-layer { transition: none; }
  .decorative-petal { animation: none; }
}

这项偏好由系统与浏览器暴露，见prefers-reduced-motion。本站还在JS层判断页面可见性，避免只隐藏元素却继续运行轮播计时。

检查阅读页时，可以依次放入长标题、长代码、宽表格和技术图，再缩小视口。允许代码块内部滚动，与整页出现横向滚动是不同情况；不能只看首页好看，就认为正文也没有布局问题。
