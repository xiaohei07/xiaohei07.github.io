普通HTML可以写出一张文章卡片。如果文章有几十篇，每张卡片的结构都类似，就适合把这部分界面组织成组件。React组件接收数据，再描述这些数据应该显示成什么样。

有一点Vue经验的话，可以先把组件与props的关系对应起来看。两者都有组件化思想，不过模板语法、响应式机制和状态更新方式并不完全相同，后面要按React的规则来写。

一、从JS函数到页面组件

tsx
type ArticleCardProps = {
  title: string;
  href: string;
  tags: string[];
};

function ArticleCard({ title, href, tags }: ArticleCardProps) {
  return (
    <article>
      <h2><a href={href}>{title}</a></h2>
      <p>{tags.join("、")}</p>
    </article>
  );
}

组件通过props接收输入，通过返回的JSX描述界面结构。这个例子中，{ title, href, tags }使用JS解构，从props对象中取出三个属性；JSX里的{title}则把title表达式的结果放到对应位置。

JSX看起来像HTML，但最终要经过工具处理。组件名使用大写开头，让React区分自定义组件和article这类原生标签。属性用className设置CSS类，标签需要正确闭合。基础规则可以参考React组件入门。

二、父子组件之间的props传递

tsx
<ArticleCard
  title="理解列表切片"
  href="/blog/python-slices/"
  tags={["Python", "切片"]}
/>

父组件决定传入什么，子组件按约定读取。props在一次渲染中应当按只读数据处理；如果文章标题发生变化，应由管理这份数据的位置产生新值，再传给子组件，避免子组件直接修改父级对象。

children也是一种props，用来承接标签之间的内容。例如文章布局可以接收任意正文，让标题、侧栏和正文的组织分开。组件可以围绕需要复用或独立管理的界面部分来拆分；只使用一次、逻辑简单的几行结构，也可以直接保留在页面里。props说明介绍了这类输入关系。

三、列表渲染与稳定key的身份对应

tsx
function ArticleList({ articles }: { articles: ArticleCardProps[] }) {
  return articles.map(article => (
    <ArticleCard key={article.href} {...article} />
  ));
}

map为每个数据项生成对应元素，{...article}把对象里的属性展开后传给ArticleCard。key用于让React识别列表变化前后的同一个条目，因此需要在同级列表中保持唯一，并在条目移动后保持稳定。

假设列表从A、B变成B、A，使用稳定ID可以继续识别原来的A和B。如果用当前下标作为key，位置虽然仍是0和1，但位置上的对象已经交换；有输入状态的子组件可能因此和错误的数据对应。本站内容一直保留稳定ID，也有助于解决这类身份问题。列表与key进一步说明了适用条件。

四、通过事件回调更新父组件的数据

tsx
function TagButton({ tag, onSelect }: {
  tag: string;
  onSelect: (tag: string) => void;
}) {
  return <button onClick={() => onSelect(tag)}>{tag}</button>;
}

点击后调用父组件传来的函数，父组件再更新筛选条件。onClick={() => onSelect(tag)}传的是函数；如果直接写onClick={onSelect(tag)}，通常会在渲染时调用它，把返回值交给onClick，执行时机就不对了。

React根据状态和props描述UI，再把更新协调到DOM。组件最终生成的原生元素仍然会影响用户操作：执行动作使用button，页面跳转使用链接，输入框提供对应的label。这些元素的语义、键盘行为和可访问名称，也需要在封装组件时一起考虑。

五、本站文章、反馈与横幅组件的职责

文章元数据进入文章卡片，完整正文进入详情页；FeedbackForm接收contentId，提交时把它一起发给API；横幅组件接收当前路径，根据栏目选图。它们分别围绕展示、写入、视觉状态组织，组件之间通过具体参数和回调衔接。

组件的执行位置取决于它所需要的能力。读取Markdown并生成文章结构，可以在构建时完成；处理按钮点击、表单输入和主题设置，则需要浏览器中的客户端逻辑。Next.js用Server Component和Client Component区分这些边界，详见Next.js渲染与交互接管。

六、条件挂载、卸载与演示状态的初始化

挂载表示组件进入React树，卸载表示它从树中离开。CSS把元素隐藏，组件可能仍在树里，状态和Effect也可能继续存在；条件渲染让组件不存在，则是另一种生命周期。

本站算法演示使用AlgorithmDemoLoader接收演示标识与静态结果。下面是从当前结构缩小的示意，Demo代表选定的动态组件：

tsx
const [open, setOpen] = useState(false);
return <>
  {!open && fallback}
  <details onToggle={event => setOpen(event.currentTarget.open)}>
    <summary>展开逐步演示</summary>
    {open && <Demo />}
  </details>
</>;

先有open=false，读者看到静态主例结果，Demo尚未挂载；打开details触发事件，将open设为true，React才产生Demo；收起则把它移出树。再次展开时，Demo会重新挂载，并按自身的初始化规则设置初始帧。如果需要在收起后保留原来的步骤，就需要把这份状态保存到不会随Demo卸载的位置。

动态组件按演示组声明加载入口，等待时显示加载提示。以链表演示为例，“下一步”推进固定轨迹中的帧位置，更新节点、边和代码行；它不向服务器提交任意Python代码。静态结果保障基础可读性，条件挂载控制组件运行时机，两个机制分别发挥作用。

条件挂载直接控制组件何时进入React树；至于下载量和首屏耗时，还会受到共享chunk、预取和缓存的影响，需要通过网络记录分别观察。状态与Effect的关系继续见下一篇。

如果准备自己练习，可以先做两张数据不同、结构相同的卡片，再增加标签点击回调。先把输入和显示结果对应清楚，再继续学习状态，就不会一下子同时面对路由、接口和数据库了。
