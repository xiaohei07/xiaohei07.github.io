Word打不开、链接乱码和SVG解码失败，看起来都可能被叫作“编码问题”，但它们经过的规则不同。要定位这类问题，需要分清字符怎样表示、标记文档允许什么、资源怎样组合，以及最后由谁解释。

这篇补齐导出文件所需的格式知识。HTTP与浏览器已经介绍URL和请求，本篇不重新讲网络流程；实际两次故障的过程见Word与PNG问题排查。

一、字符、码点、编码与字符串长度

Unicode为字符分配码点，例如“中”对应U+4E2D。UTF-8和UTF-16是表示码点的编码方式：同一个字符可以有不同的字节表示，并不意味着它变成了另一个字符。

JavaScript字符串按UTF-16码元组织。码元是编码使用的单位，不总等于一个完整字符。常见emoji可能由两个码元构成；如果逐个码元删除“看起来不在普通范围内”的值，就可能把合法字符拆坏。反过来，一个孤立代理码元没有组成完整字符，也不能直接送进所有文档格式。

js
// 教学示例：比较UTF-16码元数与UTF-8编码后的字节数。
const text = "中😀";
console.log(text.length); // 3个UTF-16码元
console.log(new TextEncoder().encode(text).length); // 7字节

这里不把字节数、码元数和人眼看到的字符数互换。复杂emoji还可能由多个码点组合；具体字符串行为可对照JavaScript字符串长度说明。

二、XML不仅要求编码正确，还限制内容是否合法

XML用元素和属性组织文档，例如<title>内容</title>。它规定标签怎样闭合、特殊符号怎样表示，也规定允许哪些字符出现。一个字符串能够存在于JavaScript里，不代表能直接进入XML 1.0。

&lt;表达一个作为文字的“小于号”，属于转义问题；U+000C控制字符不在XML 1.0允许集合中，则属于字符合法性问题。将后者写成数值字符引用&#xC;仍不合法，因为引用目标也必须满足字符集合规则。规范依据见XML字符与引用规则。

项目的wordText是一个本地文本处理函数，用于把非法字符变成可见的反斜线表示。例如控制字符本身变成普通文本\u000c，读者仍能看到原来的异常位置；正常中文、换行与合法emoji保持原状。它不猜测原文意图，也不将字符静默改成另一段自然语言。

三、HTML、XHTML、MathML和SVG为什么会相遇

网页公式不是天然的一张图片，往往包含HTML排版、MathML数学语义和SVG笔画。将这组节点放入SVG的foreignObject，再让浏览器绘制时，外层接收的是XML结构，不能直接假设HTML字符串中的全部实体仍然有效。

命名空间说明元素属于哪种标记语言。同一棵结构里，SVG外层、XHTML内容和MathML公式各有自己的语义。XMLSerializer是浏览器提供的序列化工具，把节点树按XML规则转换为文本；项目中的formulaSvg则是组织这些步骤的本地封装。

HTML的&nbsp;问题说明了这个边界：HTML解析器认识的命名实体，普通XML不一定预先定义。让正确的节点树走对应序列化，比到处替换字符串更容易保持结构。但序列化也不能替代对非法文本、资源地址和活动内容的检查。可对照XMLSerializer接口。

四、DOCX怎样把正文和资源装在一起

DOCX是一个ZIP容器，里面有正文XML、样式、图片与关系文件。Office Open XML，简称OOXML，是这类Office文档采用的一组结构规范；WordprocessingML描述Word正文。

可以把一个带链接的段落理解为：

text
段落
  普通文本片段：“请看”
  超链接：“附件”
       ↓
正文XML：段落、文本、链接引用
关系文件：引用标识 → 目标地址
媒体文件：文档实际包含的图片
       ↓
ZIP容器 → Word读取与排版

项目把会话语义映射为段落、文本、表格与图片，由docx库生成对应结构；没有自行实现整套Office规范。段落层次可参考Microsoft的WordprocessingML介绍。

超链接只保存目标位置，与把另一个文件嵌入文档不同。附带成功的文档附件位于外部assets目录，Word通过相对链接打开；公式图片则可以作为DOCX内部媒体。LaTeX保存在替代文本中，也不等于已经生成OMML原生数学对象。OMML能够表达可编辑分式等数学结构，当前项目没有实现这层转换。

五、怎样从格式层次回到检查步骤

检查层次解决的问题仍不能证明什么
字节与容器文件是否完整，ZIP能否读取内部XML是否正确
XML结构与字符各部分能否合法解析样式、关系和阅读器行为是否符合预期
资源关系图片和链接目标是否对应消费者是否按相同方式处理路径
实际应用Word能否打开、末尾是否保留、链接是否打开正确文件所有版本和其他Office软件都兼容

这个顺序也适用于其他导出项目：先确认出错的对象，再选对应解析器或消费者检查。改变文件后缀不能改变内部格式，换编码也不能修复所有结构问题。清楚每一层的输入与规则，才知道修改应该落在哪一步。
