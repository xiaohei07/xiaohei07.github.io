导出文档时，文字会经过几层处理：程序保存字符串，把字符串组织为XML等结构，再与图片和链接关系一起写入文件。Word打不开、公式图像解码失败或附件链接异常，需要沿着对应层次寻找原因。

本篇介绍字符、编码、XML和DOCX容器之间的关系。HTTP请求及地址的基础可以参考HTTP与浏览器，这些格式规则在实际故障中的应用见Word与PNG的问题修复。

一、字符、码点与编码

Unicode为字符分配码点，例如“中”对应U+4E2D。码点可以理解为字符在Unicode中的编号，UTF-8和UTF-16则规定如何把这些编号表示出来。

同一段文字采用不同编码，得到的字节表示可能不同。处理文件时，需要知道读取和写入双方采用的编码，才能正确还原文字。

1.1 JavaScript字符串的长度

JavaScript字符串按UTF-16码元组织。码元是编码使用的单位，一些字符需要两个码元表示。例如，下面的字符串包含“中”和一个emoji：

javascript
const text = "中😀";

console.log(text.length);
console.log(new TextEncoder().encode(text).length);

// 输出：
// 3
// 7

“中”占一个UTF-16码元，“😀”占两个，因此text.length为3。转换为UTF-8后，两个字符分别占3字节和4字节，总计7字节。

这个例子中的字符串长度和文件字节数使用了不同单位。更复杂的emoji还可能由多个码点组合，处理截断、长度限制或非法字符时，应先确定需要检查的是哪一种单位。相关行为见JavaScript字符串长度说明。

二、XML的结构与字符要求

XML通过元素和属性组织文档，例如<title>内容</title>。它同时规定了结构规则、特殊符号的表示方式和允许出现的字符集合。

2.1 特殊符号的转义

XML使用尖括号标记元素。如果正文需要显示小于号，就需要让解析器把它当作文字，例如通过&lt;表示<。这属于转义：原来的字符合法，只是当前位置需要使用特殊表示。

2.2 非法控制字符的处理

U+000C等控制字符不在XML 1.0允许集合中。它们可以存在于程序字符串里，但写入XML前必须处理。把U+000C写成&#xC;仍无法通过合法性检查，因为数值引用指向的字符也必须属于允许集合。XML字符规则给出了相应范围。

本项目通过一个Word文本处理函数，把非法字符转换为可见的反斜线文本。例如，原来的控制字符被写成\u000c，最终文档中可以看见这几个普通字符，从而保留异常出现的位置。正常中文、换行和合法emoji继续保留。

检查emoji时还要考虑UTF-16代理对：合法的一对码元共同表示完整字符，应一起保留；孤立的代理码元没有组成完整字符，需要按异常处理。

三、公式中的HTML、MathML与SVG

网页公式可能同时包含几种结构：HTML负责部分排版，MathML描述数学语义，SVG表达图形或笔画。把公式保存为图片时，需要让这些结构在目标文档中继续得到正确解释。

本项目使用SVG的foreignObject容纳公式相关布局，再交给浏览器绘制。foreignObject可以让SVG包含其他命名空间中的内容，例如XHTML。

命名空间用于说明元素属于哪种标记语言。同一棵节点树中，SVG外层、XHTML内容和MathML公式分别保留各自的标记含义。创建节点后，再由XMLSerializer按XML规则把节点树序列化为文本。

这里有一个具体例子：HTML中的&nbsp;表示不换行空格，普通XML并没有预定义HTML的全部命名实体。如果把HTML序列化字符串直接拼到SVG中，就可能在解码时遇到未定义实体。使用正确命名空间建立节点树，再按XML规则序列化，能够让结构与接收端规则对应起来。接口说明见XMLSerializer。

序列化负责结构表达，非法文本、资源地址及允许的活动内容仍需要在各自环节检查。

四、DOCX容器中的正文与资源

DOCX是一个ZIP容器，内部保存正文XML、样式、图片和关系文件。Office Open XML简称OOXML，是这类Office文档使用的一组结构规范；其中，WordprocessingML描述Word正文。

例如，一个带附件链接的段落可以按以下方式组织：

text
正文XML
  段落
    文本片段：“请看”
    超链接：“附件” → 关系标识

关系文件
  关系标识 → 附件目标地址

媒体目录
  文档包含的公式图片等资源

本项目把会话映射为段落、文本、表格和图片，再由docx库生成对应结构。Word打开文件时，会解析这些部分并完成排版。段落和文本的层次可以参考Microsoft的WordprocessingML介绍。

4.1 附件链接与公式图片

成功附带的文档附件保存在同一个导出ZIP内的assets目录，这个目录与对话.docx位于同一级。完整解压后，Word通过相对链接打开这些附件。公式图片则可以作为DOCX内部媒体保存，并在替代文本中保留LaTeX。

当前公式以图片形式阅读。若要直接编辑分式、根号等数学结构，还需要生成Office使用的OMML数学对象，完成额外的语法映射和兼容处理；本项目目前尚未提供这项转换。

五、按格式层次检查导出文件

检查层次具体检查内容
字节与ZIP容器文件是否完整，条目是否可以读取
XML结构与字符文档各部分是否能合法解析
图片和关系文件图片是否存在，链接标识是否指向正确目标
实际阅读软件Word是否打开文件，末尾内容是否保留，附件是否打开到正确文件

每一步解决相应层次的问题，检查结果逐步累积。实际应用验证还要记录软件版本和样例范围，其他阅读器或版本需要分别确认。这样排查时，就能把“文件打不开”进一步定位到容器、字符、结构或资源关系，再修改对应的处理步骤。
