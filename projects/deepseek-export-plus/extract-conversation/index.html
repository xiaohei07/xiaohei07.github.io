会话提取负责把DeepSeek页面中的消息整理成后续格式模块可以使用的数据。它需要保留消息内容、角色、原有顺序和附件信息，同时处理长对话、折叠思考及不同页面的数据来源。

这一模块的输入是聊天页或分享页中能够取得的内容，输出是统一的会话模型。页面节点称为DOM；“挂载”表示对应内容此刻已经建立为页面节点。组件数据的前置知识可以参考React组件与props，模块在整体流程中的位置见项目架构。

一、长对话的边滚动边收集

长对话页面可能使用虚拟列表，只把屏幕附近的一部分消息挂载到DOM中。这样能够减少同时维护的页面节点；消息滚出可见区域后，对应节点可能被卸载。

假设一段对话有A、B、C、D、E五条消息，页面一次只挂载三条。为了在节点消失前保存内容，需要在每次滚动后立即读取当前消息：

滚动位置当前可以读取的消息已收集的消息
顶部A、B、CA、B、C
向下滚动一段B、C、DA、B、C、D
继续向下滚动C、D、EA、B、C、D、E

本项目的滚动收集函数会在经过各段时保存消息。多次读取中出现的B、C、D，需要按消息身份去重。正文相同的两条消息仍可能来自不同位置，例如用户在开头和结尾都说了“继续”，这两次发言都应保留。

实现优先使用虚拟项的key与同项位置，其次使用消息ID，最后回退到节点身份。如果页面复用节点，又没有提供稳定标识，消息身份的判断仍会受到影响。

1.1 滚动范围与等待条件

会话列表和消息区域都可能滚动。收集函数会沿消息节点寻找对应的滚动祖先，操作实际承载消息的容器，再通过高度、消息key和内容长度的变化判断本段是否还在加载，并设置等待上限。

内容在一段时间内保持稳定后，可以继续下一步；对话仍在生成时，后续仍可能出现新内容。因此，导出较长对话时，适合先等待当前回答相对稳定。

如果全部消息已经挂载，探测后可以直接读取。验证完整性时，重点检查首尾消息、原顺序和重复发言是否保留。完成或取消后，还要恢复本次临时改变的滚动位置和折叠状态；恢复前会考虑页面地址是否变化，以及思考是否原本就由用户展开。

二、消息数据来源与选择顺序

结构化消息数据指程序按字段保存的消息对象，例如角色、正文、思考片段、工具结果和附件。与直接读取页面文字相比，这些对象可能保留页面上没有完全展开的信息。

分享页优先读取公开分享响应中的结构化内容。聊天页则结合当前节点关联的数据、已观察到的历史响应缓存和DOM回退。DOM回退表示改从页面中已经显示的元素读取内容，再按元素位置整理。

本项目先查找当前挂载节点关联的结构化消息对象；没有找到时，再采用历史缓存。取得对象后，解析函数尝试把它整理成消息，解析成功就返回，失败时才进入DOM路径。

用消息ID为42的例子，可以观察这个选择顺序的影响：

当前取得的数据处理结果
节点对象包含新正文、思考和工具记录，历史缓存较旧使用节点对象；即使页面思考折叠，也可以读取对象中的片段
节点对象有合法正文，但思考只出现在其他来源中正文解析成功后返回，其他来源中的思考不会自动逐字段补入
没有节点对象，历史缓存较旧，DOM显示了新正文先尝试解析缓存；缓存解析成功时，输出可能仍使用缓存内容

因此，当前实现按来源和解析结果选择消息。逐字段比较所有来源、自动合并最完整版本，还需要额外的完整性及修订判断。页面内部对象和响应结构也可能变化，读取逻辑需要随实际网页维护。

历史缓存来自经过已安装观察脚本的网络请求。安装前已经发出的请求需要页面重新请求，新的响应才有机会进入缓存。观察方式见扩展脚本的协作机制。

三、思考与工具记录的有序组织

一条助手消息可能依次包含以下内容：

text
思考A → 搜索B → 思考C → 打开网页D → 最终回答E

这个顺序反映了回答形成的过程：先有一段思考，再搜索资料，接着根据搜索结果继续思考。如果把全部思考合并到前面，再把工具记录集中放到后面，读者就很难判断每段思考使用了哪些已有信息。

因此，本项目把思考和工具组织为同一个有序序列。使用结构化消息对象时，按照对象中的片段顺序组织；进入DOM回退时，则按照页面元素的实际位置组合。工具记录中的来源链接取自能够读取到的工具字段，缺失链接会按缺失处理，避免给记录补入没有依据的地址。

四、思考选项与轮次选择

思考内容默认不导出。用户启用对应选项后，思考与工具记录进入输出中的引用块，并保持原顺序；各格式都要执行相同的选项规则，JSON中的相关字段也按此处理。

这里的选项控制的是输出内容。为了列出轮次，窗口会先读取会话；结构化响应和缓存中也可能已经包含思考字段。如果使用需求进一步要求“未选择的内容连内存都不接触”，就需要同时调整提取和缓存策略。

4.1 首次补取思考的检查

首次开启思考并执行导出动作时，窗口会重新提取整个会话，再比较新旧轮数。假设开始时有两轮，用户选择了第2轮：

  • 补取后变成三轮，轮数检查会报错，避免直接沿用旧选择。
  • 补取后仍为两轮，但第2轮回答发生了变化，轮数检查仍会通过，原数字选择应用到新会话的第2轮。

当前检查使用轮数，尚未逐条比较旧新消息ID和内容修订。首次补取成功后，同一窗口的后续动作通常复用已经取得的数据。因此，选择轮次时应结合当时显示的会话内容，导出过程中继续生成或修改回答，可能影响最终使用的数据。

五、提取结果的检查方法

可以准备一段首尾带标记、中间有两次“继续”、并穿插思考和搜索的对话，逐项检查：首尾内容是否出现？重复发言是否分别保留？工具记录的位置是否正确？关闭思考后，各格式是否省略了对应内容？

这些检查直接对应提取模块要保留的信息。提取完成后，会话模型交给格式生成模块，由它继续处理代码、表格、公式和文档层级。
