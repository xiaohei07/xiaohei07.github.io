在网页里增加一个按钮，与读取网页程序保存的消息数据，是两种不同能力。DeepSeek Export Plus既要操作页面，又要调用浏览器扩展API，还要打开独立打印页，因此不能把所有代码想象成同一段网页脚本。

已有的React组件与props解释了网页怎样组织界面数据；本篇只补浏览器扩展新增的执行环境与通信规则。扩展自己的界面使用原生JavaScript和CSS，读取DeepSeek的React数据不代表扩展本身使用React构建。

一、DOM共享，不等于JavaScript变量共享

DOM是浏览器组织页面元素的树。内容脚本可以读写这棵树，例如找到消息节点、放入按钮；但它默认运行在ISOLATED环境，自己的JavaScript变量与网页变量隔离。同一页面中的网页脚本和扩展可以看见同一个元素，不意味着它们能直接访问彼此定义的变量。

假设网页脚本里有const messageData = ...，内容脚本不能仅因看见对应段落，就直接使用这个变量。MAIN环境与网页共享JavaScript执行环境，适合执行少量必须依赖网页对象的读取，但它也受网页环境影响，不适合存放秘密或无约束运行。具体边界见Chrome内容脚本说明。

项目把当前节点的元数据读取放到MAIN里，把页面交互留给内容脚本。返回结果只包含允许的角色、文本、片段和文件字段，不把整个框架对象交给其他模块；框架对象可能有循环引用、庞大状态和与导出无关的信息。

二、怎样让两个环境找到同一条消息

一次读取可以拆成以下步骤：

  1. 内容脚本给目标节点加一个临时标记，并向后台发送读取请求。
  2. 后台检查发送者所在页面、操作类型及当前同意状态。
  3. 后台在同一标签页、同一frame的MAIN环境运行读取函数。frame指页面文档环境，嵌入的子页面也有自己的frame。
  4. 读取函数按临时标记找到节点，有限度地检查关联对象，选出允许字段。
  5. 返回结果后再检查授权是否仍有效，内容脚本移除临时标记，交给会话提取模块。

临时标记解决的是节点定位，不能当成认证凭据。有界遍历则限制检查深度和数量，避免循环或过量对象拖住页面；达到限制时也可能拿不到完整内容。网页内部字段没有稳定接口承诺，这个适配点仍需要随网页变化维护。

长期历史观察与这次读取又是两件事。历史脚本在同意后观察符合范围的fetch/XHR响应，缓存随后到来的数据；单次函数则检查眼前挂载节点。观察器没有安装前已经结束的响应，不会因为后来启用扩展就自动重现。

三、后台service worker为什么不能当永久运行的程序

Manifest V3是Chrome扩展清单及相关运行机制的第三版。清单声明入口、权限和允许访问的目标；后台使用service worker处理扩展事件。它没有网页DOM，也不保证一直驻留，浏览器可能在空闲时将其回收。

因此，把打印内容只放在后台全局Map里并不稳妥：打印页打开时，原worker实例可能已经不存在。项目将短期打印会话放在storage.session，使用会话ID、有效期、大小限制和附件白名单关联。存储可跨一次worker回收保留数据，但不跨所有扩展或浏览器生命周期，不能当永久备份。平台规则见worker生命周期与session存储。

权限与同意也分开。浏览器授予scripting能力，表示扩展可以按规则注入；用户同意处理对话，才表示应用当前可以执行相应读取。后台需要同时考虑平台权限与应用状态。

四、独立页面与离屏iframe各做什么

执行位置本项目用途与后台的区别
隐私设置页说明并管理数据处理同意是可显示的扩展页面
打印预览页读取短期会话、显示内容、调用浏览器打印有DOM和排版，不是直接PDF编码器
Word/PNG离屏iframe临时装入导出内容，稳定字体、图片并测量绘制是页面里的独立文档，不是Web Worker或云转换服务

iframe可以先理解为页面中嵌入的另一个文档。这里采用受限制的临时排版表面，完成或取消后移除；它让导出内容有自己的样式与尺寸，却不会自动把同步绘制移到后台线程。

构建时，esbuild把内容脚本、历史观察、后台和独立页面组织为各自入口。Word/PNG共用一个按需包，其中包含docx与html2canvas；它不是每种格式独立一个懒加载包。marked、DOMPurify和KaTeX已有静态依赖链，界面晚一点出现，不意味着这些代码也一定晚一点下载。

五、撤回和更新要处理已经运行的实例

撤回同意时，仅取消未来脚本注册还不够，已经注入的脚本仍可能留在页面里。需要停止已有观察逻辑、清理缓存与打印会话，并处理尚未完成的读取。任务返回以后也要重新检查授权状态，具体时序见任务取消与过期结果。

扩展重载后，旧页面中的内容脚本还可能连接着失效上下文。项目识别这种失效，清理旧界面后提示刷新；刷新提示依靠页面DOM与location.reload()，不再调用已经失效的扩展API。

如果要做类似扩展，可以先画出“哪个环境拥有哪种数据、哪个环境允许哪种操作”，再设计消息字段、来源检查与清理动作。分环境的目的，是让能力和状态有明确位置，而不是把一个小扩展拆成许多看不见关系的文件。
